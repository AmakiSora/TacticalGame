## 算法原理

同时回合的命中判定发生在**移动/部署结算之后**：攻击瞄准的是一个格子，打中的是结算时站在那个格子上的敌人。3.8.0 又把整轮改成**按行动点分步结算**——队列顺序就是行动点顺序，同一单位可以跨行动点连续行动。因此 `dest-prob` v2 的核心问题是：

> 在“我排到第 k 个行动点”时，敌人可能已经走了几步、下一步会站到哪？

算法用解析式对手模型回答它，而不是随机或整局搜索：

1. **对手落点建模**：为每个敌军枚举“原地 + 可达格”，按占点引力、火力机会、我方威胁、支援锚点、原地惯性打分，再 softmax 成落点概率分布；敌方落点候选使用 blocker-aware BFS（保守预测，避免把威胁摊得过宽）。
2. **预测射击**：攻击收益 = 覆盖格上敌军出现概率 × 伤害，而不是只看攻击者当前射程内有没有人。敌军可能走进 `line` 射线、`arc` 扇形或 `single` 的预测格，都会被计价。
3. **目的格冲突规避**：同一目的格被 ≥2 个动作声明会让所有声明者一起失败。算法把敌军落点概率聚合成“该格被认领的风险”，移动/部署成功率按 `1 − 风险` 打折，失败时还要付一次行动点机会成本。
4. **威胁预判**：用敌军落点分布反推我方每个候选落点的期望承伤；站原地最容易被敌人按当前站位预瞄，移动到非预期格会降低被弹概率，但走到争夺据点仍会被区域火力覆盖。
5. **据点计价**：据点按“裁定权重 × 预计持有回合 + 收入”计价（裁定流量分占 0.7），敌方据点按攻防转换放大 1.5 倍。因此开局会优先铺开占点，而不是把行动点撒在空地上。

### 与现有算法的区别

| 算法 | 核心 | 与落点概率算法的差别 |
|---|---|---|
| `random-sim` | 从合法计划动作中均匀随机 | 落点概率算法对每个动作做期望收益竞标，且使用敌军落点分布 |
| `threat` / `field` | 当前棋盘的威胁图/势场 | 它们评估“当前站位”的威胁；落点概率算法的核心输入是敌军下一步落点与目的格冲突概率 |
| `kriegspiel` | 把整份有序计划塞进分步结算器做 rollout + 联合搜索 | 落点概率算法只做逐行动点的解析式边际评估，不模拟整轮、不做计划组合搜索，决策在毫秒级 |
| `matrix-eq` | 计划组合矩阵博弈 + CFR 均衡混合 | 落点概率算法是确定性的纯策略期望评估，不采样混合策略，也不看对手事件史 |
| `mcts` | 标准模式整局树搜索 | 落点概率算法只面向同时回合的单轮计划，不做整局模拟 |

一句话：**它把“同时回合的隐藏计划”当成一个可逐步更新的分布问题，而不是把同时模式当成“大家轮流走”来评估。**

## 决策逻辑

每次 `decide` 调用：

### 0. 前置短路

- 无 `ctx.owner` 或无 `game.plan` → null；
- `plan.committed` 已含己方 → null（等结算）；
- `plan.myQueue.length >= actionsPerTurn` → null（预算用尽）。

### 1. 队列前缀投影

读取己方已排队的 `myQueue`，按 `src/engine/planning.ts` 的 `projectPlanQueue` 同口径投影：

- `move` 改写该单位在后续行动点的虚拟站位；
- `demolish` 把目标格地形改写为 `plain`（从下一步起生效）；
- `deploy` 目标格加入投影占位集合。

每个候选动作都从**第 k 个行动点的投影站位**开始枚举，而不是回合开始站位。这是 v2 相对 v1 最关键的改动：同一单位可以连续移动、移动后攻击、攻击后撤退。

### 2. 攻击枚举（预测射击）

对每个己方单位（不再要求“本轮尚未行动”）：

- 若队列中该单位已排的攻击数达到 `attacksPerUnit`（默认 1，3.8.0 新规则）→ 不再生成攻击；
- 从投影站位按 `attackShape` 枚举合法瞄准：`single` 射程内、`line` 射线前 `min(length, range)` 格、`arc` 相邻三格扇形；
- 覆盖格上每个敌军的 `出现概率 × min(期望伤害, 目标 HP)`；
- 击杀奖励：掷骰下限 ≥ HP 给全额权重，期望伤害 ≥ HP 给折扣权重；
- 敌方总部：伤害按 `HQ_DAMAGE_BONUS` 放大，击毁给 `HQ_KILL`；
- 区域拒止：覆盖敌方据点时，按敌方出现概率附加少量据点价值；
- 锁定射击：若 `attackLock` 且点击格上当前有敌人，按该敌军落点分布中“仍在射程内”的概率算命中率；
- 减去攻击者在当前行动点停留的期望承伤。

### 3. 治疗枚举

支援兵按 `healShape` 枚举瞄准：

- 施放者取投影站位，覆盖格按投影后的友军站位计价；
- 对每个受伤友军按 `min(缺口, 治疗力 + 方差/2) × HEAL_SCALE` 计价；
- 若该友军预计承伤 ≥ 当前 HP，附加保命奖励；
- 队列中已被治疗覆盖的目标不重复治疗（避免 `already_healthy` 空耗）；
- 跳过炮火危险区（simultaneous 恒为空，royale 轴复用）。

### 4. 移动枚举

对每个己方单位：

- 候选 = **地形 BFS** `terrainReachable`：水/障碍挡路，单位/总部不挡路（3.8.0 新口径）；
- 目的格必须是投影后空位（己方前缀移动、前缀部署、敌方当前站位均占位）；
- 排除己方队列已声明的目的格、炮火危险区；
- 落点静态价值：踩上非己方据点按据点价值计价、向目标推进按格数计价、接近据点额外加分、下一轮火力机会 × 折扣；
- 减去落点期望承伤、拥挤惩罚；
- 与投影站位的原地价值比较；成功率 = `1 − 敌军认领风险`，失败扣一次行动机会成本。

### 5. 部署与爆破枚举

- 部署源 = `utils.deployOrigins`（总部 + 可部署据点，排除 `canDeploy: false`）；目的格按**投影地形 + 投影占位**判断，允许进入本步之前被己方移动腾出的格子；
- 基础分 `DEPLOY_BASE × 兵种系数`，加“落点即据点”的占领价值、靠近争夺点/敌方总部的站位分，按目的格冲突风险打折，减去落点期望承伤；
- 重装单位在目标方向上有相邻 blocker 时生成低优先级 `demolish`；投影地形立即改写，后续移动可以借爆破开路。

### 6. 选择与提交

所有动作按收益降序，同分按 `攻击 > 治疗 > 移动 > 部署 > 爆破` 稳定排序；收益 ≤ `MIN_SCORE` 时返回 null（提交计划）。`decide` 每次只返回一个动作，runner 入队后重新读取状态；下一次调用会用新的队列前缀重新投影，因此同一单位的连续动作能正确接续。

## 实现细节

- **合法性镜像**：`computeAim` / `enumerateAims` / `shapeSpec` 逐字镜像 `src/engine/planning.ts` 的 `coveredCellsFor`；`terrainReachable` / `projectPlan` 镜像队列前缀投影与地形寻路；`attackLimitFor` 镜像 `balance.attacksPerUnit`。
- **部署预算**：`plannedDeploySpend` 扣减队列中已计划部署的花费，使用 `effectiveDeployCost` 的据点折扣。
- **确定性**：不使用 `Math.random`；敌军落点 softmax、候选排序都由棋盘状态与前缀队列决定，便于回放与标定。
- **复杂度**：每步 O(己方单位 × 瞄准格 × 覆盖格 + 敌军 × 可达格 × 覆盖格)；不做整轮模拟。实测 v2 决策平均约 3–8ms/次（真实引擎 harness）。
- **不依赖服务器拒绝**：所有候选在入队前按 3.8 计划期校验过滤；被拒动作只会空耗 runner 重问配额。

## v1 → v2：3.8.0 分步引擎适配

v1 的镜像对象是旧 `src/engine/simultaneous.ts:resolveRound`（整轮一次目的格声明池 → 部署/移动 → 攻击/治疗），并假设“一单位一轮一动作”。3.8.0 改为 `src/engine/simultaneousResolve.ts:resolveRoundSteps` 后，v2 做了镜像层与动作层的同步重写。

### 改动清单

1. **队列投影**：新增 `projectPlan`/`projectedPos`/`projectedTerrain`/`projectedEmpty`，所有攻击、治疗、移动、爆破从第 k 个行动点的投影站位枚举；`deploy` 目的格按投影占位判断，允许进入前序移动腾出的格。
2. **多动作/攻击上限**：移除“单位已排动作就跳过”的保守枚举；同一单位可跨行动点连续行动；攻击按 `balance.attacksPerUnit` 计数，达到上限后不再生成攻击候选。
3. **地形寻路**：己方移动从 `utils.reachableCells`（单位/总部挡路）改为 `terrainReachable`（只按地形 BFS），与 3.8.0 `planning.ts` 一致；敌方模型仍保留 blocker-aware BFS 作为保守预测。
4. **动作集扩展**：新增 `demolish` 候选（重装、相邻 blocker、投影地形）与排队的治疗去重；`wait` 仍由 runner 支持，但当前策略不主动生成。
5. **失败成本**：保留目的格冲突风险折扣，并把 `attacksPerUnit`、投影空位、部署预算纳入候选生成；v2 的结算期失败约 1.3–3.4/局（standoff/molten），低于 kriegspiel v2 的 10–20/局。
6. **版本与文档**：注册表 `version: 'v2'`；单算法档案补本 `v1 → v2` 节；`algorithms/docs/RELEASE_NOTES.md` 与 `ALGORITHMS_NOTES.md` 的状态同步。

### 代价与边界

- **决策耗时**：v2 平均 3–8ms/次（v1 2–4ms/次），仍远低于 kriegspiel/matrix-eq；不引入整轮模拟。
- **结算期失败**：standoff 2.4/局、molten 3.4/局，主要来自目的格冲突/到达占用；v1 约 1.4/3.4。v2 的多动作链在一步失败时会连带后续动作，故没有强行排满所有行动点。
- **对手模型仍是单步 blocker-aware BFS**：这是为预测精度做的保守近似，不模拟敌军跨行动点的完整计划；对 matrix-eq 的 molten-throne 斩首路线没有解。
- **没有联合计划搜索**：每个行动点独立边际贪心；计划组合的协同/反协同仍不如 kriegspiel/matrix-eq。
- **未覆盖 royale**：炮火缩圈、无总部与 20 回合长局需另行标定。

## 已知限制

1. **对手模型不是完整计划模型**：落点分布只按一步 blocker-aware BFS 预测；敌军跨行动点的多步计划、wait 对齐和联合路线不在模型内。
2. **不做联合计划搜索**：逐个行动点贪心，无法为“多步后总部被斩首”定价；对 matrix-eq 的 molten-throne 斩首路线是已知短板（2/30）。
3. **多动作链的失败传染**：前序移动失败会级联作废该单位后续动作；v2 已用投影占位降低失败，但无法完全消除。
4. **未覆盖 royale**：炮火缩圈、无总部与 20 回合长局需要单独标定。
5. **样本边界**：性能表为 2026-10-23 / 3.8.1 / 真实引擎 harness / 30 局/图；6 局或旧规则数据不构成结论。

## 一句话总结

落点概率算法（dest-prob）v2 是同时回合分步引擎上的解析式对手建模算法：每个行动点先投影自己的队列，再预测敌军一步落点，用“落点概率 × 伤害”做预测射击、用认领风险规避目的格冲突，用据点流量计价抢点——不模拟整轮，但把 3.8 的步序语义真正纳入了决策。
