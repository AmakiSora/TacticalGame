## 算法原理

势场算法来自机器人导航的**人工势场法**（Artificial Potential Field）：把环境表示成连续势能的叠加，目标产生引力、障碍产生斥力，智能体沿势能梯度"流动"。本算法把这套结构搬到六角战棋上：

1. **斥力井（敌方火力）**：每个敌军贡献一个井，核心是"它下回合可站的位置（BFS 可达格）∪ 原地"再按射程环展开，核心外再外扩 N 环并按 `0.5^环距` 衰减，**半径外势为 0**。每格的潜在承伤按敌方火力上限（`actionsPerTurn`）截断，并**按敌军去重**——每个敌人每格只记一档，对应"每个单位每回合只能开火一次"。
2. **引力井（阵地）**：中立/敌方据点井深 = `70 + 收入 × min(剩余回合, 8)`（敌方据点 ×1.5），井形按 `深度/(1+距离)` 衰减；**周围 2 格内每多一个己方 `canCapture` 友军，井深 ×0.6**（认领衰减）。己方据点另有驻军轻锚。
3. **推进缓坡**：从目标点出发对可走格做 BFS 得到**波前距离场**（真实绕行步距），距离 ×`PROGRESS_SCALE` 作为势能。目标不可达时退回直线距离。这是势场范式处理障碍的正统解法（navigation function），直接消掉 APF 的经典局部极小值。
4. **队形项**：贴脸友军每多一个扣分（拥挤）；离最近友军超过 2 格时轻微拉回（cohesion，孤军时自动失效）。

与既有算法的范式差异：

| 算法 | 决策结构 | 空间结构 | 对手建模 |
|---|---|---|---|
| greedy | 固定优先级阶梯 | 无 | 无 |
| mcts | 采样模拟 | 无（移动只看目标距离） | 无 |
| threat | 单步效用（逐项手工量纲） | 有（威胁图逐格查表） | 有 |
| **field** | **连续势场取梯度** | **有（井有半径与衰减）** | **有（斥力井）** |

关键区别在**"距离即梯度"**：threat 的威胁项只在"进/退一格"的增量里比较，field 的斥力按环距连续衰减，任何落点都能查到一个可比的势值；再加上机会火力项参与逐格比较（不是选完最优格再补减，那样安全的外围格永远赢过"贴脸可开火"格），于是走位自然收敛到"能打到他、他够不着我"的射程边缘。

## 实现细节

### 核心参数

| 参数 | 值 | 说明 |
|---|---:|---|
| `DAMAGE_SCALE` | 6 | 1 点期望伤害的势能削减（与 threat 同量纲，便于跨算法对拍） |
| `HEAL_SCALE` | 8 | 1 点治疗量 |
| `KILL_REWARD` | 0.85 | 稳杀奖励 = 目标价值 × 该系数 |
| `LIKELY_KILL_DISCOUNT` | 0.6 | 大概率击杀（期望够、掷骰下限不稳）的折扣 |
| `THREAT_SCALE` | 0.8 | 潜在承伤 → 势能；与 threat 标定平台一致（初版 1.15 过度避险，30 局 0 胜） |
| `LETHAL_PENALTY` | 0.85 | 势能封顶 = 0.85 × 单位价值 |
| `RANGED_EDGE_DISCOUNT` | 0.6 | 敌方射程 ≥2 时最外环的威胁折扣 |
| `DANGER_RINGS_SMALL/LARGE` | 1 / 2 | 斥力外圈环数（按战场尺度自适应） |
| `SMALL_MAP_RADIUS` | 6 | 六边形半径 ≤ 该值按小图处理 |
| `CP_BASE` / `CP_INCOME_CAP` | 70 / 8 | 据点井基准深度 / 收入计价回合上限 |
| `CP_ENEMY_BONUS` | 1.5 | 敌方据点的净收益放大 |
| `LATE_GAME_BONUS` | 80 | 最后 2 回合的据点井附加深度（终局裁定分里据点权重最重） |
| `CLAIM_DECAY` | 0.6 | 每个贴点友军的井深衰减系数 |
| `GARRISON_BONUS` | 30 | 己方据点的驻军锚定 |
| `CP_WELL_REACH_SMALL/LARGE` | 4 / 5 | 据点井作用半径（按战场尺度自适应） |
| `PROGRESS_SCALE` | 4 | 推进 1 格的势能 |
| `HQ_GOAL_DEPTH` / `HQ_EARLY_DECAY` | 26 / 0.55 | 压敌方总部的缓坡权重 / 前 3 回合收缩 |
| `CROWD_PENALTY` / `COHESION_SCALE` | 6 / 1.5 | 贴脸拥挤 / 雁行拉扯 |
| `OPPORTUNITY_DISCOUNT` | 0.75 | 走位后本回合可兑现火力的折扣 |
| `DEPLOY_POTENTIAL` | 250 | 部署基准：最优动作不超过它才补员 |
| `STOP_POTENTIAL` | 0.001 | 结束回合门槛，**必须远小于 `PROGRESS_SCALE`** |
| 单位价值 | 120 + 3×cost | 击杀/阵亡/封顶共用 |

### 四个必须守住的约束（都踩过，别再改回去）

1. **反击风险要用伤害量纲与血量比**。攻击选项的致命判定是 `counter >= a.hp`，其中 `counter` 是原始期望承伤（伤害量纲）。初版误把"势能值"（≈ 潜在承伤 ×0.8 × 疲劳，且封顶 0.85×单位价值）拿去和血量比，斥力势普遍压过血量阈值，于是**单位被贴脸也从不还手**（30 局 0 胜）。势能换算只用于落点评估，致命判定用原始伤害。
2. **机会火力必须参与逐格比较**。初版先按"裸势"选出最优落点、再把火力折扣减到该落点上，结果安全的外围格永远赢过"贴脸可开火"格，单位长期停在射程外（攻击 6.4 次/局 vs greedy 35.7）。
3. **斥力井必须按敌军去重**。射程 3 的游侠，其射程环会从多个核心格重复覆盖同一格；逐条累积等于把**同一个敌人算成 5 次齐射**，41 点承伤被放大到 205，越过致命阈值把攻击全压成负分。
4. **孤军时 cohesion 必须失效**。没有友军时"最近友军距离"是 `Infinity`，直接代入会让所有落点的势都变成 `Infinity`、增量成 `NaN`，**场上只剩一个单位时它一个移动动作都不会生成**（整回合空转）。

### 尺度自适应（mapProfile）

小图（六边形半径 ≤ 6）没有纵深，且 6 个据点井按半径 5 展开会织满整张图、把走位项盖住：此时斥力外圈收 1 环、据点井收 4 格。大图用 2 环 / 5 格。快照里没有 `map.radius`，从可玩格反推六边形半径。

实测依据（vs greedy，各 30 局、逐局交替先手）：

| 地图 | 1 环档案 | 2 环档案 |
|---|---:|---:|
| forge（半径 6，两套种子） | **43/60** | 14/60 |
| default / dual-lanes / breach / desert（半径 8） | breach 掉 20 个百分点 | **70%/83%/57%/87%** |

### 风筝走位怎么来的

远程单位不写"保持距离"规则，而是：`落点收益 = 势能 − 0.75 × 该落点本回合可打出的最优火力`。贴脸格势能高（斥力井核心 + 射程环全额），外围格没有火力，两者平衡落在射程边缘。实测（单元测试固化）：

- 游侠距重装 5 格（射程 3、移动 2）→ 落到距 3 格（正好射程外沿，不贴脸）
- 游侠已开火后贴脸（距 1）→ 回撤到距 3 格（出敌方打击范围）

### 已知限制

1. **高行动点图会输（最大短板）**：`multiplayer-ring`（每回合 7 行动点、圆环图）实测 2:28（7%），**每 324 个回合里有 280 次带着剩余行动点主动交回合**——敌方机动范围大时"井外"不存在，单位找不到正收益落点就站住，把 tempo 让给对手；threat 在同图约 50%。这是"势场避险"范式的固有代价，与 threat 在 `danger-close`（1 行动点）上只有 18% 是同一枚硬币的两面：**field 擅长低行动点的慢节奏消耗，不擅长高行动点的接触战**。
2. **三张图仍不如 threat**：default 60%（threat 95%）、breach 57%（88%）、multiplayer-ring 7%（50%）。field 的收益集中在 threat 的短板上（danger-close 97% vs 18%、desert 87% vs 70%）。
3. **不做多步推演**：单步势场，没有"我走这里→敌人打谁→我再怎么应"的回应链（与 threat 同款局限）。
4. **3-4 人局未标定**：斥力井把多席位敌人一视同仁地叠加（按火力上限截断），没有"主要威胁/结盟"判断，与 threat 的已知短板相同。
5. **`random` 地图仅 40%**：裁定权重与回合数随机化会摊薄优势（threat 同口径 53%）。

## 优化方向

### 短期改进

1. **高行动点图的 tempo 建模**（最大短板）：`multiplayer-ring` 7%。诊断明确（280/324 回合带着行动点交回合），但"什么时候该接受亏损交换"需要一个 tempo 量纲，不是再调一个系数。已被数据否掉的方向：把大图也切成 1 环档案（breach −20 个百分点）。
2. **混合导航实验已否决**：试过"直线畅通就用直线距离压上去、被挡才用波前"（string-pulling 混合场），default +10 但 breach −20、desert −10，四图合计不如纯波前，代码里保留了结论注释。
3. **`random` 地图鲁棒性**：40%，权重随机化后需要更稳的目标选择（currently 目标取自 `game-utils.movementGoal`）。
4. **参数搜索**：`THREAT_SCALE`/`CLAIM_DECAY`/`CP_BASE` 仍是人工扫描；竞技场已具备自动对拍能力，可做网格/进化调参。

### 长期扩展

1. **浅层前瞻**：用势场值作叶子估值，叠 1-2 层对手回应搜索。
2. **威胁井的时序建模**：目前把所有敌军视为同一回合出手（按火力上限截断），可细化为"谁够得着谁"的匹配。
3. **多席位主要威胁判定**：3-4 人局需要"主要威胁"识别，否则斥力井会把所有敌人等价叠加。

## 兼容性

- **支持模式**：仅标准模式（standard）
- **不支持模式**：歼灭模式（annihilation）、同时回合模式（simultaneous）
- **地图兼容性**：所有标准模式地图都能跑（含 random 地图，均合法完赛）；强度与图相关，见上表
- **席位兼容性**：2 人局已标定；3-4 人局只保证动作合法、对局正常结束，不保证强于 greedy
- **运行环境**：Node.js ≥ 24，纯 JavaScript，无外部依赖

## 使用方式

### 通过前端添加

1. 创建对局，选择标准模式地图
2. 点击"添加 AI"按钮 → 切到"算法脚本"标签
3. 选择算法类型"势场算法（Field）"，AI 名称默认预填中文名
4. 点击"确定"

### 通过命令行运行

```bash
npm run dev  # 启动服务器

# 另一个终端
node algorithms/runner.mjs \
  --algorithm field \
  --url http://localhost:3100 \
  --game <gameId> \
  --token <playerToken> \
  --side player_a
```

### 通过 API 添加

```bash
curl -X POST http://localhost:3100/api/games/<gameId>/bots/algorithm \
  -H "X-Host-Token: <hostToken>" \
  -H "Content-Type: application/json" \
  -d '{"botType":"algo_field"}'
```

## 代码结构

```javascript
// 场构建
mapRadius()          // 战场尺度（六边形半径），快照无 map.radius 时从可玩格反推

wavefrontField()     // 波前距离场：从目标点 BFS 出真实绕行步距

// 场查询
wellDamage()         // 原始期望承伤（伤害量纲，供致命判定）
threatPotential()    // 落点斥力势（×THREAT_SCALE×疲劳，按单位价值封顶）
cpBaseDepth()        // 据点井基准深度（认领衰减在 potential 内按单位计算）

// 势能与动作
potential()          // 单位站在某格的势能：斥力 + 据点井 + 波前推进 + 队形 + 支援
fireGainAt()         // 落点本回合可打出的最优火力（机会火力）
attackOptions()      // 攻击：期望伤害 + 斩杀奖励 − 反击风险（伤害量纲致命判定）
healOptions()        // 治疗：恢复量 + 危险队友加成
moveOptions()        // 移动：逐格"势能 − 机会火力"，与原地同口径比增量
demolishOptions()    // 爆破：只拆比脚下更接近目标的墙
buildContext()       // 整回合共用：斥力井、目标表、波前场、据点井、尺度档案

// 导出接口
export default {
  name: 'field',
  description: '势场算法：连续势场塑形，风筝走位、分头抢点、雁行队形',
  async decide(game, utils) { ... }
}
```

## 一句话总结

Field 把棋盘建成"敌军斥力井 + 据点引力井 + 波前距离场"的叠加场，单位沿势能梯度流动，走位自然收敛在射程边缘、兵力自动分头抢点；
7 图 30 局对 greedy 135:75（64.3%），在 threat 的短板 `danger-close`（每回合 1 行动点）上 29:1（97%），
代价是每回合 7 行动点的 `multiplayer-ring` 只有 7%——它擅长低行动点的慢节奏消耗战，不擅长高行动点的接触战。
