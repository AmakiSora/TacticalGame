## 定位

迷雾模式是「同时回合骨架 × 视野迷雾」：每轮全员秘密排一份不超过 `balance.actionsPerTurn` 的计划，服务端按行动点分步同时结算。玩家只拿到服务端投影后的视角——自己的全部单位、视野内敌军、自己的残影（`fog.lastSeen`）、公开的地形/总部/据点/资源——隐藏敌军**不在 `units` 数组里**。

`fog-scout` 是这条信息战规则下的**基线算法**，目标不是强度上限，而是：

- 只消费投影视角，证明「不看隐藏信息也能完整下完一局」；
- 给出可解释的兵种分工与动作优先级，作为后续 fog 算法的对照基线；
- 在两张首发迷雾图上零非法动作、稳定完赛，并保持座位旋转等变（同一套启发式不因出生点偏向某个绝对方向）。

它**不**读取全量单位、观战视角、`rngState`、token、幂等记录或对手队列；源码级回归断言禁止出现这些旁路接口（`tests/algorithms/fog-scout.test.ts`）。它也不按地图名、地图 id 或坐标常量分支——地图差异只从公开的 `config`、`cells`、`headquarters`、`controlPoints` 进入。

## 输入边界

| 输入 | 用途 |
|---|---|
| `game.units` | 己方单位 + 视野内敌军（服务端已投影）；隐藏敌军不在此数组 |
| `game.fog.revealed` | 是否已揭雾；揭雾后停止残影盲射 |
| `game.fog.lastSeen` | 己方残影，作为盲射候选；只保留 `seenRound >= 当前轮 - 1` 且 HP > 0 的条目 |
| `game.cells` / `game.map.terrainCells` | 可通行格与地形；`terrainCells` 覆盖层优先（与引擎同序） |
| `game.config.units` | 兵种费用、射程、移动、攻击/治疗形状、治疗量 |
| `game.config.balance` | 行动点、`attacksPerUnit`、`minimumDamage`、部署规则、据点类型效果 |
| `game.config.fog.vision` | 视野半径覆盖（缺省回落五兵种默认值，clamp 0..8） |
| `game.headquarters` / `game.controlPoints` / `game.resources` | 总部位置/血量、据点归属/类型、己方补给 |
| `game.plan.myQueue`（或 `queues[owner]`） | 已入队动作，用于前缀对账、去重与预算扣减 |
| `game.players[owner].status` / `game.phase` | 存活与可行动守卫 |

**不读**：`game.fog.visibleCells`（逐格可见性不进评分，见「侦察收益」）、其他玩家的队列内容、观战/全量接口、随机数状态。

## 决策流程

### 0. 入口守卫

`ctx.owner` 缺失、`game.config.mode !== 'fog'`、`phase !== 'active'`、自己不是 `active`、已在 `plan.committed`、或队列长度已达 `balance.actionsPerTurn`（缺省 5）时，`decide` 返回 `null`。返回 `null` 由 runner 解释为「提交计划」，因此算法本身不调用 `/end-turn`。

### 1. 前缀对账

每次 `decide` 用当前队列重建上下文：把已入队的 `move` 投影到单位位置、累计已排攻击次数、已治疗的支援单位、已占用的目标格、已花费的部署补给。候选动作只从「当前队列的下一步」生成，已经排过攻击的格子不重复排（先一步可能已打死/打跑），已经移动过的单位不再排移动。

### 2. 候选生成与统一评分

五类候选——攻击、治疗、残影盲射、移动、部署——都换算到同一条分值尺度，排序后取最高分入队。典型量级（非严格优先级，占点等加成可改变相邻顺序）：

| 候选 | 基础分 | 主要修正 |
|---|---:|---|
| 攻击（斩杀敌方总部） | 13000 | — |
| 攻击（击杀可见单位） | 10000 + 兵种价值 | 兵种价值见下表 |
| 攻击（总部非斩杀） | 6000 + min(伤害, 剩余 HP) × 12 | — |
| 攻击（单位非斩杀） | 5200 + 兵种价值 × 0.6 + min(伤害, 剩余 HP) × 8 − 剩余 HP × 0.4 | 期望伤害 = max(`minimumDamage`, 攻击 − 防御) |
| 治疗 | 3200 + 缺失 HP × 4 + 兵种价值 × 0.3 | 仅 `support` 兵种，每轮每支援单位一次 |
| 残影盲射 | 1900 + 兵种价值 × 0.4 − 过期轮数 × 250 | 非 `single` 形状 +120；过期轮数 = 当前轮 − 1 − `seenRound` |
| 部署 | 1200 + max(0, 18 − 距最近敌方总部) × 18 | 己方 < 3 单位 +420；侦察兵且 < 5 单位 +150；游侠 +120；有伤员时的支援 +240；暴露风险 × 60 |
| 移动 | 700 | 见下 |

兵种价值（仅用于「打谁更值」，不是引擎数值）：游侠 420、支援 380、侦察 320、步兵 300、重装 260。

**移动评分**（在基础 700 上叠加）：

- 侦察兵：向敌方总部推进 × 45 + `coverageGain` × 14；脱离全队（最近友军 > 3 格）−140。
- 游侠：推进 × 70 + `coverageGain` × 4，并保持 2–3 格的舒适射程；被贴脸会先死。
- 步兵/重装：推进 × 80。
- 占点：目标格是敌方据点且单位可占领 → +1600 + 据点优先级 × 6。优先级：补给 16、前线基地 13、维修 11、其余取 `income`（缺省 8）。
- 维修：残血（≤ 60% HP）且己方有维修点 → 每靠近 1 格 +50，贴到 ≤ 1 格再 +180。
- 总部防御：己方总部附近有可见敌军（≤ 6 格）或残影（≤ 5 格）→ 每靠近 1 格 +110 × min(3, 威胁数) × 兵种系数（侦察 0.5，其余 1.2）。
- 支援站位：优先贴受伤友军（每靠近 1 格 +60，进入治疗射程 +200）；无伤员时跟随主力重心（每靠近 1 格 +40）。
- 攻击预置：走到能打到 2 个可见敌军/敌方总部的格子，每个 +260。
- 暴露惩罚：`exposure` = 敌方可见单位「移动 + 射程」可达范围的兵种威胁权重之和（游侠 3、重装 2、步兵 1.5、侦察 1、支援 0.6），残影 3 格内每个 +0.4；按 `DANGER_WEIGHT` 扣分（侦察 90、支援 80、游侠 70、步兵 45、重装 25）。

### 3. 侦察收益 `coverageGain`

目标格视野内、且不在其他己方单位视野内的格子数（只用公开地形 + 己方坐标）。**不用服务端 `visibleCells` 逐格计数**：hex 线段光栅化在 120° 旋转下会差 1–2 格，把噪声写进评分会把固定方向的走位偏置放大成出生点胜率差。`visibleCells` 在 4.0.0 基线修复中已退出评分；当前实现只用 `fog.revealed` 判断是否揭雾。

### 4. 部署

每轮最多 2 次部署。兵种按缺口选择：无侦察 → 侦察；无支援且伤员 ≥ 2 → 支援；无游侠 → 游侠；单位 ≤ 2 → 步兵；随后按步兵、游侠、重装补齐。只从己方总部（`deployFromHq !== false`）或己方、允许部署、且未禁止的据点出发，落到相邻平原空格；补给不足、目标格已占用/已计划/有残影/有敌方单位时跳过。

### 5. 排序与提交

`compareCandidates` 依次比较：分值降序 → 座位局部坐标 `dot` 降序 → `cross` 升序 → 单位/来源下标 → 绝对坐标兜底。最高分动作成为下一次入队动作；队列满或没有候选时返回 `null` 提交。

## 座位局部坐标系与可复现性

4.0.0 基线修复的核心：候选 tie-break 不再用 `${q},${r}` 字典序（那会让三个座位都偏向同一个绝对方向，`fog-crossing` 西北座胜率被压到 8%），而是用**座位局部坐标系**：

- 原点 = 自家总部（无总部时取己方单位取整重心）；极轴 = 总部 → 棋盘重心。
- 平面坐标 `X = 2q + r`、`Y = 3r`；内积权重 `(3, 1)` 抵消两轴尺度差。
- `dot = 3·dx·axisX + dy·axisY`（沿极轴投影，越大越靠中心），`cross = dx·axisY − dy·axisX`（区分左右）。
- 棋盘整体旋转 + 座位转到下一个座位时，`dot` / `cross` 数值不变，三个座位的同构候选拿到同一组排序键，首轮计划互为旋转像。总部恰在棋盘重心时退化为「到原点距离 + 绝对坐标」。

单位/来源的 id 是 UUID，跨进程不可复现；排序只在同一数组下标上做 tie-break，保证同种子同视角的决策序列确定。没有随机源。

## 短期记忆

按 `(gameId, owner)` 进程内保存（最多 128 局，超出淘汰最旧）：

- 每轮记录给某单位排的移动目标；下一轮没到位（撞格、被占、路径失败）就把该格记入失败表，保留 2 轮。
- 失败格扣分 `900 − 300 × 已过轮数`，刻意低于占点收益（1600+）：只打消「不是目标的机械重排」，不阻止继续争夺高价值据点。
- 中央格 `(0,0)` 是旋转不动点，三座侦察兵都会把它排成最优目标；同一步到达会全员 `destination_conflict`，随后每轮原地重排并连带作废该单位后续动作。记忆把这串连锁损失压下去；取消中央争夺会把 2 人图拉成 28/72（已回归验证）。

`node scripts/fog-selfplay.mjs`（进程内真实引擎、每座位只拿投影视角、种子 20261120 起）：

| 口径 | 局数 | 结果 |
|---|---:|---|
| 两图多种子合计（4 种子 × 每图 60 局） | 480 | 0 非法、0 未完赛，单局 0.3–0.9 s |
| `fog-crossing` 三座（合计 240 局） | 240 | east 75 / northwest 82 / south 83 → 31.3% / 34.2% / 34.6% |
| `fog-harbor` 两座（合计 240 局） | 240 | east 113 / west 116 / 11 平 → 决胜局 49.3% / 50.7% |

## 已知限制

- **只有自对局数据**：fog 不进竞技场、统计与 RL，没有跨算法 Elo、分图胜率或与模型的对局；强度结论暂无同口径对照。
- **单步贪心**：候选按当前队列的下一拍估分，不做多拍联合推演；残影盲射的命中概率、治疗与占点的组合收益都是手工权重。
- **敌方模型粗糙**：威胁场只按「移动 + 射程」近似，未建模对手目标选择、集火顺序与残影诱导；`exposure` 对 3 人局的第三方混战尤其保守。
- **地图覆盖有限**：只在 `fog-harbor` / `fog-crossing` 两张首发图验证；新 fog 图的地形、据点类型与视野覆盖未必落在现有权重区间。
- **进程内记忆**：短期记忆只存在单进程，进程重启或多副本会丢失/不一致（本项目为单副本部署，见 `AGENTS.md`）。
- **逐格视野不参与评分**：`coverageGain` 是几何近似，不等于服务端实际 `visibleCells`；可能高估或低估某个站位的真实情报收益。
- **不读事件游标**：算法只用当前状态与自己的队列，不用 `seq` / `lastEventSeq` 推断对手隐藏行动；因此它对 4.0.1 的观者序号语义不敏感（事件投影改动不影响它的输入）。
