## 算法原理

贪心算法（Greedy Algorithm）在每一步都选择当前看起来最优的动作，不进行全局规划或未来推演。核心思想是"局部最优"，通过简单的启发式规则快速做出决策。

虽然贪心算法不保证全局最优解，但在实时对战游戏中具有以下优势：

1. **决策速度快**：O(n²) 复杂度，每个决策耗时 < 0.1 秒
2. **实现简单**：规则清晰，易于理解和调试
3. **可解释性强**：每个动作都有明确的优先级理由
4. **资源占用低**：无需模拟或搜索，CPU 和内存占用极小

## 决策优先级

从高到低依次尝试以下动作，一旦找到可执行动作立即执行：

### 1. 攻击（最高优先）

遍历所有己方单位，寻找射程内的敌方目标：

- **优先攻击总部**：如果任何单位能攻击敌方总部，立即执行
- **优先击杀低血单位**：`scoreTarget()` 对低血量单位打高分
- **攻击普通单位**：按价值和血量综合评分

目标评分公式（`scoreTarget` 函数）：

```
score = baseCost / max(1, currentHp / 10)
```

- 单位成本越高，分数越高（优先打贵的）
- 血量越低，分数越高（优先收割）
- 总部固定高分（180 分）

### 2. 治疗（次优先）

遍历所有己方支援兵，寻找受伤友军：

- **优先治疗低血高价值单位**：评分同攻击逻辑
- **治疗距离 1 格内**：支援兵射程为 1
- 已满血单位不考虑

### 3. 爆破（拓展通路）

遍历所有己方重装单位，寻找相邻障碍物：

- 重装可花费行动爆破 `blocker` 地形变为 `plain`
- 优先级低于攻击和治疗，避免浪费战斗机会
- 当前实现：找到第一个可爆破的重装立即执行

### 4. 部署（补充兵力）

如果资源充足且有空闲部署点：

- **部署优先级**：scout > infantry > support > heavy > ranger
  - 侦察兵：快速抢点（移动 5）
  - 步兵：性价比高、可占点
  - 支援兵：提供治疗
  - 重装：血厚但移动慢
  - 游侠：攻击强但脆弱
- **部署位置**：总部或己方据点的相邻空地
- **资源检查**：确保补给足够（scout 38、infantry 45 等）

### 5. 移动（最低优先）

所有战斗和部署动作都尝试后，开始移动单位：

- **移动目标**由 `movementGoal()` 计算：
  - 有敌方单位时：向最近的敌方单位移动
  - 无敌方单位时：向最近的敌方总部移动
  - 距离计算使用六边形距离 `hexDistance()`
- **路径规划**：`reachableCells()` 计算可达范围，选择最接近目标的位置
- **优先移动未行动的单位**：每个单位每回合最多移动一次

### 6. 结束回合

如果以上所有动作都无法执行，返回 `null`，运行器调用 `endTurn()`。

## 实现细节

### 核心函数

| 函数 | 功能 | 复杂度 |
|---|---|---|
| `tryAttack()` | 寻找并执行攻击动作 | O(n·m) |
| `tryHeal()` | 寻找并执行治疗动作 | O(n·m) |
| `tryDemolish()` | 寻找并执行爆破动作 | O(n) |
| `tryDeploy()` | 尝试部署新单位 | O(k·p) |
| `tryMove()` | 尝试移动单位 | O(n·c) |

- n = 己方单位数（通常 5-15）
- m = 敌方单位数（通常 5-15）
- k = 部署点数（通常 1-5）
- p = 每个部署点的相邻格数（6）
- c = 每个单位的可达格数（平均 10-30）

总复杂度：O(n·m + n·c) ≈ **O(n²)**

### 状态检查

每个动作前都会检查：

1. 单位是否已移动/行动（`unit.hasMoved` / `unit.hasActed`）
2. 行动点是否充足（`game.turn.actionsLeft > 0` 或单位已激活）
3. 目标是否合法（敌我关系、射程、血量等）

### 工具函数依赖

从 `game-utils.mjs` 导入：

- `hexDistance()` — 六边形距离
- `neighbors()` — 相邻六格
- `reachableCells()` — 单位可达范围
- `livingUnits()` — 存活单位列表
- `enemyTargets()` — 敌方目标（单位 + 总部）
- `scoreTarget()` — 目标评分
- `movementGoal()` — 移动目标计算

## 性能表现

### vs 其他算法（default 地图）

| 对手 | 胜率 | 先手/后手 | 备注 |
|---|---:|---|---|
| random | **96.9%** (31:1) | 16:0 / 15:1 | 32 局，3.5.0 实测 |
| mcts | **80%** (24:6) | 15:3 / 9:3 | 30 局，3.5.1 实测 |

**分析**：
- 对 random 几乎全胜（96.9%），证明基础决策逻辑有效
- 对 mcts 胜率 80%：场均攻击约 41 vs 17，集火补刀带来更好的单位交换比（场均阵亡 1-2 vs 3-4）
- 当前算法 AI 中最强，攻击/抢点/部署等宏观指标与 mcts 相当，优势在战斗效率

### vs RL 模型（random 地图，48 局配对换座）

| 对手 | 胜率 | 先手/后手 | Wilson 下界 |
|---|---:|---|---:|
| v2.7.0 | **18.8%** (9:39) | 6:18 / 3:21 | 11.8% |
| v3.0.2 (champion) | **10.4%** (5:43) | 3:21 / 2:22 | 5.1% |

**分析**：
- 对 v2.7.0 胜率仅 18.8%，被 RL 模型碾压
- 对 v3.0.2 胜率更是跌至 10.4%，几乎无胜算
- 先手后手胜率均极低，说明整体战术水平不足

**结论**：greedy 是当前算法 AI 中最强（对 random 96.9%、对 mcts 80%），适合快速演示、基准对照和中等强度对战；对 RL 模型仍有显著差距。

## 决策时间

| 场景 | 耗时 |
|---|---:|
| 早期（单位 < 5） | 0.01-0.03 秒 |
| 中期（单位 5-10） | 0.03-0.06 秒 |
| 后期（单位 > 10） | 0.06-0.10 秒 |

平均每个决策耗时 **< 0.1 秒**，远快于 MCTS（0.5-1 秒）和 RL 模型推理（0.1-0.2 秒）。

## 已知缺陷

1. **无全局规划**：只看当前回合，不考虑多回合战术
2. **无风险评估**：可能把单位送到危险位置
3. **部署时机差**：资源够就部署，不考虑战场形势
4. **移动目标单一**：只会直线推进，不会迂回或防守
5. **治疗优先级低**：可能错过关键保人时机
6. **不会占点**：没有专门的据点占领逻辑

## 改进方向

### 短期改进

1. **据点优先**：步兵/侦察兵优先移动到未占领据点
2. **防守总部**：总部血量低时优先治疗和防御
3. **风险评估**：移动前检查目标位置是否在敌方射程内
4. **部署时机**：根据战场形势决定是否部署（而非有钱就部署）

### 长期改进

1. **多步规划**：前瞻 2-3 步，评估动作序列的价值
2. **态势评估**：计算双方军力对比，决定进攻或防守
3. **兵种配合**：重装掩护游侠、支援跟随前线等
4. **资源管理**：预留资源应对突发情况

## 兼容性

- **支持模式**：仅标准模式（standard）
- **不支持模式**：歼灭模式（annihilation）、同时回合模式（simultaneous）
- **地图兼容性**：所有标准模式地图（default、random、dual-lanes、desert 等）
- **运行环境**：Node.js ≥ 24，纯 JavaScript，无外部依赖

## 代码结构

```javascript
// 核心决策函数（按优先级顺序）
async function tryAttack(game, owner, utils) { ... }
async function tryHeal(game, owner, utils) { ... }
async function tryDemolish(game, owner, utils) { ... }
async function tryDeploy(game, owner, utils) { ... }
async function tryMove(game, owner, utils) { ... }

// 导出接口
export default {
  name: 'greedy',
  description: '...',
  async decide(game, utils) {
    // 依次尝试五类动作
    return await tryAttack(...) 
        || await tryHeal(...) 
        || await tryDemolish(...) 
        || await tryDeploy(...) 
        || await tryMove(...) 
        || null;
  }
}
```

完整源码见 `algorithms/builtin/greedy.mjs`（约 180 行）。

## 代码来源

greedy 算法的核心决策逻辑提取自 `scripts/auto-standard-game.mjs`，该脚本是早期用于自动化测试的 LLM 玩家基准。通过重构和模块化，将决策逻辑封装为独立算法模块。

## 一句话总结

greedy 通过"攻击 > 治疗 > 爆破 > 部署 > 移动"五级优先级快速做出局部最优决策（耗时 < 0.1 秒），对 random 碾压（96.9%）、对 mcts 胜率 80%，是当前算法 AI 中最强，但对 RL 模型仍有显著差距（对 v2.7.0 仅 18.8%），适合作为演示、教学、算法基准和中等强度对战对手。
