## 算法原理

蒙特卡洛树搜索（Monte Carlo Tree Search, MCTS）是一种基于随机采样的决策算法，广泛应用于围棋、国际象棋等复杂对抗游戏。核心思想是通过构建搜索树、反复模拟对局，统计每个动作的胜率，最终选择访问次数最多（或胜率最高）的动作。

### 四个阶段

1. **Selection（选择）**：从根节点开始，使用 UCB1 策略选择子节点，直到到达叶子节点
2. **Expansion（扩展）**：如果叶子节点未完全展开，随机选择一个未尝试的动作，创建新子节点
3. **Simulation（模拟）**：从新节点开始，使用轻量级策略模拟到终局或最大深度
4. **Backpropagation（回传）**：将模拟结果沿路径向上回传，更新每个节点的访问次数和累计奖励

### UCB1 选择策略

$$
\text{UCB1}(node) = \frac{Q(node)}{N(node)} + c \sqrt{\frac{\ln N(parent)}{N(node)}}
$$

- $Q(node)$：节点累计奖励
- $N(node)$：节点访问次数
- $c$：探索常数（本算法使用 1.414）
- 第一项：利用（exploitation），倾向选择高价值动作
- 第二项：探索（exploration），倾向选择访问少的动作

## 实现细节

### 核心参数

| 参数 | 值 | 说明 |
|---|---:|---|
| `iterationLimit` | 100 | 每个决策的 MCTS 迭代次数 |
| `explorationConstant` | 1.414 | UCB1 探索常数（√2） |
| `maxDepth` | 8 | 模拟最大深度 |
| 动作采样上限 | 20 | 每次收集的候选动作数 |
| 移动采样单位 | 3 | 采样前 3 个可移动单位 |
| 移动采样位置 | 2+1 | 每单位取最贴近 movementGoal 的 2 格；canCapture 单位额外生成据点占领动作（优先级 1.2） |

### 动作收集策略

优先级从高到低：

1. **攻击动作**（优先级 1-3）
   - 攻击总部：优先级 3
   - 攻击低血单位（HP < 40）：优先级 2
   - 攻击其他敌方单位：优先级 1

2. **治疗动作**（优先级 1.5）
   - 支援兵治疗受伤友军

3. **移动动作**（优先级 0.5，据点占领 1.2）
   - 采样前 3 个未移动单位
   - 每单位取可达格中最贴近 `movementGoal` 的 2 格（目标导向，替代早期均匀抽样）
   - `canCapture` 单位若可达范围内有中立/敌方据点，额外生成占领动作（优先级 1.2）
   - 避免全遍历导致组合爆炸

所有动作按优先级排序后取前 20 个，确保搜索效率。

> 部署（deploy）不在 MCTS 动作空间内：`decide` 入口按补给/兵力状况先行判断（触发条件与 greedy 一致），直接返回部署动作后再进入搜索。

### 状态评估函数

```
score = Σ(我方单位成本) 
      - Σ(敌方存活单位成本)
      + 我方据点数 × 60
      + 我方总部存活时 HP × 2（阵亡 -10000）
      + Σ(敌方总部已受伤害) × 3（阵亡 +10000）
```

- **我方/敌方单位**：按配置的 `cost` 扁平计价（缺省 50）——击杀敌人即移除其全部价值，天然保持集火补刀的激励
- **我方据点**：每个 +60，配合模拟中的据点占领，让搜索能评估抢点动作
- **我方总部血量**：权重 ×2，鼓励防守；总部阵亡直接 -10000
- **敌方总部伤害**：按 `maxHp - hp` 计，权重 ×3，强化进攻目标；总部阵亡直接 +10000

### 简化模拟

为提高效率，状态模拟进行了以下简化：

1. **攻击伤害固定**：`damage = max(1, attack - defense)`，不考虑随机波动
2. **治疗量取基准值**：支援兵 `healPower`（引擎实际为 healPower + 随机浮动）
3. **移动不检查路径**：直接传送到目标位置
4. **不模拟部署和爆破**：动作收集阶段已排除
5. **克隆状态**：逐个克隆单位与总部对象，模拟不会污染真实游戏状态
6. **单边推演**：模拟阶段只推演己方动作，不建模对手回应

这些简化使得模拟速度提升约 10 倍，但与真实游戏规则存在偏差。

### 已知限制

1. **无对手建模**：模拟不含敌方回应，走位暴露不会被惩罚，会系统性高估推进类动作
2. **不爆破障碍**：动作收集无 demolish，被障碍围死时无法开路
3. **战斗效率低于 greedy**：不主动集火低血量目标，单位交换比吃亏（场均阵亡 3-4 vs 1-2）
4. **移动采样有偏**：只采样前 3 个未移动单位；采样未覆盖到时由 `fallbackMove` 退化为贪心移动（向 `movementGoal` 推进），避免还有可动单位却提前结束回合
5. **胜负方差大**：决策含随机模拟，算法强度对比需要 30+ 局的大样本

## 性能表现

### vs 其他算法（default 地图）

| 对手 | 胜率 | 先手/后手 | 备注 |
|---|---:|---|---|
| random | **100%** (12:0) | 6:0 / 6:0 | 终局评分约 3200 vs 500，评分碾压为主 |
| greedy | **26.7%** (8:22) | 4:11 / 4:11 | 30 局 |

**分析**：
- 对 random 全胜：攻击/抢点/部署协同下经济与兵力全面占优
- 对 greedy 胜率 26.7%：攻击/抢点/部署等宏观指标与 greedy 持平，差距在集火补刀效率（greedy 场均攻击约 41 vs 17，单位交换比占优）
- 对 RL 模型的同口径实测尚未进行
- MCTS 决策含随机模拟，胜负方差较大；可靠的算法强度对比需 30+ 局（见未来方向"算法锦标赛"）

## 决策时间

| 场景 | 耗时 |
|---|---:|
| 早期（单位 < 5） | 0.3-0.5 秒 |
| 中期（单位 5-10） | 0.5-0.8 秒 |
| 后期（单位 > 10） | 0.8-1.2 秒 |

100 次迭代下，平均每个决策耗时 0.5-1 秒，符合实时对战要求。如需加速可降低 `iterationLimit`，但会损失决策质量。

## 优化方向

### 短期改进

1. **动态迭代次数**：早期少迭代、后期多迭代
2. **RAVE（快速动作值估计）**：记录历史动作价值，加速收敛
3. **渐进加宽**：逐步增加展开的子节点数
4. **更精确的模拟**：包含伤害波动、路径检查

### 长期扩展

1. **学习评估函数**：用 RL 模型替代手工评估函数
2. **多线程并行**：Worker Threads 并行模拟
3. **开局库**：预计算前 5 回合的最优开局
4. **残局库**：预计算终局必胜/必败态势
5. **AlphaZero 风格**：MCTS + 深度神经网络

## 兼容性

- **支持模式**：仅标准模式（standard）
- **不支持模式**：歼灭模式（annihilation）、同时回合模式（simultaneous）
- **地图兼容性**：所有标准模式地图（default、random、dual-lanes、desert 等）
- **运行环境**：Node.js ≥ 24，纯 JavaScript，无外部依赖

## 一句话总结

MCTS 通过 UCB1 平衡探索与利用、每个决策进行 100 次模拟推演、使用手工评估函数打分，攻击/抢点/部署等宏观指标与 greedy 持平，但集火补刀效率不足，实测对 greedy 胜率 26.7%（30 局 8:22）；适合作为无需训练的中等强度对手和算法研究基准。
