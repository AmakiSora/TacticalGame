## 定位

同时回合的难点不是“当前哪一步收益最高”，而是：

1. 五个行动点组成一份**不可事后修改的联合计划**；
2. 对手也在同一时刻提交计划，命中与到达结果由双方队列共同决定；
3. 同一单位可以跨行动点移动、攻击、撤退，单步贪心会把行动点浪费在彼此不衔接的动作上；
4. 撞格、级联失败、锁定射击和范围覆盖会让“看起来合法”的计划在结算时产生完全不同的结果。

`prism` 因此直接在**整份队列**上搜索：每层扩展一个行动点的候选动作，对若干种对手行为假设分别跑一次同步结算镜像，再按风险约束后的局面价值保留束宽内的完整计划。

### 与其它同时模式算法的路线差异

| 路线 | 代表算法 | prism 的差异 |
|---|---|---|
| 均匀随机基线 | `random-sim` | 不做随机抽样，而是联合搜索整轮队列 |
| 解析式落点/期望评估 | `dest-prob` | 不依赖单一落点分布，直接对完整计划做多情境结算 |
| 有序计划 rollout + 局部精修 | `kriegspiel` | 用确定性束搜索逐层构造完整队列，不做随机 rollout 或爬山 |
| 计划组合矩阵博弈 / CFR | `matrix-eq` | 不维护组合支付矩阵，也不输出均衡混合；直接优化多情境下的鲁棒计划 |
| 联合推演的其它实现 | — | 本算法不导入、不调用、不路由任何现有算法，所有候选生成、镜像和评分均为本文件独立实现 |

## 通用性约束

实现中有三条硬约束：

- **无算法依赖**：不 `import` 其它算法，不按对手名称切换策略。
- **无地图特化**：不读取 `mapId`，不出现 `standoff` / `molten-throne` 等地图名分支；地图差异只通过 `game.config`（兵种数值、形状、部署规则、据点类型、裁决权重、炮火危险区）进入决策。
- **无隐藏信息**：只使用 API 快照允许的公开字段和己方 `plan.myQueue`；不读取、不推测服务器未下发的对手队列。

## 决策流程

### 0. 前置短路与缓存

`decide` 在以下情况直接返回 `null`：

- 缺少 `ctx.owner`、对局不在 `active`、己方已淘汰或已提交；
- `plan.myQueue.length >= balance.actionsPerTurn`。

每轮第一次决策时从当前 `myQueue` 前缀开始合成整轮计划，并缓存到 `(gameId, owner, roundNumber)`。后续动作点只要服务器队列与缓存前缀一致，就直接返回计划中的下一条，不重复搜索；队列被外部修改时自动重新合成。

### 1. 队列前缀投影

按引擎 `projectPlanQueue` 的口径建立己方投影：

- `move` 改写后续动作点的虚拟站位；
- `demolish` 把目标格投影为 `plain`；
- `deploy` 扣除投影补给；
- 攻击次数按 `balance.attacksPerUnit` 累计。

候选动作始终从**当前行动点的投影站位**生成，因此同一单位可以“移动→攻击→再移动”，而不是按回合开始站位重复枚举。

### 2. 动作候选生成

每个束节点按当前行动点生成至多 18 个候选：

- **攻击**：按 `attackShape` 枚举 `single` / `line` / `arc` 的合法瞄准；目标格集合包含敌军当前位置、相邻格与可达格，通过覆盖价值和锁定射击价值排序；
- **移动**：按地形 BFS（计划期忽略单位与总部占位）生成可达格，综合占点、进入射程、缩短与总部距离、当前暴露和撤回价值排序，并额外保留占点/最佳火力/最安全三类目的地；
- **治疗**：按 `healShape` 枚举覆盖格，以预计治疗量和保命价值排序；
- **部署**：按实际折扣、剩余补给、兵种构成和落点战术价值排序；
- **爆破**：重装对相邻障碍生成低优先级候选，用于开路；
- **待命**：保留最低优先级候选，用于把关键动作对齐到更晚行动点。

所有瞄准格都会检查是否在棋盘内，避免生成计划期可解释但服务器必拒的越界动作。

### 3. 多情境对手模型

每个束节点同时维护四套对手行为假设：

| 情境 | 行为倾向 |
|---|---|
| `press` | 优先当前可命中的攻击，否则向己方目标推进 |
| `mobile` | 更愿意调整站位，兼顾下一行动点的火力机会 |
| `objective` | 优先占点、治疗和据点附近的争夺 |
| `hold` | 倾向原地攻击/治疗，只有高价值目标才移动 |

每个情境内的对手都从自己的**回合开始已存在单位**中生成动作。对手本回合新部署的单位可以被攻击，但不能在同一轮凭空获得后续行动，这与计划队列在回合开始前锁定的语义一致。

### 4. 同步结算镜像

每个候选动作与当前情境的对手动作一起进入 `resolveStep`，按 3.8 分步规则模拟：

1. 单位已亡或前序硬失败 → 后续动作作废；
2. `move` / `deploy` 同时到达：同格多人全部失败、地形阻挡、总部占位、占用者本步未移出 → 失败；交换和链式腾格按依赖迭代求解；
3. 部署扣补给、移动落位；
4. 爆破把地形改为 `plain`；
5. 治疗先结算（对覆盖格内每个受伤友军分别计算）；
6. 攻击按移动后的站位和覆盖形状结算，`attackLock` 按计划时刻目标锁定；
7. 同一阶段全部伤害施加后统一判死；总部摧毁立即淘汰该席位；
8. 局面评分按占点后的虚拟控制权计算，不修改原对局状态。

镜像使用期望伤害（`attack - defense`，下限取配置值）和治疗期望量，而不是随机掷骰；它服务于计划排序，不是官方裁判。

### 5. 风险约束评分

`evaluate` 不写死地图价值，而是读取本局：

- `balance.adjudicationWeights` 的斩首、己方总部、据点、军力、补给、击杀权重；
- 回合上限与据点流量口径；
- `artillery.dangerCells` / `warningCells`；
- 兵种造价、攻击/防御/射程/形状、部署折扣与据点维修/收入。

评分由三部分组成：

1. **终局计分差**：己方裁决分 − 最强对手裁决分，避免多人局只看单一敌人；
2. **下一轮潜力/威胁**：每个存活单位的可达火力、占点距离、总部压力与炮火暴露；
3. **计划质量惩罚**：自冲突失败、攻击落空、无效待命按次数扣分。

四个情境形成分布后，束节点采用“加权均值 + 最差情境惩罚”而不是只看平均：最差情境额外按 12% 计入负向价值，降低计划只在某一种对手行为下成立的脆弱性。

### 6. 束搜索与保留策略

- 每层扩展后按多情境评分排序，保留束宽 10（总单位数超过 10 时降为 7）；
- 搜索深度等于本局 `actionsPerTurn`，因此输出的是完整队列而不是单步动作；
- 非法动作不会进入候选，镜像失败只影响评分；
- 最终返回当前行动点对应的动作；后续动作点复用同一份联合计划。

## 接口与容错

- `decide` 只返回 `{ type, payload }` 或 `null`，不实现 `playTurn`，因此 REST runner、进程内评估和竞技场都走同一路径；
- 计划只引用服务器下发的真实单位/据点 ID，不伪造本回合部署单位的后续动作；
- 缓存按局、座位、轮次隔离，不会跨局或跨座位复用；
- 无地图 ID / 算法名 switch，新增同时模式地图不需要改代码。

## 已知限制

1. **一轮视野**：搜索深度是当前回合的 `actionsPerTurn`，不评估“本轮保存单位/据点后，下一轮是否会被斩首”的多轮期限问题；长线排程需后续加入跨轮价值。
2. **固定对手情境**：四种行为假设是通用启发式，不根据 `round_resolved` 事件史识别具体对手习惯；对强读盘对手仍可能被针对。
3. **期望值结算**：伤害/治疗使用期望值，方差敏感场景（擦边击杀、保命治疗）可能有偏差。
4. **束搜索非完备**：束宽 7–10、每层 18 个候选，只能覆盖有限计划；组合收益极高的隐蔽路线可能被剪枝。
5. **确定性输出**：同一局同一轮同队列会得到同一计划；轮内缓存便于复现，但确定性计划可被会读盘的对手预判。
6. **多人评分简化**：多席位时用“最强敌人”做零和差，盟友、交叉火力和共同削弱强者的收益只通过情境分布间接体现。
7. **耗时**：首次 `decide` 需要合成整轮计划，明显高于逐动作启发式；缓存命中后的后续动作点只做查表。当前没有硬实时超时，超大地图/极多单位时应压束宽。

## 使用方式

```bash
# 命令行（地图必须为 simultaneous 模式）
node algorithms/runner.mjs --algorithm prism \
  --url http://localhost:3100 --game <gameId> \
  --token <playerToken> --side player_a

# 大厅 bot 接口
curl -X POST http://localhost:3100/api/games/<gameId>/bots/algorithm \
  -H "X-Host-Token: <hostToken>" -H "Content-Type: application/json" \
  -d '{"botType":"algo_prism"}'
```

注册信息见 `algorithms/registry.mjs`；开发接口见 `algorithms/builtin/README.md`；测试入口为 `tests/algorithms/prism*.test.ts`。

## 一句话总结

棱镜算法（prism）v1 是同时回合模式的通用整轮搜索路线：逐行动点生成联合队列，用四种对手情境分别跑分步结算镜像，再按本局裁决权重与最差情境风险选择完整计划；它不依赖其它算法、不读取地图 ID，也不使用对手隐藏队列。
