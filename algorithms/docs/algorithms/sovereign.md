# Sovereign — 统御算法

> 歼灭模式（annihilation）独立设计的内置算法：概率齐射竞价 + 多轮炮火逃逸 + 协同让行与移动爆破。
> 独立设计边界：只依据歼灭规则、引擎行为与公开接口推导，不读取、不导入、不调用仓库内其他算法或策略辅助实现；现有算法仅作为不透明对手运行。

## 设计原则

- **以单位激活为决策单元**：引擎中一次激活 = 一次移动 + 一次攻击/治疗/爆破，顺序任意；行动点耗尽后该单位仍可完成这次激活的免费后续动作，新部署单位当回合可免费攻击/治疗。算法按"移动落点 × 后续动作"整体竞价，而不是逐动作贪心。
- **只读公开状态**：从公共快照读取地形、单位、据点、资源、炮火圈、裁决快照与配置；不使用随机数、文件、环境变量或对手内部信息。
- **参数全部取自本局配置**：兵种数值、射程、治疗量、部署折扣、行动点、伤害/治疗方差、缩圈时刻表与 `adjudicationWeights` 均实时读取，不按地图名、对手名或单位 id 分支。
- **确定性**：同一状态给出同一动作；实体/地图/对局 id 与座位标签不参与策略计算（回归覆盖重命名不变性）。

## 算法原理

### 1. 精确离散伤害与齐射竞价

伤害公式与引擎一致：`max(minimumDamage, attack − defense + Δ)`，`Δ` 在 `[−damageVarianceRange, +damageVarianceRange]` 内等概率取整数；`damageDistribution` 直接枚举全部 `2v+1` 个结果，`convolve` 在目标剩余血量处截断，因此期望伤害、击杀概率与"打空/过量"都由分布给出，而不是用均值近似。

单次击杀的估值由三部分组成：

- **军力蒸发**：`cost × 伤害 / maxHp × armyValue权重`；
- **击杀分**：`cost × (killValue权重 + 0.85)`；
- **终局惩罚**：若目标是敌方最后一个单位，额外计 `90 + 4 × unitWorth`，避免"差一刀收尾"被低估。

`salvoOptions` 对同一目标组合 2–4 个攻击单位（每单位取该目标下得分最高的选项，最多 8 个候选、枚举 8 位掩码），过滤行动点不足、落点冲突与联合击杀概率低于 0.65 的组合，再按"期望收益 + 走位改善 + 击杀后的反击减免"除以行动点成本排序（组合中不额外消耗行动点的已激活单位按 0.2 加权）。排序后只返回首个动作，下一次 `decide` 用真实状态重算，避免镜像与引擎的偏差累积。

### 2. 反击风险

`incoming` 对每个候选站位逐敌方 owner 估计下回合承伤：

- 敌军当前能直接射击该格时按必然考虑，需要先移动才够得着时按 0.8 折减；
- 若同一敌军还能打到其他友军，按其可选目标数衰减被选中的概率（`0.45 + 0.55/(1+备选数)`）；
- 每个 owner 只保留威胁最大的 `actionsPerTurn` 次射击，再逐次卷积到候选单位的血量分布上。

结果按 `id:type:hp:格索引:被击杀目标` 缓存，供攻击、移动、部署与治疗复用。该模型是启发式对抗估计，不是精确的对手策略搜索。

### 3. 多轮炮火逃逸

安全半径按引擎公式实时计算：

```
count  = round < startRound ? 0 : 1 + floor((round − startRound) / intervalRounds)
radius = max(minimumSafeRadius, map.radius − count)
```

`escapeDamage` 在最多 6 轮（受 `maxTurns` 截断）内做反向 min-plus 动态规划：除最远一轮外，每轮回推时先把"未来损失"沿相邻平地进行至多 `moveRange` 步的最小值松弛（模拟撤离线），乘 0.92 折扣，再对落在该轮安全半径外的格子加上满额炮伤。`artilleryLoss` 把最终损失折算为军力价值，并对炮火致死追加 `2.5 × unitWorth`，己方最后单位再加 400，防止把"唯一的兵被烧死"当成普通血量损失。

该推演忽略未来单位占位与爆破开路，属于乐观估计；它的作用是对撤退方向排序，而不是精确预测每一轮的落点。

### 4. 协同让行、重装开路与据点

- **权威地形**：以 `game.cells` 为底图，`map.terrainCells` 覆盖同名格；覆盖层中的 water/blocker 生效，地图空洞不可走。移动 BFS 以全部存活单位为障碍，与引擎的行进规则一致。
- **最终安全区距离场**：以 `minimumSafeRadius` 内的全部平地为中心做 Dijkstra，得到每个格子到最终安全区的距离；另做一份允许 blocker 以代价 3 通过的"爆破距离场"。
- **让行收益**：对每个占位友军，临时将其从占据中移除，比较其他可动友军（已移动或行动点不足者除外）到最终安全区的可达最小距离；若距离缩短，给该占位格累加让行收益，每名受益友军最多计 18 分，堵塞核心通道的站位会被扣分。
- **重装开路**：重装的可达落点逐格枚举相邻 blocker；只有拆除后确实缩短爆破距离场的方向才计收益（`12 + min(40, 缩短量 × 5)`；最终安全区完全不可达但能打通时固定 42）。因此支持"移动 + 同次激活内爆破"，也支持行动点耗尽后的免费爆破；重装站位另按爆破距离场每格扣 2，促使它向可开路的方向靠拢。
- **据点价值**：按 `controlPointTypes[kind]` 读取收入与 `canDeploy`，结合到达轮次、剩余可部署窗口与是否落在未来安全圈内估算；炮火吞掉据点后收入仍计，但"能否把收入花成兵力"由可用部署源决定。

### 5. 部署与经济

`deploymentOptions` 只考虑己方、非危险区、`canDeploy !== false` 的据点，落点为其相邻的空平地；费用为 `max(0, spec.cost − deployDiscount)`。每个兵种构造完整假想单位（满血、当回合可免费攻击/治疗）后综合评估：

- 兵种性价比（攻击、射程、血量、防御、治疗量）与当前兵力拥挤度；
- 落点的反击风险与炮火损失；
- 当回合立即攻击/治疗的收益；
- 补给权重与终局轮次的 `armyValue` 折现；
- 软性"攒钱买更强兵"偏好：当兵力已不少于行动点、据点未来两轮仍安全且不是终局轮时，对低质量兵种扣分，等待更贵的可用兵种；这是软约束，不会硬性禁止补员；
- 若当前已无存活单位，额外加 500，确保空场先恢复兵力。

## 实现细节

### 核心参数

| 参数 | 值 | 含义 |
|---|---:|---|
| 逃逸前瞻 | ≤6 轮 | `min(6, maxTurns − round)`，未来折扣 0.92/轮 |
| 齐射规模 | 2–4 个单位 | 联合击杀概率门槛 0.65 |
| 齐射候选 | 每目标 8 个候选 | 每单位取最高分选项后按得分取前 8，掩码枚举 |
| 移动基础罚分 | 0.4 | 同等收益下优先原地完成动作 |
| 让行收益 | 每名受益友军上限 18 | 每缩短 1 格距离计 5 |
| 爆破收益 | 12 + min(40, 缩短量×5) | 最终安全区不可达但能打通时固定 42 |
| 重装爆破距离罚分 | 2/格 | 牵引重装靠近可开路方向 |
| 反击风险折扣 | 必然 1.0 / 需移动 0.8 | 再乘目标分散系数 |
| 行动门槛 | 得分 > 0.05 | 否则返回 null 结束回合 |

### 决策流程（`decide`）

1. 门卫：非 `annihilation`、非 `active`、无当前座位、座位与 `ctx.owner` 不一致、或快照无 `artillery` 时返回 null。
2. `makeWorld` 一次性构建：地形与邻接、存活单位、占据表、安全区/爆破距离场、让行收益、各射程的接敌距离场、据点距离场、按移动力缓存的逃逸表。
3. 汇总候选：每个友军的激活选项 + 齐射选项 + 部署选项。
4. 按得分降序取最高者；得分不超过 0.05 则结束回合。

### 合法性镜像（回归覆盖）

- 移动：BFS 仅经空 plain 格，终点不得被占；`hasMoved` 只允许一次。
- 攻击：几何射程内、`hasActed` 未用；无视线/掩体判定。
- 治疗：仅 support，`healRange ?? attackRange`，施放者与目标都不得在**当前**炮火危险区；允许自疗。
- 部署：己方、可部署、非危险区据点；原点与落点都必须在危险区外；相邻空平地；折扣后费用不超过补给。
- 爆破：仅重装、相邻 blocker 且无占位。
- 行动点：已激活单位的后续动作免费；`actionsUsed >= actionsPerTurn` 只阻止新激活。
- 炮火：半径与轮界结算完全按配置推导，不写死回合表。

## 已知限制

1. **不是完整回合对抗搜索**：齐射宏只返回首个动作，随后按真实状态重算，不保留完整的多动作承诺；对手的后续应对由启发式风险评估近似。
2. **反击概率是启发式**：直接可射按必然、需移动按 0.8，再按其他友军分流；不是对手策略的均衡或抽样求解。
3. **火力与炮伤分项计价**：单位可能在"火力击杀"和"炮火击杀"叠加时仍被低估，尚未实现联合死亡概率卷积。
4. **逃逸推演是乐观近似**：忽略未来单位占位与爆破开路，只沿平地按最小累计炮伤松弛，可能低估狭窄地形下的撤离成本。
5. **最终安全区若全是 blocker**：中心距离场的源点为空，让行/开路收益退化；该场景未单独验证，随机图极端地形下可能表现不佳。
6. **部署经济是启发式**：兵种质量公式与"攒钱"偏好为人工设定，跨权重极端配置（如 `supply` 权重很高）未单独标定。
7. **多人混战**：3/6 人样本显示对 shrinkroll、crucible 无明显优势（六人 0:6），多人风险合成与目标选择仍是短板。
8. **无未来保证**：强度来自规则级建模与配置泛化，不针对具体对手；未来算法或地图若利用上述近似盲区仍可能取胜。

## 优化方向

- 把齐射升级为带对手回应的联合搜索（保留多动作承诺，加入对手最优/混合应对）。
- 将火力与炮火的死亡概率合成一个联合分布，修正残血单位的真实生存价值。
- 逃逸推演加入单位占位、爆破开路与重装通行代价，减少狭窄地形的乐观偏差。
- 多人局的目标选择与反击风险按对手威胁加权，而不是简单按 owner 分组截断。
- 对部署经济做同口径参数标定，避免质量公式在非默认权重图上偏置。

## 兼容性

- 仅 `annihilation` 模式；`standard` / `simultaneous` / `royale` 一律返回 null。
- 注册表 `ALGORITHMS` + `ALGORITHM_META` 单源接入大厅、runner、评估控制台与竞技场榜单。
- 无外部依赖、无环境变量、无文件 IO；可在进程内评估通道与 REST runner 两种链路运行。
- 决策是同步纯计算（`async` 仅为接口兼容），不发起网络请求，不修改传入快照。

## 代码结构

```javascript
// 战斗与风险
damageDistribution()  // 引擎同口径的离散伤害分布
convolve()            // 在剩余血量处截断的分布卷积
shot()                // 单位对目标的伤害分布（读取本局最小伤害与方差）
casualties()          // 军力蒸发 + 击杀分 + 最后单位惩罚
incoming()            // 候选站位的敌方回合承伤分布（按 owner 截断、缓存）

// 地形与炮火
boardFor()            // cells + terrainCells 覆盖、六角邻接
reachable()           // 移动 BFS（单位阻挡、仅平地）
distances()           // 安全区 / 爆破距离场 / 据点距离场
safeRadius()          // 引擎缩圈公式
escapeDamage()        // 多轮最小累计炮伤动态规划
artilleryLoss()       // 炮火损失与死亡惩罚计价

// 局面与动作
pointValue()          // 据点收入 × 可部署窗口
positionValue()       // 站位的炮伤、接敌、协同、让行、开路与抢点价值
makeWorld()           // 每回合一次性构建的只读世界
activationOptions()   // 单位激活：移动 × 攻击/治疗/爆破
salvoOptions()        // 多单位齐射组合竞价
deploymentOptions()   // 据点补员与假想单位评估

export default {
  name: 'sovereign',
  async decide(game, _utils, ctx) { /* 门卫 → 世界 → 候选 → 最高分 */ },
};
```

## 一句话总结

Sovereign 把一次单位激活当作一个竞价单元：用精确伤害分布组合齐射，用多轮炮火动态规划选撤退方向，用距离场让路和拆墙，再从本局配置推导补员与据点价值；它不读取其他算法，也不按地图或对手名字分支。
