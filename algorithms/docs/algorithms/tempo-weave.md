## 定位

把“让哪个单位完成什么任务、需要几个行动点、结束后还能否存活”作为决策单位。先生成完整任务，再争用本轮预算。移动→移动→攻击可作为一个任务参与比较，不会仅因第一步没有即时伤害而被删掉。

| 算法 | 主要路线 | 经纬的路线差异 |
|---|---|---|
| random-sim | 随机合法动作 | 经纬按任务收益与行动预算分配兵力 |
| dest-prob | 敌方落点概率与逐动作评分 | 经纬不建立落点分布，使用包含机动依赖的变长任务 |
| kriegspiel | 采样敌方完整计划、rollout 与计划精修 | 经纬不采样敌方计划；对己方任务做静止参照投影，使用预算化火力包络评估风险 |
| matrix-eq | 计划支付矩阵与 CFR 混合策略 | 经纬不构造支付矩阵；以按 AP 分层的有限宽度搜索排程任务 |

所有策略代码独立编写。没有导入、调用、复制或路由任何现有 builtin 算法；对手名称不参与策略。

## 通用性约束

- 地形、可玩区域取 `game.cells`；兵种参数、形状、行动点、攻击上限、裁决权重、部署折扣与入口开关取公开 `config`。
- 不读取地图名称、地图 ID；没有地图坐标表、开局走法表或按图参数。六个方向向量只是轴坐标几何定义。
- 不读取 `plan.queues`、服务器随机状态或未公开对手计划。唯一读取的计划内容是 `plan.myQueue`。不通过事件史重建任何当前秘密计划。
- 公共敌军位置只用于可达范围与火力上界。不能把这种包络解读为“已经知道对手下一步”。
- 逐席位限制敌军火力预算。多席位时，“消灭一家”并不等于胜利，因此增加第三方威胁下的回防紧迫度。
- 支持配置中的 `single`、`line`、`arc`、`attackLock`、`attacksPerUnit`、`maxTurns: null` 和可部署据点类型。
- 本轮新部署单位使用内部临时身份参与占位评估，绝不把该身份输出到 API。

## 决策流程

1. **入口与缓存校验。** 错误模式、缺少席位、淘汰、已提交或预算用尽时返回 `null`。缓存按公开棋盘、配置、席位和回合更新，复用前必须逐项核对有序队列前缀；撤回、重排、外部插入 `wait` 不会误取旧计划下一项。缓存最多保留 32 项。
2. **地形拓扑。** BFS 只把水与障碍作为墙。单位可穿过有人的路径，但候选动作的落点排除当前参照局面中的占位；已由己方前序动作腾空的格子可再次进入。
3. **任务生成。** 为单位生成直接射击、区域治疗、占点、跨步接敌后射击、脱离火力圈、攻城接近与开路任务；部署与上述任务使用同一个预算。任务按收益/行动点成本排序，每次最多保留 12 个候选。
4. **收益核算。** 占点价值包含配置中的裁决流量/期末权重、收入和部署入口价值。攻击核算伤害、残值与击杀收益。已排队集火造成的伤害在参照棋盘中扣除，减少过量射击。离开本轮刚抵达、尚未结算占领的据点会扣回对应占点收益，避免反复进出刷分。
5. **风险与多席位回防。** 按每个敌方席位的 AP 截断威胁；移动到新格、仍处于锁定圈、原地停留分别估价。三席及以上时，用接敌距离、火力预算和己方 HQ 剩余 HP 估计两轮内的压力，提高处理本部威胁的收益并降低远端攻城收益。这里是启发式软约束，不保证总部绝对安全。
6. **变长任务排程。** 以已用 AP 分桶，每层最多展开 4 个前缀、每个前缀最多扩展前 8 个任务。每个组合都重新通过独立计划合法性检查，再用分步镜像核算己方动作依赖。搜索预算为 650ms，到预算后保留已经找到的合法计划。
7. **逐条输出。** 返回 `{type,payload}`；攻击/治疗只输出格子 `q,r`。后续调用复用计划并再做合法性门控，最后返回 `null` 提交。

### 分步镜像的范围

`resolveSteps` 独立实现动作结算：级联预检 → 步初到达冲突与腾格依赖 → 部署 → 移动 → 爆破 → 待命 → 形状/锁定攻击与治疗 → 延迟判死与 HQ 淘汰。

攻击次数含已结算攻击；落空与治疗无人可治不触发硬失败连锁。治疗先补至上限再结算伤害，互杀的炮弹仍然落地。淘汰清除军队、据点中立化；仅剩一方或同归于尽时停止继续推进。

镜像的生产用途是**己方队列在静止敌军参照下的投影**，使用中位掷骰，不宣称预测真实伤害或敌方计划。测试可注入随机源对齐引擎的逐次随机抽样。它不执行轮末占点、收入、维修、翻盘补给和终局裁决，也不复刻事件日志、随机 UUID 或全量统计字段。所有胜负与成绩均由真实引擎判定。

## 已知限制

1. 有限宽度任务排程不是全局最优搜索。静止参照中成功的移动，实战中仍会因对手移动、部署或击杀而冲突、落空、级联失败；“零 API 拒绝”不等于“零结算失败”。
2. 风险系数、任务收益折算和回防压力均为通用启发式，没有对手学习，也没有博弈均衡保证。多方混战的胜率需要按席位、阵容和地图继续标定。
3. `wait` 的合法性和分步语义完整支持，但任务生成不会主动搜索预测射击时机或等待对手让路；爆破只在能改善目标可达性时参与竞争。
4. 镜像不包含轮末收入/维修等完整回合流程。经济与后续火力用启发式折算，不能保证长线围困、极端兵种数值或超大行动预算下的最优策略。
5. 650ms 是软预算，长循环检查点之间仍可能有少量额外耗时。报告中的“低于 1 秒”是本次运行环境的实测，不是任意硬件和任意规模输入上的硬实时保证。
6. 未来地图未经实测。已验证配置扰动与坐标平移的合法性，不能把现有两张图的战绩外推为所有未来地图都必胜。
7. 计时上限、机器负载以及引擎生成的 UUID 可能影响边界处的探索或对手 tie-break；同种子不承诺逐字节相同回放。报告保留实现 SHA-256、种子、座位、版本与逐局数据以便复核。

## 使用方式

本算法已随 3.8.5 集成入库：注册表已登记，标定 harness 位于 `scripts/`。大厅算法列表会从注册表自动发现“经纬算法”。

```bash
npm install
npm run build
npm test -- --maxWorkers=2 --minWorkers=1
npm run dev
node algorithms/runner.mjs --algorithm tempo-weave --url http://localhost:3100 --game <id> --token <token> --side player_a
```

仅运行新算法回归：

```bash
npm test -- tests/algorithms/tempo-weave.test.ts tests/algorithms/tempo-weave-selfplay.test.ts --maxWorkers=2 --minWorkers=1
```

## 一句话总结

经纬把攻城、占点、集火和回防组织成有成本、有先后依赖的任务，在共享行动点预算内排程，并用实际引擎验证每一条输出。
