## 为什么是"第六种完全不同的算法"

同时模式已有五条路线，各自占住一个极值：

- `random-sim`：动作级**无模型**随机（性能下界）；
- `dest-prob`：**落点概率模型**——预测敌方单位会落在哪些格，再按期望值贪心；
- `kriegspiel`：**整份计划联合搜索**——分步 rollout 评估计划组合 + 风险规避；
- `matrix-eq`：**正则形式博弈**——计划组合矩阵 + CFR 求均衡混合；
- `prism`：**情境束搜索**——对多种对手行为假设分别镜像分步结算，风险约束下选整轮队列。

它们共同的隐含假设是"这一轮怎么下最好"。tempo 换的问题是**"这一轮的每一拍分别该发生什么"**：
结算按行动点逐拍推进，早拍击杀会作废受害者后续全部动作，晚拍占点同样算分却少挨一整轮打。
拍序本身就是一种资源，前五条路线都没有把它当作一等公民来优化。tempo 的做法是：

1. 用敌方的**离散剧本**（不是概率格）投影出每一拍谁在哪；
2. 把这些投影叠成「第 k 拍 × 格子」的**威胁时间线**，给每个移动候选算"落地后还要挨几拍"；
3. 用 `adjudication` 快照的**分差 + 剩余轮数**决定这一轮是收着打还是 all-in；
4. 最后按价值把动作**排进具体的拍**：斩杀抢早、占点压尾、治疗跟在预测伤害之后。

## 算法原理

### 1. 敌方剧本预测（level-1）

对每个敌军单位，按"抢点 > 原地开火 > 残血撤退 > 推进"的通用优先级推一条最可能的行为，
输出 `posAt(k)` 与开火拍（原地开火第 1 拍、推进后开火第 2 拍）。剧本是**通明的启发式**，
不记忆对手历史、不针对任何具体算法或地图。

### 2. 威胁时间线

```
threat[k][cell] = Σ 预测射击(0.65 × 期望伤害) + 可及火力区(0.08 × 期望伤害)
```

攻击在同一拍内于移动之后结算，所以第 1 拍的威胁就按敌方投影位置计。
移动候选的暴露成本 = 落地拍起各拍威胁之和 × 单位每点 HP 价值 × 姿态系数。

### 3. 裁决姿态

读 `game.adjudication`（`weights` / `scores` / `maxTurns`）：

- `rel = (我 - 最强对手) / 归一化分母`；
- 攻击价值 × `aggression = clamp(1 - 1.5·rel)`，暴露成本 × `riskAversion = clamp(1 + 1.5·rel)`；
- 剩 ≤2 轮时推到极值：领先 0.6/1.8（保分），落后 1.6/0.6（搏命）；
- 补给权重为 0 的地图上，末轮把补给全部换成单位。

### 4. 候选与排程

候选 mission 四类：攻击（原地 / 移动后，含锁定与预测射击）、占点、治疗、部署，
外加避险/推进兜底走位。价值 = 期望伤害 × 目标每点 HP 价值 + 击杀奖金 + 据点收益，
命中概率：HQ 1.0、锁定 0.95、剧本落点 0.7、纯预测 0.55、不动的目标 0.6、会动的目标 0.22。

排程按价值贪心插入：`early` 插在已有 early 之后、`mid` 居中、`late` 压尾；
两腿 mission（移动→攻击/治疗）整对插入，先移后打；移动腿额外扣 0.3 价值（同值时少动腿优先，
降低失败连锁风险）。容量不足时整条跳过——瞄准格是按投影位置校验的，不能砍掉移动腿降级。

### 5. 接口适配与容错

- 每次 `decide` 都从**已入队前缀**（`plan.myQueue`）的投影重排剩余计划，前缀永远不被改写；
- 模块级记忆记录"某个队列长度上给过的动作"，队列没增长即判定被拒，重排时禁掉该动作；
- 全部数值读 `config` / `adjudication`，无 `mapId` 分支；炮火区仅在 `game.artillery` 存在时过滤。

## 验证（单测）

`tests/algorithms/tempo.test.ts`（11 例）：

- 计划约束：无座位 / 已提交 / AP 用尽均返回 `null`；
- 锁定射击瞄敌人当前格；移动后攻击按投影位置取瞄准格；支援治疗受伤友军；侦察兵抢可达据点；
- 被拒动作记忆：同轮同队列长度再次询问会给出不同动作；
- 反折返回归：已入队前缀里移动过的单位本轮不再排新的移动；
- 真实 `standoff`：双方整轮计划逐条通过引擎入队校验并正常结算；连续 5 轮零非法。

## 基准结果（真实引擎进程内，2026-10-24）

harness：`scripts/tempo_benchmark.mjs`——直接驱动 `dist/` 真实引擎，投影口径与
`rl/training/local-worker.ts` 的 decide 通道一致（只暴露己方 `myQueue`、携带 `adjudication`
快照、`queue*Action` 做计划期校验、`commitAndMaybeResolve` 结算），每局交替座位，
种子由（对手, 地图, 局号）派生，双方零非法动作。每对 60 局（standoff 40 + molten-throne 20）。

| 对手 | standoff | molten-throne | 合计 |
|---|---:|---:|---:|
| `random-sim` | 100%（40/40） | 100%（20/20） | **100%** |
| `dest-prob` | 37.5%（15/40） | 90.0%（18/20） | **55.0%** |
| `kriegspiel` | 32.5%（13/40） | 85.0%（17/20） | **50.0%** |
| `matrix-eq` | 40.0%（16/40） | 50.0%（10/20） | **43.3%** |

读法：

- **molten-throne 是强项**：据点权重 75 的地图上对 `dest-prob` / `kriegspiel` 有 85–90%，
  靠"抢点压末拍 + 快攻敌方总部"，对局常在 7–10 轮以 HQ 摧毁结束；
- **standoff 是弱项**：15 轮裁决局、据点流量分（权重 60）决定胜负。形状火力（line/arc）
  预判会持续消耗我的守点单位，对三个强对手只有 32–40%；
- `random-sim` 全胜属基线性质（对手随机入队），不代表强度；
- 40/20 局样本的置信区间约 ±15 个点，跨版本比较请按同一 harness、同批种子复跑。

## 首发前的实现迭代（未升版）

tempo 在 3.8.4 首发前只有一次实现迭代，因此不占用版本号：对外交付的 `v1` 已包含下面的修复，
竞技场参与者 id 从 `algo_tempo@v1` 起算。

### 修复：折返废拍

`decide` 是逐条调用的（服务器每接收一个动作就刷新状态）。原实现每次重排都会把同一个单位
派向下一个"最优"目标，于是队列里出现 `A→B→A→B` 的折返——实测一局 4 个行动点全耗在
一个侦察兵来回走，其余单位整轮待机。修法是候选层约束：已入队前缀里排过移动的单位，
本轮不再生成新的移动候选（只保留原地攻击/治疗）。

### 修复前后同口径对照（真实引擎进程内、同种子、交替座位、同一 40+20 分片）

| 对手 | 修复前（60 局） | 修复后（60 局） | 变化 |
|---|---:|---:|---|
| `dest-prob` | 31.7% | 55.0% | **+23.3** |
| `kriegspiel` | 50.0% | 50.0% | 0 |
| `matrix-eq` | 46.7% | 43.3% | −3.4（噪声内） |
| `random-sim` | 100% | 100% | 0 |

分图看，修复把 molten-throne 上对 `dest-prob` / `kriegspiel` 的胜率从 45% 拉到 85–90%，
代价是 standoff 对 `kriegspiel` 从 52.5% 掉到 32.5%：折返废拍在短回合、快攻图上是纯亏，
在长裁决图上偶尔起到"乱走位躲预判"的作用。按模式整体均值，修复后仍占优。

### 代价与边界

- 决策耗时：`decide` 单次 0.1–0.5ms（`random-sim` 对手）到 15–47ms（`kriegspiel` 对手整局均值，
  主要花在敌情投影与候选枚举）；无非法动作、无超时。
- **实测负收益、已回退的路线**（不写进实现）：整轮计划缓存切片（standoff 对 `dest-prob` −20 点）、
  强制生产配额（molten-throne −25 点）、两跳占点、远征计价、总部拦截、集火加成、稀缺度乘数、
  占点压制加成（−5 点）。它们各自在小样本上像"增益"，叠加后是净损失——本档案因此坚持
  "同口径、同种子、≥40 局/图才下结论"。

## 已知限制

- **standoff 的裁决局偏弱**：据点流量分主导的地图上，形状火力（line/arc）预判会持续消耗我的守点单位，
  目前只有 32–40% 对三个强对手；
- **单层剧本**：敌方只按一条最可能剧本投影，遇到随机化程度高的对手预测命中会被高估；
- **贪心排程**：不回溯，多腿 mission 挤不进容量就整条丢弃；
- **不做联合计划搜索**：不比较整轮 5 拍的全组合（那是 kriegspiel / matrix-eq 的路线），上限受候选粒度限制；
- **多人局**（standoff 3/6 人）只按全体敌人各自最优剧本叠加威胁，未建模敌人之间的互相牵制。

## 使用方式

```bash
# 命令行
node algorithms/runner.mjs --algorithm tempo --url http://localhost:3100 \
  --game <gameId> --token <playerToken> --side player_a
```

竞技场评估控制台规格：`algo:tempo`；榜单参与者 id：`algo_tempo@v1`。

## 一句话总结

把"这一轮怎么下"拆成"每一拍该发生什么"：先预测敌人每拍在哪，再让自己的斩杀落在前拍、占点落在末拍。
