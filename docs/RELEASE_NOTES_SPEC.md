# RELEASE_NOTES 编写规范

本文档规定 `RELEASE_NOTES.md`（版本迭代日志）的版本号语义与条目组织方式。版本号规则遵循[语义化版本 2.0.0（中文版）](https://semver.org/lang/zh-CN/)。

## 1. 版本号：主版本号.次版本号.修订号

版本格式为 `X.Y.Z`（X = 主版本号 Major，Y = 次版本号 Minor，Z = 修订号 Patch），X/Y/Z 为非负整数。语义化版本的核心约定：

- 已发布的版本内容不可变更，任何修改都必须以新版本号发布；
- 有破坏性变更（不兼容的修改）时递增主版本号，此时次版本号与修订号归零；
- 向下兼容的功能性新增递增次版本号，此时修订号归零；
- 向下兼容的问题修正递增修订号；
- 每次递增必须比上一次至少多 1，且不得在数字前补零。

本项目对外契约（相当于 SemVer 语境下的「公开 API」）包括：

- REST 接口（`src/api/`：路径、请求/响应结构、鉴权语义）；
- SSE 事件流与事件 payload schema（`src/engine/events.ts`）；
- 持久化与恢复格式（`runtime/games.json`）；
- 回放导入/导出格式与 `records/` 存档结构；
- `skill/` 规范文档的协议约定（流程、接口、`wait-turn.mjs` 退出码契约、文件清单）；
- 前端页面入口（`public/*.html`）与共享模块对外暴露的接口。

对应到本项目的递增判定：

| 改动内容 | 递增位 | 本项目示例 |
| --- | --- | --- |
| 不兼容修改：破坏上述任一契约（改路径/字段语义、删除对外能力、旧持久化或旧回放无法读取、玩法规则不兼容升级） | 主版本号 X | 3.0.0 双人对战升级为 2-8 人多人混战，胜负规则、回放与 skill 协议全面变更 |
| 向下兼容的功能性新增：新接口、新模式、新地图、新页面、新算法/模型、新统计维度等 | 次版本号 Y | 3.3.0 新增同时回合模式、3.4.0 强化学习 AI 上线 |
| 向下兼容的问题修正与内部改进：bug 修复、性能优化、文案/样式/平衡性调整、文档补充 | 修订号 Z | 3.3.1 修复同时模式兼容构造器、3.1.7 大厅选图卡片重排 |

本项目自 1.0.0 起即为正式版本，不使用 0.y.z 开发阶段命名；先行版本号与版本编译元数据（如 `3.6.0-rc.1`）暂未使用，如需引入应遵循 SemVer 第 9、10 条。

## 2. 版本小节结构

每个版本一个小节，标题格式固定为 `## x.y.z`（`script/bump-version.mjs` 依赖该格式检测与插入占位小节），版本按倒序排列。小节内部按以下固定顺序分类，无内容的分类省略：

```markdown
## x.y.z

### 新增
- ...

### 变更
- ...

### 修复
- ...

### 移除
- ...

### 测试与验证
- ...
```

分类定义：

- **新增**：新功能、新模块、新接口、新地图、新页面、新算法/模型、新文档。
- **变更**：对既有功能、行为、数值、文案、结构、文档的调整，含重构、平衡性调整、体验优化、版本号提升。
- **修复**：缺陷修正，含补齐此前缺失或失真的行为与数据。
- **移除**：功能、页面、限制、文档等的删除与下线。
- **测试与验证**：测试用例补充与端到端验证记录，置于小节末尾。

归类原则：

- 按条目的**主导效果**归类，一条只进一个分类；混合改动以主导效果为准，其余内容在条目正文里自行说明，不拆散原条目。
- **破坏性变更**条目应在句首加「**破坏性变更**：」标注；含此类条目的版本必须递增主版本号。
- 版本号递增位 = 该版本所有条目对应的最高级别：含「新增」→ 次版本号；仅「修复」与向下兼容的「变更」→ 修订号；含「破坏性变更」或「移除」对外能力 → 主版本号。
- 3.0.0 之前的历史小节保持原始叙事格式，不回改。

## 3. 条目书写

- 每条一个主题，粗体导语概括主题，正文给出细节、数据与影响面，保留可追溯的文件路径与数值。
- 不改写既有条目的历史语义：整理历史版本时只做分类归位，不重写事实。
- 版本号提升本身（`npm run version`）一般不单独立条，除非伴随其他值得记录的改动。

## 4. 与版本工具的配合

- 发版：在 `release/x.y.z` 分支上执行 `npm run version x.y.z`，脚本会同步全部版本引用，并在 `RELEASE_NOTES.md` 插入 `- TODO 补充本版本改动` 占位小节，随后由作者替换为完整的分类小节。
- 一致性校验：`npm run check-version`。

## 5. 历史说明

3.0.0 起的小节已按本规范补加分类。3.x 的历史版本号沿用发布时的实际编号——其中部分含功能新增的版本使用了修订号位（例如 3.2.2 新增歼灭模式、3.4.1 新增随机地图系统），按第 1 节的现行规则应记为次版本号；为保持既有引用与阅读习惯，历史编号不回改。自本规范确立起，新版本严格按第 1 节递增。
