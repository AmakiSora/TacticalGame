## 核心教训

### 致命错误: 完全忽视了游骑兵射程3可远程直轰我方HQ的威胁

对手在R6部署游骑兵 `ef10f2cf` 于 (5,-4)，R7再部署第二架 `0da055ba` 于 (4,-2)，均利用 cp_ne（forward_base，部署折扣-8，造价仅70）低耗产出。游骑兵 `attackRange=3`、`attack=44`，从 (7,-2) 到敌方 HQ(8,0) 的六边形距离恰好为 3（`max(|7-8|, |-2-0|, |-(-5)-(-8)|)=3`），完全在射程内。

```text
第8轮 / player_a: ranger ef10f2cf 从 (7,-2) 射击我方 HQ(8,0) → 42 伤害，HQ 100→58
第8轮 / player_a: heavy(3,-2) 集火我 heavy(2,-2) → 29 伤害，71→41
第8轮 / player_a: scout(3,-3) 补刀 → 4 伤害，41→37
第9轮 / player_a: ranger ef10f2cf 射击 HQ → 46 伤害，58→12
第9轮 / player_a: ranger 0da055ba 射击 HQ → 42 伤害，12→0 → headquarters_destroyed
```

我方全程未部署任何游骑兵或支援单位来反制远程威胁，也从未意识到石墙无法阻挡 3 格射程的攻击。这是本局最致命的战术盲区。

## 失误与改进

### 失误1: 对游骑兵射程3的威胁完全低估（最致命）

**问题:** 破障行动地图中央有十字石墙阻断通行路径，直观感觉是"必须拆墙才能攻击HQ"。但游骑兵 `attackRange=3` 不需要贴脸——从东北侧 (7,-2) 到 (8,0) 的六边形距离恰好为 3，可隔墙直轰。对手利用 cp_ne 的 forward_base 部署折扣（游骑兵造价从 78 降至 70），R6-R7 连续两轮换出 2 架游骑兵，随后 R8-R9 每轮对 HQ 造成 42-46 伤害，3 次射击即摧毁。

**改进:**
- 开局后必须检查 `config.units.ranger.attackRange`，若 ≥3 则预判其可跨墙攻击
- 在对手 cp_ne/cp_sw 出现游骑兵时，必须立即用己方游骑兵或高机动单位抢占拦截位
- 至少部署 1 架游骑兵作为对等远程火力，或部署 support 为 HQ 建立缓冲

**预期收益:** 己方拥有一架游骑兵即可在 R7-R8 反击对手游骑兵（双方 AR=3 对射），大幅降低己方 HQ 承伤。即使不击杀，游骑兵每轮对敌方 HQ 造成 44 伤害也可积累 `enemyHqDamage` 裁决分。

### 失误2: 据点争夺严重落后，经济差距拉大到无法挽回

**问题:** 对手在第3轮就扫荡了 cp_w、cp_sw、cp_ne 三个己方 CP（加上 cp_nw 共 4 个），我方仅持 cp_se + cp_e 两个。据点控制差距导致：

| 项目 | 我方 (2 CP) | 对手 (4 CP) | 差距 |
|------|-------------|-------------|------|
| 每轮收入 | 10+20+8 = 38 | 10+20+8+8+8 = 54 | -16/轮 |
| 部署折扣 | 无（cp_se 为 supply，cp_e 为 repair） | cp_ne forward_base -8 | 对手游骑兵 70 部署 vs 我方 78 |

第3轮后对手每轮多 16 补给，到第9轮累计差距 128 补给，足以多出 2 架游骑兵和若干 scout。

**改进:**
- R3 在占 cp_e 的同时，应考虑先部署 scout 推进至 cp_ne(4,-3) 邻位（scout MR=5，从 (6,0) 出发可 2 步到达），抢占部署点
- forward_base CP 的部署折扣（-8）对高造价单位（heavy 92→84，ranger 78→70）价值极大，必须优先争夺

**预期收益:** 若 R3 抢占 cp_ne，对手无法享受 forward_base 折扣，游骑兵造价从 70 升至 78，经济差距缩小约 8 补给/架，至少延后 1-2 轮游骑兵登场。

### 失误3: 过度依赖 heavy 攻坚，输出结构单一

**问题:** 全局限死了 heavy(2,-2) 一个单位来对敌方 heavy 造成输出（累计 29+25+29+28+24=135 伤害），7 个回合才将敌方 heavy 从 150 打至 15 HP，始终未击杀。同时：
- 己方 scout(4,-2) 在 R5 被敌方双重攻击击杀（敌方 2 单位集火，scout 仅 65 HP）
- scout(3,-1) 在 R8 部署后 R9 未执行攻击（因 API 调用使用了错误的单位 ID `f1076ae2-3b4c-5d6e-7f8a-9b0c1d2e3f4a`，正确 ID 为 `f1076ae2-e1ca-4be5-98cf-3a6236312acc`，导致攻击静默失败、AP 浪费）
- 始终未部署 ranger 或 support

**改进:**
- scout 部署后必须立即攻击邻近敌方单位，不要等到下个回合
- API 调用前始终从最新 `GET /api/games/:id` 响应中读取单位 ID，不可凭记忆拼接
- R5 起每回合至少保留 1 AP 用于 deploy（即使当前不缺单位），以保持对对手新单位的应对灵活性

**预期收益:** 正确执行 scout(3,-1) 攻击可在 R9 额外造成 16 伤害，将敌方 heavy 从 15 降至 -1（击杀），减少对手对己方 heavy 的输出压力。

### 失误4: 缺乏对 HQ 的正面保护与反制措施

**问题:** 我方 HQ(8,0) 在整个游戏期间无任何单位贴身保护。对手游骑兵只需在 (7,-2) 或 (6,-3) 等位置即可远程射击。我方所有重型火力都集中在左翼对敌方 heavy 的消耗上，右侧（东侧，即 HQ 方向）始终空虚。

**改进:**
- 在拥有 scout MR=5 的高机动性下，应在 R4-R5 即部署 1 架 scout 驻守 HQ 邻位（如 (7,0) 或 (8,-1)），即使不能击退游骑兵，也能通过阻挡部署路径干扰对手
- 在对手游骑兵出现后（R6），应至少将 1 架 heavy 调回防守 HQ，而非继续投入左翼消耗战

**预期收益:** heavy(40 ATK) 在 (7,0) 可攻击 (7,-2) 的游骑兵（距离 2，但 heavy AR=1 无法触及），实际仍需 scout 或部署另一架 heavy 至 (6,-2) 邻位才能反击。更优方案是 R5 部署游骑兵对射。

## 总结

### 失败关键因素
1. **游骑兵远程威胁完全未预判** — AR=3 可隔墙直轰 HQ，十字墙无法提供保护
2. **据点争夺严重落后（2:4）** — 对手多出 16 补给/轮和 forward_base 部署折扣，经济碾压
3. **输出结构单一** — 全部依赖 heavy 攻坚，未部署 ranger 对射，也未部署 support 治疗
4. **API 操作失误** — R9 scout 攻击使用了错误单位 ID 导致攻击静默失败，浪费 1 AP

### 核心战术原则

> **"标准模式下必须时刻检查敌方远程单位射程——石墙挡不了 AR≥3 的远程火力，HQ 永远是最脆弱的目标。"**

### 一句话总结

**在破障行动这张图上，游骑兵 3 格射程可以隔墙直轰 HQ——不部署对等远程火力等于送死，据点控制差距 1:2 就会经济崩盘。**
