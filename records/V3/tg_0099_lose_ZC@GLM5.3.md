## 核心教训

### 致命错误: 三次操作失误（R6路径误判、R8/R13的ID与脚本连环失败）合计浪费约3个整回合的行动量，叠加"补给花光不留终轮兑换银行"，被对手末轮一波爆兵裁决翻盘

1. **R6 北重型路径误判**（seq前 API 失败 `target is not reachable`）：目标 (-8,-1) 的最短路径被敌侦察兵 56a01b68 占据的 (-6,-1) 封死，实际需4步超出移动力3，当回合首击敌HQ计划落空，整整延迟到R7（seq115 才打出41伤害）。若R6成功，heavyN 以60血贴脸可打满2击（约80伤害，+195分）。
2. **R8 手写单位ID失败**（`unit_not_found`）：预备步兵 a81db95b 的完整ID凭记忆编造出错，移动未执行；同轮部署 (4,1) 又因与 cp_e(3,0) 不相邻失败——**全轮仅完成1次攻击（1/5 AP）**。
3. **R13 整轮作废**：ID提取脚本未过滤阵亡单位且临时文件路径在 Windows 下失效，导致 JSON 拼接损坏、移动/攻击全部失败后误触 end-turn——**零有效行动白丢一整轮**，而这正是最终222分差距中最大的一块。
4. **战略层：补给兑换时机完败**。双方全程部署花费几乎相等（我646 vs 对手651），但对手把226补给留到第15轮才兑换成3个游骑（seq275-277，cp_w×78、cp_sw×70、cp_nw×78），零死亡风险全额转化为军力值×2；我方每轮花到只剩0~16，中期买的单位又有7个（508军力值）相继阵亡。

正确做法：每一步移动前用六角格三分量公式+占位检查程序化校验路径与目标ID（本局R2/R8/R13共4次ID或路径错误，全是 tg_0097 已写过的教训）；同时在 armyValue×2 的地图上从第10轮起至少保留78+补给的"终轮银行"，逼迫对手的爆兵优势无法单方面兑现。
