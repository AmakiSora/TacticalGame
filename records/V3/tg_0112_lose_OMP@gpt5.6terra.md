### 致命错误: 把外圈单位留在炮火预警线上，并在敌方经济与远程火力成型后才转入保军

第4轮炮火预警（seq 54）已经给出安全半径6与下一圈 warningCells；第5轮收缩至安全半径5（seq 71），第7轮收缩至4（seq 101）。我方 infantry `e2dd...` 留在 `(4,1)`，连续承受第7、8、9、10轮炮击：25、25、25、25点；第9轮时 `336d...` 在 `(-1,-3)` 被炮火直接击杀。第9轮收缩至安全半径3后，`e2dd...` 和 `b068...` 仍在外圈，分别继续掉血；第10轮结束时这些外圈单位死亡或濒死，最终在第11轮收缩至安全半径2后我方全灭。

**正确做法:** 第4轮预警出现时，立即把所有位于未来危险圈、尤其是 `(4,1)` 与 `(3,1)` 的单位向中心安全格撤离；第5轮收缩前不要把低血量 infantry 留在外圈。炮火模式中，保留一支满血 heavy 和至少一支可撤离 infantry 的价值高于继续占据外圈位置。

## 补给与分数账本

**实际情况:**
- 初始补给：配置 `startingSupplies=45`；各阶段 API 快照中的补给变化受收入与部署共同影响，逐事件的完整初始余额未在回放摘要中单独提供。
- 我方部署：初始 `infantry×2 + heavy×1`；第1轮部署 infantry×1；第3轮部署 infantry×1；第5轮部署 infantry×1。回放统计我方 `deploy` 事件共3次，部署类型均为 infantry，实际总花费可由实例成本核对，但部署前后的逐笔余额回放未提供完整可靠账本，不能伪造逐笔精确余额。
- 基础收入：`baseIncome=8`；我方前期控制 `cp_east`（forward_base，收入4）与 `supply_east`（supply，收入8），因此典型整轮收入为20。对手控制4个据点时收入为36（seq 38、55、72等 income 事件）。
- 无效或低收益开销：第3轮在 `(4,1)` 部署 infantry；第5轮首次收缩后仍从 `cp_east` 向 `(3,1)` 部署 infantry；第4轮预警后未撤离外圈单位，导致之后多次25点炮火承伤。这些不是单纯补给浪费，而是把部署和行动点转成了会被炮火快速削减的军力价值。
- 炮火承伤：回放明确记录的我方炮火事件包括 `336d...` 第9轮死亡；`e2dd...` 在第7、8、9、10轮各承受25并最终归零；`b068...` 在第9、10轮各承受25，终局前降至50。其余死亡若同时受到攻击与边界炮火，单凭摘要无法可靠拆分每个单位的最终伤害来源。
- 最终六项裁决分（值 × 本局权重）：HQ伤害不适用（无HQ，权重0）；HQ HP不适用（无HQ，权重0）；据点2×0=0；军力0×2=0；补给102×0=0；`actionScore=240`（已是最终加分，不再乘 effectiveActions）。总分 **240**。

**正确策略估算:**
- 若第4轮预警后不再从东侧外圈部署，并用2—3个激活机会把 `(4,1)`、`(3,1)` 和低血单位撤至安全半径内，至少可避免已记录的多次25点炮火承伤；这是基于炮火配置和单位坐标的策略估算，不是回放事实。
- 若同时把第5轮部署改为向安全中心部署，或者保留补给等待安全格，预期收益是保住更多军力价值并延长最后生还时间；是否足以逆转对手4据点经济，回放无法证明。

## 经验教训

### ✅ 做得好的
1. **第1轮抢到本侧补给点并获得有效行动分。** `player_a` 的 infantry 在 `(5,0)→(3,0)`，第1轮结束占领 `supply_east`；第2—5轮连续攻击造成真实伤害，actionScore从早期快照的30逐步提高到终局240。没有把整局完全浪费在空移动上。
2. **对敌方前线单位实施了集火。** 第2—5轮攻击敌 infantry、scout、heavy，最终击杀了敌 scout和一名 infantry；说明攻击优先级方向正确，但没有与炮火撤离结合。

### ❌ 致命失误
1. **忽略第4轮 artillery warning。** seq 54 已明确预警，仍让东侧外圈单位留在 `(4,1)`、`(3,1)` 附近；之后 `e2dd...` 连续承受4次25点炮火，`336d...`在第9轮被炮火击杀。
2. **首次收缩后继续外圈部署。** 第5轮 safeRadius=5 后仍从 `cp_east` 向 `(3,1)` 部署 infantry。该部署没有足够时间在第7轮收缩前撤离，反而增加了炮火暴露单位数。
3. **经济差距形成后没有把据点当作部署网络争夺。** `player_b` 第2轮已控制4个据点并获得36/整轮收入；我方只有2个据点、20/整轮收入。虽然据点权重为0，但它们决定可用补给与部署来源，仍应派一名 capturer 抢中部安全据点或切断对手收入。
4. **对行动点和位置合法性的核验不够稳定。** 实战中多次出现移动/攻击不可达或超射程尝试。每次 API 失败都消耗了决策时间，且暴露出没有在调用前按当前单位实例、`game.cells`、六边形距离和占用情况做完整检查。

### 🔑 核心教训
> **“炮火预警出现即撤离外圈；据点权重为0也要抢，因为它决定收入、部署和最终军力。”**

## 下次的正确策略

```text
第1轮 / player_a:
  两名 infantry 中一名抢最近安全 supply，另一名沿中心推进；heavy 只推进到能支援中心的位置。
  保留至少1个单位专门观察中部安全据点，不把全部AP投入同一条外圈战线。

第2—3轮 / player_a:
  每次回合开始先核对双方据点、补给与炮火状态；若 player_b 已取得3—4个据点，优先派 capturer 争夺安全中部据点或切断其部署链。
  攻击只选择可在当前实例射程内造成实伤害的目标；所有移动先验证 game.cells、单位占用和逐格可达路径。

第4轮 artillery warning:
  立即把所有位于 warningCells 或无法在下一次收缩前离开的单位撤入当前 safeRadius 内；停止向外圈部署。
  这是硬触发条件，不因一次近战机会而推迟。

第5轮首次收缩后:
  先保军，再攻击。优先移动低血单位和未来危险格单位；heavy 留在安全中心作为反击核心。
  若敌方 ranger 成型，采用中心集火和安全距离，不用外圈低血 infantry 换取一次低收益攻击。

第7轮及以后:
  每次 shrink 前重新计算安全半径、warningCells、dangerCells 和下一收缩轮；任何单位若下一边界会承受25伤害且不能保证击杀，必须撤离。

终局检查:
  先确认是否仍有存活单位；再看 armyValue、actionScore、补给和据点。歼灭模式中“有补给”不等于“能继续比赛”，最后单位必须活着。
```
