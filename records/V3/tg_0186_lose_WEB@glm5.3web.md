## 失误与改进

1. **R7 部署 API 失败且未验证（最大操作失误）**
   - 实际做法：POST /deploy 只传 `unitType/q/r`，漏 `fromId`（规范明示 `fromId` = HQ 实体 ID 或自有据点 ID）；收到异常响应后未核对单位列表与资金即 end-turn（end-turn 亦 400，但回合照样流转）。
   - 正确做法：每次动作（deploy/move/attack）后立即 GET state 验证生效（部署 = units 出现新单位 + 资金扣减）；失败当回合按 400 错误信息重试——R8 补上 fromId 后一次成功，证明当回合内可修复。
   - 触发条件：任何 API 动作返回非 200，或响应体与预期不符时。
   - 预期收益：游侠提前 1 轮登场。**须诚实标注：本图地理下即使 R7 成功，北走廊炮位仍需 R11 才首炮，仍晚于 R10 的 HQ 死亡——单独修复此失误不足以翻盘，必须叠加第 2 条。**
2. **未按地图设计执行重装爆破路线（最大战略失误）**
   - 实际做法：沿用"侦察占点 + 游侠远程轰"的通用打法；全局无重装、无拆墙，R7 才部署主力。
   - 正确做法：开局读 `config.description`（「双方 HQ 仅隔 4 格…唯一的突破口是重装兵的爆破」）+ 障碍分布（空心墙结构），识别胜负机关后约 R3–R4 部署重装（50 金）走中路对轰——敌方正是此剧本（~R4 部署→R7 拆 (1,0)→R10 击杀）。镜像对轰下我有先手 + R6 已先手贴脸 11 点，HQ 竞速占优。
   - 触发条件：新对局读完配置与地形后的第一个部署决策。
   - 预期收益：把败局变成竞速局；按先手差估算约等于抢先 1 回合完成击杀（避免 -2273 分差）。
3. **纸面火力路线（次要失误）**
   - 实际做法：把 (1,2)/(0,1) 当作游侠射程内炮位，R9 两笔调用被服务器拒绝（"target is not reachable" / "out of range (5>3)"）。
   - 正确做法：规划远程单位前先做几何预演：敌 HQ 射程 3 炮位格 ∩ 我方可达路径（计入障碍与敌占格）；发现唯一通路为北走廊 12 格后，R8 部署即改道。
   - 触发条件：任何远程单位的火力路线规划前。
   - 预期收益：省 1 回合行军；避免依赖直觉坐标造成的行动空转。
