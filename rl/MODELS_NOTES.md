# RL 模型说明

本文按“一个模型一个大标题”组织。以后新增模型时，应新增一个独立的二级标题，并完整填写该模型的文件、版本、网络、输入输出、训练数据、对手、策略、性能、部署方式和兼容性；不要只在总表里追加一行。

资料来源：`rl/RELEASE_NOTES.md`、`rl/README.md`、`rl/env.py`、`rl/env_v200.py`、`rl/local_env.py`、`rl/train.py`、`rl/evaluate_cross.py`、模型 zip 内的 `data`/`system_info.txt`，以及 `rl/tb/` TensorBoard 日志。性能数字只对注明的评估协议负责，不代表所有地图、座位或真人对手上的泛化能力。

## 模型 1：hex_ppo_v2.1.1_20260825_default_rule_mixed_500000

### 身份与文件

- **文件**：`rl/models/hex_ppo_v2.1.1_20260825_default_rule_mixed_500000.zip`
- **定位**：当前默认推荐模型，适用于 v2.1 普通双人顺序模式。
- **训练环境版本**：v2.1.1（2026-08-25）。v2.1.1 修复了 12 个稳定单位槽中空槽治疗访问 `None` 的崩溃问题；观察空间、动作空间和模型兼容性没有变化。
- **地图/对手标记**：`default` 地图，`rule_mixed` 对手；每局在 aggressive、defensive、economy 三种规则风格中随机选择。
- **训练步数**：目标 500,000；zip 中 `num_timesteps=500,224`。
- **文件大小**：约 6.27 MB。
- **参数量**：514,039 个可训练参数。
- **推荐运行器**：`rl/run_model.py`；服务端根据动作空间 54 自动路由到该运行器。

### 网络与序列化参数

算法为 `sb3_contrib.MaskablePPO`，策略为 `MaskableActorCriticPolicy`/`MlpPolicy`。actor 与 critic 不共享 MLP：

```text
policy_net: Linear(3922, 64) → Tanh → Linear(64, 64) → Tanh → action head(54)
value_net : Linear(3922, 64) → Tanh → Linear(64, 64) → Tanh → value head(1)
```

zip 元数据记录：Python 3.14.5、Stable-Baselines3 2.9.0、PyTorch 2.11.0+cu128、Gymnasium 1.3.0、NumPy 2.5.2；训练机检测到 CUDA。运行时依赖仍应以当前 `rl/requirements.txt` 和本机设备为准。

### 观察空间

模型接收固定长度 `Box(-1, 1, float32)`，形状为 **3,922**：`217 个地图格 × 18 个格特征 + 16 个全局特征`。

- 每格：plain/water/blocker 地形 3 维；无据点/己方据点/敌方据点 3 维；空地/己方/敌方实体 3 维；5 种单位类型 one-hot；生命比例；`hasMoved`；`hasActed`；1 个预留位。
- 全局：双方补给、双方 HQ HP、回合数、行动点消耗、双方据点比例、双方存活单位数；分别按 300、200、20、5、20 等比例归一化并裁剪到 `[-1,1]`。
- v2.1 的相对视角已修正：模型坐 `player_a` 或 `player_b` 时，自己的单位、HQ、据点和资源始终编码为“己方”。

### 动作空间与合法动作

动作空间为 **`Discrete(54)`**，索引语义固定：

| 索引 | 语义 |
|---:|---|
| 0 | `end_turn` |
| 1–48 | 12 个稳定单位槽 × `move`、`attack`、`heal`、`special` |
| 49–53 | `infantry`、`scout`、`heavy`、`ranger`、`support` 部署 |

单位首次出现时分配稳定槽位，移动、受伤和排序变化不会改变槽位；死亡后释放槽位，新部署单位再使用空槽。`special` 当前主要承载重装单位相邻阻挡地形的 `demolish`。所有当前不可执行的槽由 `action_masks()` 屏蔽，MaskablePPO 不会对这些槽采样。

移动候选使用 BFS 计算可达路径，可以绕开水域、阻挡和占用格；部署候选从 HQ 或己方据点相邻的空 plain 格中选择，并倾向于更接近敌方 HQ 的位置。

### 训练过程与超参数

训练入口为 `rl/train.py`，环境为 `LocalHexGameEnv`。Python 通过持久 JSON-lines worker 调用 `rl/local-worker.ts` 的 TypeScript 引擎，不需要启动 HTTP 服务器；每次 reset 新建一局 `default` 双人顺序地图，agent 默认是 `player_a`，规则对手是 `player_b`。并行环境数为 1，主要吞吐瓶颈是游戏模拟而非 MLP 更新。

| 参数 | 值 |
|---|---:|
| `learning_rate` | 3e-4（常数） |
| `n_steps` | 256 |
| `batch_size` | 64 |
| `n_epochs` | 10 |
| `gamma` | 0.99 |
| `gae_lambda` | 0.95 |
| `clip_range` | 0.2 |
| `ent_coef` | 0.01 |
| `vf_coef` | 0.5 |
| `max_grad_norm` | 0.5 |
| 评估 | 每 10,000 步、每次 20 局 |
| checkpoint | 每 20,000 步 |

训练支持 `RL_DEVICE=auto/cuda/cpu`、`RL_LOAD_MODEL=auto/latest`、断点续训、TensorBoard 和 best checkpoint。观察或动作契约不一致时会拒绝续训；v2.1 模型必须在 v2.1 环境中使用。

### 训练对手

`mixed` 每局从三种风格随机选择，降低单一脚本过拟合：

- **aggressive**：攻击 → 移动 → 补给至少 60 时部署 → 治疗；
- **defensive**：攻击 → 治疗 → 补给至少 70 时部署 → 移动；
- **economy**：补给至少 90 时部署 → 移动 → 攻击 → 治疗。

三种风格共用目标导向的合法动作生成器：攻击优先 HQ/高价值目标，治疗优先生命缺口最大的单位，可捕获单位向未占据据点推进，其他单位向敌军或 HQ 靠近。它仍不是自我对弈，未覆盖真人的诱骗、牺牲和非贪心战术。

### 奖励与策略倾向

v2.1 在 agent 动作完成后立即读取状态并结算奖励，再执行对手回合，避免把对手攻击或占点错误归因给 agent。奖励包括：

1. 裁决分增量：`clip((immediate_score - previous_score)/100, -1, 1)`；
2. 稠密塑形：占据据点每个 `+0.7`，敌方 HP 下降按 `/100`，己方 HP 恢复按 `/160`，接近未占据据点每格 `+0.025`；部署 `+0.12`，攻击 `+0.05`，没有占点进展的结束回合 `-0.01`；
3. 终局胜利 `+1`、失败 `-1`；最终返回值裁剪到 `[-2,2]`；非法动作 `-0.05`。

因此模型被鼓励尽早部署、用可捕获单位推进、争夺据点、在攻击与治疗间按即时裁决分取舍，并用重装爆破绕开阻挡。以上是奖励和环境偏置下的可解释倾向，不是对网络内部决策的严格证明。

### 性能记录

来源：`rl/tb/ppo_default_20260825-053124_1`，每次评估 20 局、确定性策略、mixed 规则对手，共 50 个评估点：

| 指标 | 结果 |
|---|---:|
| rollout 平均回报 | 10.47（256 步）→ 24.24（500,224 步） |
| rollout 平均 episode 长度 | 62.0 → 83.54 |
| 评估平均回报 | 全程均值 24.26；范围 20.30–25.79；末 10 次均值 25.16 |
| 评估胜率 | 全程均值 38.5%；单点评估最高 70%；最后一次 55% |
| 平均己方据点数 | 全程均值 2.09；末 10 次均值 2.34；最高 2.70 |
| explained variance | 早期 -0.04，训练末期约 0.995 |

`best/best_model.zip` 按平均回报选择，不按单独胜率选择；当前 best 文件对应 480,000 步检查点，而正式发布文件是完整训练到 500,224 步的最终快照。评估 callback 还会在终端输出部署、攻击、移动和结束回合次数，但历史 TensorBoard 文件没有持久化这些动作计数。

### 部署与兼容性

直接使用 `run_model.py`，模型动作空间必须为 54。它可以坐 `player_a` 或 `player_b`，并使用对应座位的相对视角编码。模型只适用于普通双人顺序地图；`standoff` 同时回合、`artillery-zone` 歼灭规则及多人地图需要单独环境。

## 模型 2：hex_ppo_v2.0.0_20260824_default_rule_500000

### 身份与文件

- **文件**：`rl/models/hex_ppo_v2.0.0_20260824_default_rule_500000.zip`
- **定位**：v2.0.0 历史正式模型，保留用于旧版本大厅和跨版本离线对战。
- **训练环境版本**：v2.0.0（2026-08-24）。该版本把随机合法动作对手替换为简单规则对手，并首次使用固定意图槽位。
- **地图/对手**：`default` 地图，单一 `rule` 对手。
- **训练步数**：目标 500,000；zip 中 `num_timesteps=500,224`。
- **参数量**：512,999；文件约 6.26 MB。
- **推荐运行器**：`rl/run_model_v200.py`；必须搭配不可变环境快照 `rl/env_v200.py`。

### 网络、观察和动作

主体网络同样是两个 `3922 → 64 → 64` 的 Tanh MLP；action head 为 `38 × 64 + 38`，总参数 512,999。观察向量仍为 3,922 维、217 格×18 特征+16 全局特征，但当时编码固定以 `player_a` 为己方视角。

动作空间为 **`Discrete(38)`**：`end_turn` 1 个、8 个单位槽×4 意图 32 个、5 个部署槽。v2.0 的单位由当前状态排序后截取前 8 个，槽位不像 v2.1 那样跨状态稳定；因此必须使用 `env_v200.py` 的合法动作和编码逻辑。

### 训练过程与对手

算法仍是 MaskablePPO，正式 zip 的主要超参数为 `learning_rate=3e-4`、`n_steps=256`、`batch_size=64`、`n_epochs=10`、`gamma=0.99`、`gae_lambda=0.95`、`clip_range=0.2`、`ent_coef=0.01`、`vf_coef=0.5`、`max_grad_norm=0.5`。训练通过本地 TypeScript worker 运行，默认 500,000 步。

规则对手优先级为：有攻击先攻击；否则治疗；补给至少 90 时部署；否则移动；都不可用时结束回合。可捕获单位向未占据据点推进，其他单位向最近敌军或 HQ 靠近。该对手比 v1 随机策略更有目标，但只有单一行为分布。

### 奖励与已知缺陷

v2.0 已加入据点、伤害、治疗、部署和接近据点的塑形奖励，终局胜负奖励和 `[-2,2]` 裁剪也已存在。但 v2.0 在对手回合完成后才计算分差，可能把对手的攻击或占点混入 agent 奖励；v2.1.0 才改为 agent 动作完成后立即结算。

### 性能记录

该次训练没有保存周期 eval/win-rate 标量，只有 rollout 日志：平均回报从 -7.60（256 步）升至 20.76（500,224 步），平均 episode 长度从 48.4 增至 116.57，explained variance 从 -0.044 最终升至约 0.991。由于缺少同协议评估，不能把 rollout 回报直接解释为胜率。

跨版本抽样（`default`、确定性策略、最多 100 回合）结果：固定 v2.0 坐 `player_a`、v2.1.1 坐 `player_b` 的 4 局中 v2.0 **4–0**，每局 15 回合；启用 `--swap-sides` 的 4 局中 v2.1.1 **3–1**。后一个结果包含 v2.0 坐 `player_b` 的分布外情况，且混入先手优势，不能视为严格 Elo 结论。

### 部署与兼容性

必须使用 `run_model_v200.py` 和 `env_v200.py`。旧模型尽量固定在 `player_a`；坐 `player_b` 时虽能正常行动，但固定视角会造成训练分布外失真。v2.0 的 38 动作不能加载到 v2.1 的 54 动作环境，也不能续训 v1 或 v2.1 模型。

## 模型 3：hex_ppo_v1.0.0_20260824_default_random_opponent_120000

### 身份与文件

- **文件**：`rl/models/hex_ppo_v1.0.0_20260824_default_random_opponent_120000.zip`
- **定位**：v1 训练流程的默认图历史模型；不是当前部署模型。
- **训练步数**：`num_timesteps=120,000`；约 6.63 MB；参数量 543,809。
- **环境特征**：观察 3,922 维，动作 `Discrete(512)`；动作索引表示旧环境合法动作列表中的第 N 项。
- **训练设备记录**：PyTorch 2.13.0 CPU；这是 zip 生成时的历史环境信息，不是当前运行要求。

### 网络与动作

主体仍为两个 `3922 → 64 → 64` 的 Tanh MLP，但 action head 为 `512 × 64 + 512`，总参数 543,809。512 个动作不是稳定意图槽；每个状态重新生成合法动作列表，再由 action mask 屏蔽不可用索引。该模型不能解释为“第 37 号永远攻击”之类的固定语义。

### 训练对手、奖励与策略边界

v1 使用随机合法动作对手。对手没有攻击、治疗、部署或占点推进优先级，模型容易学到利用随机空档的策略，而不是应对目标明确的反击。v1 的训练日志没有与当前 v2.1 相同协议的胜率、据点和回报评估，因此仓库不提供可比的正式性能数字。

### 兼容性

该模型的 `Discrete(512)` 与 v2.0 的 38、v2.1 的 54 完全不兼容。当前服务端将其路由到 `run_model_v100.py`，使用 `env_v100.py` 的历史快照。

## 共同限制与后续方向

- 当前训练只有一个环境实例，样本吞吐受 TypeScript worker 限制；并行环境或批量引擎是主要加速方向。
- v2.1 对手仍是手写规则而非 self-play，模型可能针对三种风格的行为分布过拟合。
- 观察向量未显式编码完整攻击力、防御、移动范围和据点类型，策略只能从格占用、HP 和全局量间接推断。
- `special` 槽目前主要对应重装爆破；增加特殊技能时必须明确新语义并升版本。
- 当前 eval 通常每次只有 20 局，胜率标准误差较大；发布新模型前应增加独立随机种子、换座位、换地图和真人/历史模型对手评估。
- v2.0 的旧奖励归因和固定视角限制无法通过后处理修复；需要可比结果时必须使用各自快照运行器并保留兼容性警告。
