# 强化学习版本说明

本文档只记录 `rl/` 目录下训练环境、模型接口和训练工具的变化，不记录游戏引擎本身的版本变化。
条目按时间倒序排列。每次修改强化学习代码时，必须在本文件顶部追加一条记录。

## 2026-08-29 · v2.3.2

- **自对弈快照阶梯对手**：随机地图训练默认 60% 局（`RL_SELF_PLAY_PROB`）的对手从自己历史策略快照中随机抽一个（最近 8 个），
  对手强度随训练提升，解决只会打弱规则对手、遇上强模型对手就崩的瓶颈（v2.3.1 对规则 8:2 但对 v2.2.0 0:8）。
- `train.py` 新增 `SnapshotCallback`：每 `RL_SNAPSHOT_FREQ` 次回调（默认 5000，并行下 1 次 = N 帧）原子写入一个快照，
  只保留最近 `RL_SNAPSHOT_KEEP`（默认 20）个；目录 `RL_SNAPSHOT_DIR`（默认 `rl/selfplay/<地图>`，已入 gitignore）。
- 训练初期无快照时自动用规则对手；快照加载/行动失败时当局降级为 mixed 规则，不会中断训练。
- 评估环境仍只用规则对手（衡量绝对强度的标尺不变）；不改变观测/动作/奖励语义，v2.3.x 断点可续训。

## 2026-08-29 · 评估工具（不升模型版本）

- `evaluate_cross.py` 按模型观测维度路由编码 helper：54 动作不再一律用当前 `env.py`，
  5974 维 → `env.py`（v2.3，支持随机地图），3922 维 → `env_v22.py`（v2.1/v2.2 快照），38 动作维持 `env_v200.py`。
  此前 v2.2.x 模型对上 v2.3.x 模型会因观测形状不匹配直接报错。
- 仅工具变更，不改变训练环境语义，模型版本不升；v2.2 helper 在随机地图上属分布外（编码只覆盖半径 8 的格、归一化常数为静态图数值），观察到的正是旧模型的退化量。

## 2026-08-29 · v2.3.1

- **并行训练**：`RL_NUM_ENVS`（默认 4）用 `SubprocVecEnv` 并行多个训练环境，每个环境一个独立的
tsx 引擎 worker 进程，样本吞吐（此前唯一瓶颈）成倍提升；GPU 负责 PPO 更新。单环境自动退回 `DummyVecEnv`，行为同构。
- 子进程适配：对手模型不再在主进程加载后传对象（对象不可跨进程序列化），改为传路径、由子进程内懒加载；
  `env.py`/`local_env.py` 新增 `opponent_model_path` 参数，`opponent_model` 对象入参仍兼容。
- 动作掩码经 `env_method("action_masks")` 从各子环境收集（sb3 原生支持），向量化训练环境不再包 `ActionMasker`；
  评估环境仍为单环境，行为不变。
- 不改变观测/动作/奖励语义；v2.3.0 的 checkpoint 可直接续训。

## 2026-08-29 · v2.3.0

- **训练环境接入对称随机地图**（依赖游戏侧 3.4.1 的随机地图生成器）：`RL_MAP_ID=random` 即可训练，
  每局由引擎现生成一张标准模式对称随机图（地形/复活点/据点/回合数/行动点/兵种数值/经济与总部全部随机，
  可玩性由服务端连通性校验保证）。种子从 `np_random` 派生，gym seed 可复现整条训练序列；
  `RL_RANDOM_OPTIONS`（JSON）可覆盖默认随机域，如固定半径/回合数。
- **观测空间 3922 → 5974 维，旧模型全部不兼容**：`MAX_CELLS` 217 → 331（半径 10 标准六边形），
  格子改为按绝对 (q, r) 映射到半径 10 标准定序表，半径 6-9 地图余槽补零，位置语义跨半径一致。
  动作空间仍 `Discrete(54)` 不变，但按仓库兼容策略（同动作数不同编码语义也需独立快照/运行器）：
  新增不可变快照 `env_v22.py` 与运行器 `run_model_v22.py` 承载全部现存 54 动作模型（v2.1.x/v2.2.x），
  `src/api/bots.ts` 对 54 动作按文件名版本分流（≥ v2.3 → `run_model.py`，否则 → `run_model_v22.py`）。
- **归一化随局配置动态化**：回合数/行动点/补给/总部血量的观测归一除数改读本局 `config.balance` 与
  `headquartersSpec`（随机参数下固定除数会失真）；新增半径与地形障碍占比两个全局特征；
  单位格补齐归一化攻击力、总部格补防御（槽 17），随机兵种数值因此可被感知。
- **模型对手降级编码**：modelmix 对手（v2.0.0，3922 维）的观测改由 `env_v22` 快照编码器产出
  相对视角编码，与其训练时逐格一致；v2.3 的 5974 维观测不会喂给旧模型。
  随机地图上 v2.0.0 对手属分布外，`RL_MAP_ID=random` 时 `RL_MODEL_OPPONENT_PROB` 默认 0（只用规则对手）。
- **本地引擎 worker**：`rl/local-worker.ts` 的 `reset` 支持 `mapId: "random"` + `random` 参数（与 REST 同一套生成/校验）；
  `handleCommand` 导出供测试直接调用，仅主进程运行时监听 stdin。`src/state/store.ts` 新增
  `createInitialGameWithConfig` 支持任意配置开局。`evaluate_cross.py` 支持 `--map random`（每局种子 `cross-<局序>`）。
- 训练命令：`$env:RL_MAP_ID = "random"; python rl/train.py`；模型命名
  `hex_ppo_v2.3.0_<日期>_random_modelmix_<步数>.zip`，checkpoint 落 `rl/checkpoints/random/`。
  从零训练，不能加载任何旧模型。

## 2026-08-28 · v2.2.1

- 交付模型改为评估选出的 best 断点：训练结束后把 `checkpoints/<run>/best/best_model.zip`
  复制到 `rl/models/` 的最终路径，不再交付训练终点模型。实测终点模型常在后期震荡中退化（v2.2.0 终点对 v2.0.0 0:8，同期 best 16:0）。
- 未启用评估（`RL_EVAL_FREQ=0`）或评估未及运行时退回交付终点模型。
- 不改变训练环境、观测/动作/奖励语义；仅影响训练结束时的交付文件选择。

## 2026-08-27 · v2.1.9

- 修复回合交替损坏：v2.1.7 改动删掉了智能体动作后、对手阶段前的状态刷新，对手回合循环读到陈旧
  状态（仍显示智能体回合）而在智能体 end_turn 后被跳过；引擎只在 end_turn 时校验回合归属，
  导致智能体下一步单位动作照常在对手回合执行——每回合白嫖 1 个先手动作并偷走对手 1 点 AP。
  v2.1.7/v2.1.8 的训练与自评（100% 胜率）全部建立在这个作弊节奏上，换到正确交替的互打环境即 0:8 溃败。
- 恢复动作后的状态刷新；另附一个次生观察：智能体连续 end_turn 时曾出现死循环（每步 -0.05 直到截断）。
- 本修复与 v2.2.0 的座位随机化随同一次训练发布，模型文件名版本号为 v2.2.0；
  v2.1.7/v2.1.8 模型均已在损坏节奏下训练，不建议继续使用。

## 2026-08-27 · v2.2.0

- 训练环境每局随机智能体座位（player_a / player_b 各 50%）。
  实测发现观测按绝对坐标布局编码，旧模型对手换座后严重退化（真身 vs 训练形态 8:0），
  v2.1.5～v2.1.8 训练自评 100% 胜率实际打赢的是残疾对手；互打验收要求 v2.1.x 坐
  player_b 迎战真身，因此必须让智能体学会双座位作战。
- 智能体坐 player_b 时，模型对手坐在它的主场 player_a，相对视角编码与其原生编码完全一致，
  对手即满血真身；坐 player_a 时对手仍为退化形态（无法避免，旧模型只能在主场满血）。
- 镜像对局验证无座位优势（3:3），不影响裁决公平性。不改变观测/动作空间形状，
  v2.1.x 模型可直接加载，但双座位能力需重新训练。
- `local_env.py` 的 `_apply` 改为按当前 owner/opponent 映射，不再硬编码 player_a。

## 2026-08-27 · v2.1.8

- 修复对手回合崩溃：对手（尤其旧模型）发出过期动作被拒后，兜底的结束回合可能遇上游戏已结束（如智能体上一步刚摧毁总部），
  `game_over` 异常不再向上传播打断训练，改为刷新状态后由循环守卫退出。v2.1.7 训练在约 13 万步处因此崩溃。
- 不改观测/动作/奖励语义；v2.1.7 的 checkpoint 可直接续训。
- v2.1.7 初步效果验证：奖励修复后 13 万步评估胜率达到 100%、平均占点 4.25（v2.1.6 同期为 0%/0.4）。

## 2026-08-27 · v2.1.7

- 奖励结算回退到 v2.0.0 语义：在对手响应之后再结算分数差。
  v2.1.0 改为“自己动作后立即结算”后，占点/收入等回合边界结算的收益全部被下一次基线更新吸收，
  占点（裁决分权重最大项，90/点）从奖励信号中消失，导致 v2.1.x 策略不抢点（诊断局：占点 1:4，
  且只部署侦察兵）。v2.1.6 修好移动与部署后依然 0:8 输给 v2.0.0，本条修复针对该根因。
- 不改变观测/动作空间；模型结构兼容但策略是在无占点信号下学出来的，建议从零重训。
- 顺带说明：v2.1.3 实际是用单一 defensive 规则对手训练（文件名 `rule_defensive`），
  与 modelmix 训练的版本评估条件不同，横向对比时需注意。

## 2026-08-27 · v2.1.6

- 修复移动动作只走一格的严重效率问题：v2.1.0 的 BFS 移动重构会把目标回溯到起点旁第一格，
  而引擎允许一次移动动作直达任意可达格，导致 v2.1.x 单位机动效率只有 v2.0.0 的 1/3~1/5，
  这是 v2.1 系列在裁决分对局中全线输给 v2.0.0 的主要原因。
- 现在直接移动到离战略目标最近的可达格；`_reachable` 本身已 BFS 绕开障碍/水域，绕路语义保留。
- 旧动作语义（`legacy` 分支）与观测编码不变；v2.1.x 旧模型可直接用新移动语义重新评估，
  但建议从零重训以获得与新移动节奏匹配的奖励学习。

## 2026-08-27 · v2.1.5

- 修复模型对手动作语义错位：v2.1.4 把 v2.0.0 的 38 动作直接按下标映射到当前 54 动作表，
  但当前版本使用 12 个局内稳定槽位和绕路移动，与 v2.0.0 的“每步排序取前 8 槽、严格接近目标”
  语义不同，导致旧模型对手实际行为接近噪声。
- `_legal_actions` / `_fixed_move` 新增 legacy 参数复现 v2.0.0 的 38 动作生成逻辑（已用 378 个
  真实对局状态与 `env_v200` 原版逐格比对验证），模型对手直接按旧动作表行动，不再经过槽位映射。
- v2.1.4 模型因训练对手失真而退化（离线互打 0:4 输给 v2.0.0 与 v2.1.3），不建议继续使用；
  请用本版本从零重训（`RL_LOAD_MODEL` 留空）。
- 三个 REST 运行器（`run_model.py` / `run_model_v100.py` / `run_model_v200.py`）新增限流等待重试，
  动作被拒（如动作过期、AP 耗尽）时回退为结束回合，避免异常中断整局。
- 修复 `env_v100.py` 快照中部署动作未检查剩余 AP 的合法性错误；不影响训练环境与模型兼容性。

## 2026-08-26 · v2.1.4

- 新增模型对手混合训练：默认自动加载 v2.0.0 模型，50% 对局使用模型对手，另外 50% 在 aggressive/mixed 规则对手间切换。
- 兼容旧模型的 `Discrete(38)` 动作，通过固定槽位映射到当前 `Discrete(54)` 环境；对手观察使用 player_b 相对视角。
- `RL_OPPONENT_MODEL` 可指定旧模型路径，`RL_MODEL_OPPONENT_PROB` 可调整模型对手比例；找不到旧模型时自动退回规则对手。
- 评估最佳模型改为按胜率优先、平均占点数次之、平均奖励最后选择。
- 新训练版本为 v2.1.4；不能续训 v2.0 模型作为智能体，但会将其作为对手进行新训练。

## 2026-08-26 · v2.1.3

- 更新训练脚本、运行器自动选模、跨版本评估示例及相关文档，兼容旧命名模型。

## 2026-08-26 · v2.1.2

- 新增 `env_v200.py` / `run_model_v200.py`：v2.0.0（38 动作）时期的环境快照与 REST 运行器；`run_model.py` 继续服务 v2.1 模型。

## 2026-08-25 · v2.1.1

- 修复 12 个稳定单位槽位中存在空槽时，治疗动作生成逻辑访问 `None` 导致训练崩溃的问题。
- 不改变观察空间、动作空间或模型兼容性；已生成的 v2.1.0 模型可以继续使用。

## 2026-08-25 · v2.1.0

- 奖励改为在智能体动作完成后立即结算，再执行对手回合，避免把对手的攻击或占点错误归因给智能体。
- 移动规划改为基于 BFS 的可达路径，遇到障碍时允许绕路；单位动作槽位从 8 个扩展到 12 个，并在一局内保持单位槽位稳定。
- 修正编码器的相对视角：无论训练哪一方，自己的单位、总部和据点都使用同一组特征。
- 规则对手支持 aggressive/defensive/economy 三种风格，默认 mixed 每局随机选择，减少过拟合单一脚本。
- 评估输出胜率、平均占点数以及部署/攻击/移动次数，便于判断模型是否真的在执行战术目标。
- 动作空间由 `Discrete(38)` 变为 `Discrete(54)`，v2.0 及更旧模型不能续训；请清除 `RL_LOAD_MODEL` 后从零训练 v2.1 模型。

## 2026-08-24 · v2.0.4

  本文件顶部条目一致，训练时可用 `RL_MODEL_VERSION` 覆盖。同一天相同步数重跑会同名报错，
  需换 `RL_MODEL_PATH` 或设置 `RL_ALLOW_OVERWRITE=1`。

  命名，旧模型仍可被自动找到并续训。
- 修复：版本号含点号（如 v2.0.4）时 sb3 的 `save()` 会把 `.4` 误判为扩展名而不补
  `.zip`，最终保存前统一调用 `ensure_zip_suffix` 保证文件带 `.zip` 后缀。
- 不改变观察空间、动作空间、奖励定义和模型兼容性；已生成的旧文件无需迁移，仅影响
  新模型的默认保存路径。

## 2026-08-24 · v2.0.0

- 将对手从随机合法动作策略改为简单规则策略：优先攻击、治疗、部署，并让可占点单位向未占领据点推进。
- 将动态“第 N 个合法动作”改为固定意图动作槽位：结束回合、8 个单位槽位（移动/攻击/治疗/特殊动作）和 5 个兵种部署槽位。

- 新增奖励塑形：占点、造成伤害、恢复己方生命、部署单位、靠近未占领据点分别提供辅助奖励；无进展结束回合略微扣分。
- 默认训练步数提升到 500000，探索系数默认 `0.01`，裁剪范围默认 `0.2`，评估默认每次 20 局。
- `run_model.py` 增加动作空间版本检查，错误模型会在执行前明确提示。
- 训练默认模型名改为 `hex_ppo_v2_<map>_rule_opponent`。

## 2026-08-24 · v1.2.0

- `train.py` 合并断点续训、checkpoint、TensorBoard 和带动作掩码的周期评估功能。
- 支持 `RL_LOAD_MODEL=auto`、`RL_SAVE_FREQ`、`RL_CHECKPOINT_DIR`、`RL_EVAL_FREQ` 与主要 PPO 超参数环境变量。
- 自动创建模型、日志和评估目录；训练产生的模型、日志和临时测试目录加入 Git 忽略。

## 2026-08-24 · v1.1.0

- 本地训练 worker 支持 `RL_MAP_ID`，可训练普通双人顺序模式地图，例如 `default`、`dual-lanes`、`desert` 和 `forge`。
- 增加 `run_model.py`，可以把训练好的模型接入已有 REST 对局。
- 增加模型路径和地图路径配置，训练不再依赖 HTTP 服务器。

## 2026-08-24 · v1.0.0

- 新增 Gymnasium + `MaskablePPO` 训练环境。
- 本地 TypeScript 引擎通过 JSON Lines worker 供 Python 训练调用。
- 支持默认地图上的移动、攻击、治疗、部署、拆除和结束回合动作。
- 初始模型采用固定长度观察向量和动作屏蔽。

## 后续记录格式

每次改动按下面格式追加到文件顶部：

```markdown
## YYYY-MM-DD · vX.Y.Z

- 改了什么，以及影响了训练或部署的哪个部分。
- 是否改变观察空间、动作空间、奖励定义或模型兼容性。
- 迁移方式：从零训练、可以续训，或需要指定新的模型路径。
```
