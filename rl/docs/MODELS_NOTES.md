# RL 模型说明（导航页）

本文件是 RL 模型的**导航页 / 索引**。每个模型的完整档案已按「一个模型一个文件」拆分到 `rl/docs/models/<版本号>.md`；本页只保留跨模型共享的内容：**模型状态总表**（每行的版本列即指向对应档案）、检查点与测试快照索引、版本演进与路由规则、新增模型模板、共同限制与后续方向。单个模型的网络/观测/动作/训练/性能/兼容性细节，请点开对应档案。

**当前生产 champion：v3.0.3（5M 断点）** → [`models/v3.0.3.md`](models/v3.0.3.md)。

资料来源：`rl/docs/RELEASE_NOTES.md`、`rl/README.md`、`rl/envs/env.py` 与 `env_v100`–`env_v27` 历史快照、`rl/training/local_env.py`、`rl/training/train.py`、`rl/training/extractors.py`、`rl/training/distill.py`、`rl/evaluation/evaluate_cross.py`、模型 zip 内的 `data`/`system_info.txt`，以及 `rl/tb/` TensorBoard 日志与 git 提交历史。性能数字只对注明的评估协议负责，不代表所有地图、座位或真人对手上的泛化能力。

## 模型状态总表

v2.7.0 是 v3.0.2 之前的生产 champion：96 局全新随机图配对换座取得 66:30，95% Wilson 下界 58.9%，两个座位的下界都超过 50%。
v2.8.0 只改训练管线（语义与 v2.7 相同），验收 43:53 未反超，不替换 champion。
v3.0.0（155 分层动作 / 6715 维观测 / Transformer 编码器 / 蒸馏冷启动）验收 51:45 与 v2.7.0 打平，
但把 v2.8 的后手座短板从 29.2% 抬到 47.9%；其交付断点只有 5 万步，因价值头尺度缺陷导致 PPO 前期退化。
v3.0.1 已修复该缺陷（价值目标不再缩放，PPO 初始学习率降到 5e-5）：训练在 749,568 步（25%）被 GPU 驱动错误中断，
但 75 万步内 `explained_variance` 在 0.50-0.89 区间无趋势性下跌（早期爬升）、对锚点胜率 40%-60% 无趋势性下跌，**崩溃已治好**；
best 为 35 万步断点，验收 96 局对 v2.7.0 **49:47**（51.0%，Wilson 下界 41.2%，先手座 62.5% / 后手座 39.6%），仍为打平。
v3.0.0 与 v3.0.1 两代独立证据表明「蒸馏冷启动 + 少量 PPO」是当前配方上限，不续训、不替换 champion；v2.7.0 继续生产。
v3.0.2（合法集内标签平滑 + `RL_ENT_COEF` 死变量修复 + 探索监控）打破探索死锁后，1.4M 断点在两批全新随机图各 96 局配对换座验收中对 v2.7.0 累计 **123:69**（64.1%，Wilson 下界 **57.1%**；先手座 76.0%/下界 66.6%，后手座 52.1%/下界 42.2%），总分下界达到 v2.7.0 当年晋级线同级证据，**已替换为生产 champion**；v2.7.0 降级为上一代 champion 与自对弈锚点。注意：训练期 best 选择键被 default 场景 OOD 崩塌主导，选中的 10 万步断点（96 局 53:43）弱于 1.4M 断点——交付模型以验收互打实测为准，不以训练期 best 为准。
v3.0.3（全 7 图训练混合 + 锚点 v3.0.0 20% + best 选择键拆分，纯配方改动）从 v3.0.2 的 1.4M 断点续训 356 万帧：2026-09-07 的 round_robin（15288 局）暴露 v3.0.2 全图总榜仅第 6、danger-close 全场垫底（28%、先手 8%，对四代模型 0:24），明细挖掘定位败因为部署饥饿与三张静态图（breach/danger-close/desert）完全不在训练分布。v3.0.3-5M 交付断点对 v3.0.2 **480 局 352:127**（73.3%，Wilson 下界 **69.2%**，历代最强晋级证据；先手 63.3%/后手 83.3%），danger-close **96:0**；对 v2.7.0 277:202（57.7%，下界 53.2%）。门禁图 danger-close 双座 100%、default 双座（对 v3.0.2）54%/98% 全部过线，**已替换为生产 champion**；记录在案的退化：breach 35%、desert 46% 弱于 v3.0.2，random 优势让掉（52%），default 先手座对 v2.7.0 仍 42%。
v3.0.4（弱图加权续训：breach/desert 双 48:0 修复、random 57:39，但 dual-lanes 0:48 一票否决；[v3.0.4](models/v3.0.4.md)）、v3.1.0（3 层×128 容量对照：forge 0:48 证伪容量假设；[v3.1.0](models/v3.1.0.md)）、v3.1.1（随机域拓宽第一代：dual-lanes 自愈 + default 破座位锁，总分 312:168 历代最高，但 forge 连续第二代 0:48；[v3.1.1](models/v3.1.1.md)）三代挑战者均未过线，champion 保持 v3.0.3。
v3.2.0（算法对手接入对手池 + 奖励补 HQ 项 + 评估场景与 best 选择键分离）从 A4 断点续训 100 万帧交付 9.8M 断点：两套 192 局头对头对 v3.1.1 **50.0% / 48.4%（均值 49.2%）**，而零假设（v3.1.1 打自己）结构性恒为 **50.0%** ⇒ **打平、未超越**；轨迹测试证明那 50.0% 是换一套种子题即不复现的孤立尖峰（剔除它的邻域均值只有 43.9%）。七轮配方实验（奖励量纲 / 靶子构成 / 解锁 LR / 拉长规模 / 还原 3.x 原配方）**全部落在 40–50%，无一条产生可复现的正向位移**，唯一稳定规律是 `schedule` 优于 `constant` ⇒ 配方路线关闭，champion 不变（选型建议继续用 v3.1.1，本模型为统计等价备选）。
v4.0.0（从零训练 + 2 层×d128 大容量 + 算法教师蒸馏冷启动）交付 11.4M 断点：对 v3.1.1 两套 192 局合计 **46.6%（lb 41.7%）**、对 v3.0.3 **53.6%（lb 48.6%）**，能力序 **v3.1.1 > v4.0.0 > v3.0.3**；全图 480 局中 **default/breach/desert 三张静态图 0%**（一票否决）、danger-close 100%。**未通过验收，不作 champion**。本代最大的产出是**证伪了「对算法弱」这个前提**：arena 的 16.5% 是 7 图聚合假象——同一模型在随机图上对同批算法是 41%/45%/64%（`eval_worker` 同尺子复测 v3.1.1），静态图（desert 17%、breach 33%）把总数拉低了；静态图崩塌与算法对抗是同一个病（训练分布覆盖不足）。另：S3 消融（算法 40% + lr 8e-05）**第四次复现「收敛后继续训练 = 退化」**，同步骤对照 11.6M 起两条轨迹分叉并单调拉开（14.2M：rule 64% vs 72%、field 39% vs 59%）。

### 已过期模型（登记源 `arena/model-status.json`，退出评估但保留榜单）

「过期」是介于「在役」与「作废」之间的**第三态**，三者的口径不同，勿混用：

| 状态 | 模型 zip 位置 | 历史对局 | 新一轮评估 | 前端榜单 |
|---|---|---|---|---|
| 在役 | `rl/models/` | 计分 | 参与 | 展示 |
| **已过期** | `rl/models/`（**不移动，不归档**） | **仍进 Bradley-Terry 池计分**（分数随池子漂移，不是冻结） | 不参与（`--models` 显式点名可临时拉回，供审计/复现） | **默认隐藏**，可展开 |
| 已作废 | `rl/models/deprecated/` | 全部丢弃 | 不参与 | 完全不展示 |

过期**不等于冻结分数**：过期模型与它在役对手之间的历史对局（每对约 168 局）仍留在评分池里把相对强弱钉死，新模型加入只会让两边同时下移，所以过期 3 个模型不会让其余参与者的评分发生跳变（连续加入 3 代新模型的模拟：两者差距稳定在 22~32 分，不倒挂）。

单一事实来源是 `arena/model-status.json`（按版本登记 `expiredAt` / `reason` / `evidence`），由 `script/modelStatus.mjs` 读取，JS 脚本（榜单/统计）、服务端 TS（`src/api/bots.ts`）与 Python 编排器（`rl/evaluation/round_robin.py`）共用。错误处理分两种立场：JS 脚本与 `round_robin.py` 对结构非法**一律抛错中止**（带着坏名单跑评估会把过期模型悄悄拉回对手池）；`bots.ts` 是唯一允许降级的消费端（坏登记表不阻断线上对局，退化为「无过期」并打告警）。登记表**缺失**在所有消费端都按「无过期」处理。Python 侧镜像校验由 `tests/rl/test_model_status_contract.py` 钉死与 JS 一致。判定与登记用 `npm run arena-expire -- --analyze` / `--expire <版本列表> --reason "…"`（`--restore` 回滚、`--list` 查看）。

过期与作废**互斥**：同一版本不得同时出现在两份名单（`--expire` 拒绝登记已作废版本，`generateArenaLeaderboard` 启动时再做一致性断言兜底）——否则状态展示为「已过期」但对局被按作废整局丢弃，语义互相抵消。

判定规则：**必须每张地图都排在该图池子后半段，且没有任何一张图挤进该图前 25%**。某一两张图特别优秀、其余图垫底的**偏科模型不算过期**——那类模型对新模型仍有对手价值（`--analyze` 会列出淘汰原因）。已过期模型不再进入候选，避免重复登记。

## 共同限制与后续方向

- 自 v2.3.1 起支持 `RL_NUM_ENVS` 并行环境（每环境一个引擎 worker，样本吞吐约 N 倍）；批量引擎（单进程多局）仍是进一步加速方向。
- **静态地图是验证集，不进训练分布**（明确决策）：自对弈提升绝对棋力而非混入静态图。**但 default 验证集本身的先手效应使 8 局样本失效**：历代随机图模型（v2.3.3 起）坐 player_a 对 v2.2.0 全部 0:8，后手才能赢；历史记录的 7:1/6:2 为小样本噪声。default 上的真实差距需用分座位大样本重估；先手崩溃的成因（随机图训练分布缺少固定布局先手经验）是后续方向。
- **评估样本量教训（v2.5.0 验收）**：同一配置重复 8 局互打结果可在 6:2↔4:4（随机图）、6:1↔1:7（default 后手）间摆动；单次 8 局无统计意义。“历代 5:3”“6:2 拉开”“8:0 碾压”“1:6 退化”均已被复测推翻或归入噪声。验收必须用累计大样本（≥24 局）或分座位统计，否则结论随机翻转。
- **evaluate_cross 座位 bug 教训（已修复）**：`--swap-sides` 第 2 局换边后重建控制器时固定取初始名字，第 3 局起座位不再往返，**历史上所有换边多局成绩全部作废**（包括历代记录的 7:1/6:2/5:3）。修复后真换边复测：v2.4.0 对 v2.5.0 随机图 15:9；v2.5.0 对 v2.2.0 default 先手 0:12/后手 9 胜 2 负 1 平。任何旧换边数据需要重测才能引用。
- **训练期评估 best 不等于真实水平 / 不等于最强断点**：v2.5.0 评估 best（6 万步，峰值 80%）互打全 4:4；v3.0.2 训练期 best（10 万步）96 局仅 53:43，而 1.4M 断点累计 123:69。当评估场景含训练分布外（default 对随机图世代是静态图）时，`min_wilson_lb` 选择键会被 OOD 崩塌主导、系统性偏向早期断点；候选断点交付前必须互打验收。改进方向：把选择键拆分为「random 场景下界」选 best、default 下界仅记录不参与选择。
- **对手生态加压的天花板已确认（v2.6.0 实验）**：自对弈 85% + 快照近期加权 + 强锚点仍未能超越 v2.4.0（10:14），且高自对弈比例引发静态图灾难性遗忘（default 0:24，连后手局也丢）。观测扩展（v2.5）与生态加压（v2.6）两条路均已验证无效；随机图 + 自对弈阶梯配方在 54 动作空间上的收益接近耗尽——这正是 v3.0 改分层动作空间 + 结构化编码器的动机。
- **高自对弈比例的副作用**：自对弈 ≥85% 时训练期评估（规则对手）峰值虚高更严重（85% 峰值但互打落后），且静态图能力快速遗忘；自对弈比例与静态图保持需权衡（60% 是历代验证过的平衡点）。
- **蒸馏 + PPO 的探索死锁（v3.0.x）**：纯克隆蒸馏把新动作 logit 反复下压，PPO 只对采样到的动作有梯度 → 概率≈0 的新候选永远采不到；`RL_ENT_COEF` 曾因续训死变量对 v3.0.0/v3.0.1 全程失效（零熵正则），策略熵单调坍缩。v3.0.2 用合法集内标签平滑 + `resume_custom_objects` 修复 + 探索监控打破死锁（新候选选用率 0%→0.6%-1.5%、策略熵稳定 1.5-1.8 nats）。
- 观察向量已编码攻击力/防御（v2.3 槽 17）与完整规则参数（v2.7 的 51 维），但据点类型等仍有间接推断成分；`special` 槽目前主要对应重装爆破，增加特殊技能时必须明确新语义并升版本。
- 训练后期存在胜率震荡（v2.2.0 峰值 90% → 终点 45%），已通过交付 best 断点 + 学习率衰减兜底。
- v2.0.0 只能在 player_a 满血，验收时固定该座位；评估应使用镜像局排除座位/先手因素（`default` 地图实测无先手优势）。v2.0 的旧视角限制无法通过后处理修复；可比结果必须使用各自快照运行器并保留兼容性警告。
- **「对算法弱」是聚合假象（v4.0.0 结项，2026-09-24）**：arena 把 7 张图平均后 v3.1.1 对算法只有 40%（threat 28%、field 22%），据此长期判断「算法对手是最大痛点」。但同尺子（`eval_worker`，随机图）复测 v3.1.1 对同批算法是 **41%/45%/64%**——差距全在静态图（arena 分图：desert 17%、breach 33%、forge 41%，而 random 54%）。**给模型设强度目标前，必须先确认读数用的是哪张图 / 哪套聚合**；跨图聚合会掩盖「某类地图全面崩塌」这一真相。
- **静态图崩塌与算法对抗是同一个病（v4.0.0 结项）**：v4.0.0 花 20M 帧专攻算法对抗（占比 20%→40%），结果对算法绝对水平与 v3.1.1 持平，而 default/breach/desert 三张静态图 **0%**。根因是训练分布里静态图权重只有 0.05 ——**模型在静态图上从未获得过梯度**，与对手是谁无关。注意区分：v3.0.4 的「削权重→整图遗忘」是**削**的教训，「加权重」尚未被证伪，是下一轮首选方向。
- **步兵海是跨代复发的病（v3.2.0 首现、v4.0.0 复发）**：`RL_REWARD_NEW_UNIT_TYPE`（A5）只奖励**每兵种首次部署**，收完即失效；14M 帧长跑后 default 图步兵占比回到 **81%**（对手 v3.1.1 为 53%）、游侠仅 14%，造成伤害 774 vs 1111。**压制兵种单一化需要持续性多样性奖励，一次性 novelty 只对短训有效。**
- **「收敛后继续训练 = 退化」已四次复现（v3.2.0 champ5 / r3x、v4.0.0 S3）**：v4.0.0 S3 抬 LR 到 8e-05 + 算法占比 40% + 自对弈降到 60%，同步骤对照在起点处两条轨迹重合、之后分叉并单调拉开（14.2M：rule 64% vs 72%、field 39% vs 59%），`explained_variance` 0.64→0.46。**已收敛策略的安全续训 LR 是 5e-05**（v3.2.0 champ 与 v4.0.0 S2 均用此值）；任何「续训 + 改配方」轮次都应预期退化而非提升。
- **容量不是静态图问题的解（v3.1.0 首证、v4.0.0 从零复证）**：0.87M → 1.44M 参数（2 层×d128）+ 从零训练，静态图仍三张 0%。与 v3.1.0 的 3 层×128 短训实验结论一致。
- **`evaluate_cross` 的 stats jsonl 座位口径**：`scores`/`winner` 是**引擎原始座位键**（`player_a`/`player_b`），`--swap-sides` 下必须用 `players` 字段（模型名）反查座位，否则换座对局会被算反（症状：均分差为正却 0 胜）。
