## 网络、观察和动作

### 网络

- 算法：`sb3-contrib` **MaskablePPO**（`MaskableActorCriticPolicy` + `MaskableRolloutBuffer`）。
- 结构：默认 `MlpPolicy`，`policy_kwargs={}`，即 actor/critic 各为 `3922 → 64 → 64` 的两层 Tanh MLP，动作头 `512 × 64 + 512`。参数量 543,809。

### 观察（`Box(-1.0, 1.0, (3922,), float32)`）

3922 = **217 格 × 18 格特征 + 16 全局特征**，全部裁剪到 `[-1, 1]`。

- **每格 18 维**（按 `(q, r)` 定序取前 217 格）：
  - 地形 one-hot 3 维（plain / water / blocker）；
  - 据点归属 3 维（无 / 己方 player_a / 敌方）；
  - 单位或总部归属 3 维（无 / 己方 / 敌方）；
  - 兵种 one-hot 5 维（infantry / scout / heavy / ranger / support）；
  - HP 比例 1 维（`hp / maxHp`）；
  - `hasMoved`、`hasActed` 各 1 维。
- **全局 16 维**（实际写入前 10 维，其余补零）：己方/敌方补给 `/300`、己方/敌方总部 HP `/200`、回合数 `/20`、本回合已用 AP `/5`、己方/敌方据点占比、己方/敌方存活单位数 `/20`。
- **视角**：格级编码用常量 `PLAYER = "player_a"` 判定「己方/敌方」，是**固定 player_a 视角**（尚无 v2.1.0 之后的相对视角编码）。这决定了模型只在 player_a 座位是分布内的。

### 动作（`Discrete(512)`）

- 动作索引 = **当前状态动态生成的合法动作列表中的第 N 项**，不是固定语义槽位。
- 合法动作列表每次由 `_legal_actions()` 重新生成，顺序为：`end_turn` → 每个己方单位的 `move`（BFS 可达且落点为 plain 空格）/ `attack`（射程内敌方单位或总部）/ `heal`（support 对受伤友军）/ `demolish`（heavy 对相邻 blocker）→ 有剩余 AP 时的 `deploy`（从总部/己方据点相邻空格部署各兵种）；列表被截断到前 512 项（`MAX_ACTIONS`）。
- mask：`action_masks()` 只把前 `len(actions)` 个索引置真，屏蔽列表之外的动作。
- **关键局限**：因为列表每个状态重排、且截断在 512，同一动作索引在不同状态下语义不同，无法解释为固定意图——这正是 v2.0.0 引入「固定意图槽 + `Discrete(38)`」的直接动因。

## 训练对手与奖励

- **对手**：`player_b` 全程由随机合法动作策略驱动（`_play_opponent_until_agent_turn()` 在合法动作里均匀随机取一个，动作被拒时兜底 `end_turn`）。这是最弱的对手生态，模型学到的是「在无人有效反抗下稳定占点/推进」的行为，不具备对抗性棋力。
- **奖励**（`step()`）：
  - 稠密项：裁决总分（`adjudication.scores[owner].total`，反映据点控制等）的增量 `/100`，裁剪到 `[-1, 1]`；
  - 终局项：胜 `+1`、负 `-1`；
  - 非法/过期动作：`-0.05`（不中断整段 rollout）；
  - 单步总奖励裁剪到 `[-2, 2]`。
- 回合上限 `max_steps=500`，但对局通常在约 88–90 步内因裁决/回合数结束（见性能记录），远未触顶。

## 性能记录

**没有统一的胜率评估**——v1 时期还没有 `evaluate_cross.py` 那样的互打协议，随机对手也无法作为棋力标尺。可用的只有 zip 内 `ep_info_buffer`（训练收尾最近 100 局 rollout，对手为随机策略）：

| 指标 | 值 |
|---|---|
| 平均回报 | **8.12** |
| 回报区间 | 1.65 – 12.90 |
| 平均局长 | 89.6 步 |
| 局长区间 | 86 – 95 步（高度收敛，几乎无长尾） |

解读：

- 这里的「回报」是基于裁决分增量的累计 return，**不是胜率**，也不能跨对手/跨版本直接比较。
- 局长稳定收敛在 86–95 步，说明续训到 12 万步后策略在随机对手分布内已相当稳定（作为对照，同版从零训练的 100096 步早期实验版局长在 66–130 步大幅波动、平均回报仅 6.22，已删除）。

## 部署与兼容性

- **动作空间不兼容**：`Discrete(512)` 与 v2.0.0 的 `Discrete(38)`、v2.2.0+ 的 `Discrete(54)`、v3.x 的 `Discrete(155)` 完全互不兼容，断点无法加载进任何后续环境。
- **路由**：服务端 `src/api/bots.ts` 按动作空间 **512 → `run_model_v100.py`（label `v1`）** 分流；必须搭配不可变快照 `rl/envs/env_v100.py`，以保证动态动作排序与观测编码与训练时逐格一致。
- **座位限制**：观测格级编码硬编码 player_a 视角，**只有坐在 player_a 是分布内的**；`run_model_v100.py` 虽可通过 `--side` 指定座位，但坐 player_b 时格级己方/敌方标记会颠倒，属分布外，不应据此评估。
- **地图限制**：仅在 `default` 静态图上训练与可用；不支持随机图、`standoff`/`artillery-zone` 等后续场景。
- **续训**：理论上可用 `env_v100.py` 续训，但 v1 配方（随机对手 + 动态 512 动作）已被 v2.0.0 全面取代，续训无实际价值；保留意义在于旧环境回归验证与版本演进的起点样本。

## 一句话总结

v1.0.0 是仓库 RL 的「Hello World」：在 `default` 图上用 MaskablePPO 对随机对手跑通训练与部署链路，验证了观测编码、动态合法动作 mask 和基于裁决分的奖励塑形；其 `Discrete(512)` 动态动作与固定 player_a 视角是两大历史局限，直接催生了 v2.0.0 的固定意图槽与规则对手改造。
