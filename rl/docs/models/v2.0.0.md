## 网络、观察和动作

### 网络

- 算法：`sb3-contrib` MaskablePPO；默认 `MlpPolicy`，`policy_kwargs={}`，actor/critic 各 `3922 → 64 → 64` 两层 Tanh MLP，动作头 38。参数量 512,999（比 v1.0.0 的 543,809 小，因动作头 512→38）。

### 观察（`Box(-1.0, 1.0, (3922,), float32)`）

与 v1.0.0 **逐格一致**：3922 = 217 格 × 18 特征 + 16 全局特征，固定 `player_a` 视角。

- 每格 18 维：地形 one-hot 3、据点归属 3、单位/总部归属 3、兵种 one-hot 5、HP 比例 1、`hasMoved`/`hasActed` 各 1。
- 全局 16 维（实际写前 10）：己方/敌方补给 `/300`、己方/敌方总部 HP `/200`、回合数 `/20`、已用 AP `/5`、己方/敌方据点占比、己方/敌方存活单位数 `/20`。
- **视角限制**：格级编码用常量 `PLAYER="player_a"`，坐 `player_b` 时己方/敌方标记颠倒，属严重分布外——这是 v2.0.0「只能坐 player_a 满血」的根因，直到 v2.1.0 才引入相对视角编码。

### 动作（`Discrete(38)`）

`MAX_ACTIONS = 1 + 8×4 + 5 = 38`，槽位固定语义：

| 槽位 | 含义 |
|---|---|
| 0 | `end_turn` |
| 1–32 | **8 个单位槽 × 4 意图**：`move` / `attack` / `heal` / `special`（heavy 的 `demolish`） |
| 33–37 | **5 个兵种部署槽**：infantry / scout / heavy / ranger / support 各一 |

- **单位分槽**：每步把己方存活单位按 `(兵种序号, q, r, −hp)` 排序取前 8 分槽——**槽位跨状态不稳定**（同一单位在不同回合可能落到不同槽号），这是 v2.0.0 与后续 v2.1.0「12 个局内稳定槽」的关键差异。
- **移动语义**：`_fixed_move` 要求落点严格**接近**移动目标（`distance < 当前距离`），不绕路到任意可达格——与引擎「一步可直达任意可达格」的能力不对齐，机动性受限（v2.1.6 才修）。
- **攻击目标**：`_best_target` 优先级 = 总部（权重 10000）＞受伤最重（`maxHp−hp` 最大）＞血量最低。
- **治疗**：仅 support，治疗范围内 `maxHp−hp` 最大的受伤友军。
- **部署**：`_fixed_deploy` 从总部/己方据点相邻的 plain 空格中，选离敌方总部最近者；需补给 ≥ 兵种 cost。
- mask：`action_masks()` 按每个槽是否填入合法动作（`action[0]` 非空）逐槽置真。

## 训练对手与奖励

### 规则对手（`player_b`）

`_play_opponent_until_agent_turn()` 的优先级脚本：

1. 有攻击动作 → 取第一个 `attack`；
2. 否则有治疗 → 取第一个 `heal`；
3. 否则有部署且**补给 ≥ 90** → 取第一个 `deploy`；
4. 否则有移动 → 取第一个 `move`；
5. 都没有 → 取第一个合法动作（通常 `end_turn`）。

对手动作被拒时兜底 `end_turn`；遇限流向上抛出。这是一个「会反击但不会适应」的中等强度脚本，比 v1 的随机对手强得多，因此成为 v2.1.x 系列的验收标尺。

### 奖励（`step()`，首次引入塑形）

总奖励 = 裁决分增量项 + 塑形项 + 终局项，裁剪到 `[-2, 2]`：

- **主项**：裁决总分（`adjudication.scores[owner].total`）增量 `/100`，裁剪 `[-1, 1]`。
- **塑形项** `_shaped_reward`（裁剪 `[-1, 1]`），精确常数：
  - 占点数增量 × **0.7**；
  - 敌方 HP 削减 `/100`；
  - 己方 HP 恢复 `/160`；
  - 最近未占领据点距离的**势函数** shaping × **0.025**（靠近为正、远离为负）；
  - `deploy` 动作 **+0.12**、`attack` 动作 **+0.05**；
  - 无占点变化的 `end_turn` **−0.01**（鼓励推进、惩罚空过）。
- **终局项**：胜 `+1`、负 `−1`。
- 非法/过期动作：`−0.05`（不中断 rollout）。
- **结算时机**：在对手响应之后结算分数差——该时机后被证明正确（v2.1.0 改为立即结算导致占点信号被吞，v2.1.7 又回退到此语义）。

## 性能记录

评估协议：`rl/evaluation/evaluate_cross.py`，确定性策略，`default` 地图，15 回合裁决分定胜负。

- **训练回报**：无周期评估标量胜率，仅 rollout 日志；`ep_info_buffer`（收尾 100 局）平均回报 **20.76**（区间 12.76–26.53）、平均局长 **116.6 步**（109–122）。`RELEASE_NOTES`/`MODELS_NOTES` 记录的「平均回报 −7.60 → 20.76」中的 20.76 即此收尾值。注意该回报含 v2.0.0 新增的塑形项，**量纲与 v1.0.0 的 8.12 不可直接比较**。
- **跨版本压制**：作为 v2.1.x 的对手与标尺，对 v2.1.1–v2.1.8 各版本保持压制（详见各模型档案：v2.1.1 固定坐 player_b 时对 v2.0.0 为 0:4；v2.1.4–v2.1.8 互打对 v2.0.0 全 0:8）。
- **镜像对局**：证明 `default` 地图无先手优势（v2.2.0 期镜像局 3:3）。
- **关键限制**：**只能坐 `player_a` 满血**——坐 `player_b` 时固定视角编码严重分布外，实测训练形态被真身 8:0。这一限制无法通过后处理修复。

## 部署与兼容性

- **必须**用 `run_model_v200.py` + `env_v200.py` 快照，尽量固定 `player_a`；服务端 `src/api/bots.ts` 按动作空间 **38 → `run_model_v200.py`（label `v2.0`）** 路由。
- **动作空间不兼容**：`Discrete(38)` 不能加载进 54 动作（v2.1+）或 155 动作（v3.x）环境。
- **作为训练对手**：在 v2.1.x/v2.2.x 环境中由 `env.py` 的 `legacy` 分支驱动（复现 38 动作语义 + 相对视角观测）；`env_v200` 原版动作生成已用 378 个真实对局状态与 legacy 分支逐格对拍验证（v2.1.5）。
- **续训**：不能续训 v1 的 512 动作模型；v2.0.0 自身可作为 v2.0.x 续训起点，但动作空间变更到 v2.1.0 后必须从零训练。

## 一句话总结

v2.0.0 把 RL 从「跑通链路」推进到「有对手、有塑形、有固定动作语义」：规则对手 + 38 固定意图槽 + 精确奖励塑形，使它成为整个 v2.1.x 系列的对手与验收标尺；但固定 player_a 视角与「单位排序分槽、移动严格接近」两处语义，注定它只能在主场满血，并被 v2.1.0 的相对视角 + 12 稳定槽 + BFS 绕路全面重构。
