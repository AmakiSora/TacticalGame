## 网络、观察和动作

同 v2.3.1：`5974 → 64 → 64` Tanh MLP ×2，`Discrete(54)`，5974 维相对视角观测（331 格标准定序 × 18 特征 + 16 全局，槽 17 攻击力/防御、动态归一化，详见 v2.3.1 档案），参数量 776,695。

## 训练过程与超参数

- **自对弈快照阶梯（v2.3.2 核心）**：`train.py` 新增 `SnapshotCallback`，每 `RL_SNAPSHOT_FREQ`（默认 5000）次回调**原子写入**一个历史策略快照，只保留最近 `RL_SNAPSHOT_KEEP`（默认 20）个，目录 `rl/selfplay/random`（已入 gitignore）。每局对手有 60% 概率从最近 8 个快照中随机抽一个（对手视角编码、模型缓存），40% 用 mixed 规则。
- **训练初期无快照时自动用规则对手**；快照加载/行动失败时当局降级为 mixed 规则，不中断训练。
- **评估环境仍为纯规则对手**（衡量绝对强度的标尺不变，与历史可比）。
- 4 环境并行、GPU、标准超参（`lr=3e-4`、`clip_range=0.2`、`ent_coef=0.01`、`n_steps=256`、`batch_size=64`、`gamma=0.99`、`target_kl=None`）；`_n_updates=3320`。
- 诊断动机（`3d38124`）：v2.3.1 在 default 静态图对规则对手 8:2（布局能泛化），但对强模型对手 0:8——瓶颈是**训练只打弱规则对手、对手强度封顶**。自对弈让对手强度随训练一起提升。

## 性能记录

评估协议：确定性策略，双座位换边。

| 对局 | 结果 |
|---|---|
| vs mixed 规则对手（随机图，20 局） | 12:0:8，平均据点 1.70（对规则未提升，但规则对手不再是有效标尺） |
| vs `v2.3.1`（随机图，8 局换边） | **7:1** |
| vs `v2.2.0`（随机图，8 局换边） | **7:1** |
| vs `v2.2.0`（**default 验证集**，8 局换边） | **7:1**（v2.3.1 同一对局为 0:8） |
| 训练期评估（随机图、规则对手） | 区间 15%-75%，峰值 75%@5 万步 |
| `ep_info_buffer`（收尾 100 局） | 平均回报 6.99（区间 −12.30–39.29），平均局长 99.4 步（20–202） |

关键结论（`MODELS_NOTES` 模型 10）：

- **default 验证集从 0:8 翻到 7:1** 证实：布局泛化本就存在，瓶颈确实是对手强度；自对弈提升绝对棋力后，未见过的地图也能赢——「无论玩什么图都得胜利」的目标初步达成。
- **对规则胜率反降（14:6→12:8）不是退化**：自对弈后策略针对的是会反击的对手，对不会适应的弱规则对手的刷分不再优先。
- 训练期胜率曲线震荡但互打分持续上升，再次说明**随机地图上的训练自评胜率不是可靠棋力标尺**，交付/验收必须用互打。
- ⚠️ **样本口径提醒**：上表 8 局换边成绩早于 `--swap-sides` 座位 bug 修复（见 v2.5.0 档案）；且 default「7:1」在 v2.5.0 期拆座位复测中被推翻——历代随机图模型坐 player_a 对 v2.2.0 全部 0:8，只有后手能赢，历史 7:1/6:2 属换边小样本噪声。引用需带此保留。

## 部署与兼容性

- **双座位可战**，任意标准双人地图（随机图与静态图）当时都推荐用本模型；`8c96e34` 记录已部署生产（容器内加载 + predict 通过，`/api/rl/models` ≥v2.3 → `run_model.py` 路由正确）。
- 可在当前环境续训；快照目录 `rl/selfplay/random` 已有梯度，续训即恢复自对弈。
- 部署排除 `rl/selfplay`（约 190MB 训练产物，服务器只需正式模型，不打进镜像）。
- 3922 维旧模型不能加载进本环境；跨版本对战用 `evaluate_cross.py`（5974→env_v24）。

## 一句话总结

v2.3.2 用「60% 自对弈快照阶梯 + 40% 规则」把对手强度从封顶解放出来，第一次做到随机图与未见过的 default 都能赢，达成「任意地图可战」；它确立的自对弈快照机制成为此后每一代（v2.3.3→v2.7.0→v3.0.2）的训练地基。
