## 训练过程与超参数（本代三处新增）

1. **学习率线性衰减**：从 `RL_LEARNING_RATE`（默认 3e-4）线性降到 `RL_LR_END`（默认 3e-5），治后期胜率震荡；续训经 `MaskablePPO.load(learning_rate=schedule)` 覆盖，进度按本次 learn 的总步数计。
2. **锚点对手**：`RL_ANCHOR_MODEL` 指定的强基准常驻自对弈候选池（与最近 8 个快照一起均匀抽样），防策略漂移退化；**未显式指定时续训默认用被续训的模型自身**（本次即 v2.3.2）。
3. **快照按保存时间排序**：续训时新快照的步数计数器可能低于旧快照，按步数排序会导致阶梯错位、裁剪倒挂；改为按保存时间排序。

- **训练中断**：目标 200 万步，**在约 146 万步处进程被外力中断**（日志无错误尾巴，疑似终端/宿主机休眠断开），断点完好（断点文件连续存至 1,460,000 步）。交付评估 best（77 万步，40 局评估峰值 77.5%）。评估提到 40 局/次（降噪）。
- 超参（zip `data`）：`clip_range=0.2`、`ent_coef=0.01`、`n_steps=256`、`batch_size=64`、`gamma=0.99`、`target_kl=None`；GPU；`_n_updates=7510`。
  - ⚠️ **交付 zip 的 `learning_rate` 显示为常数 3e-4**：这是 `sanitize_delivery_zip`（`12a2a0a`）清洗的结果——启用 lr 衰减后 `model.save` 会把 lr 调度闭包经 cloudpickle 序列化进 zip，该闭包在**异构机器（服务器）反序列化直接 SIGSEGV**（本地正常）。清洗把 `learning_rate` 改常数、移除 `lr_schedule` 字段；推理只需策略权重（lr 不影响 `predict`），续训经 `load(learning_rate=schedule)` 重新注入，不影响训练能力。**实际训练用的是 3e-4→3e-5 线性衰减。**

## 性能记录

评估协议：确定性策略，双座位换边。

| 对局 | 结果 |
|---|---|
| vs mixed 规则对手（随机图，20 局） | **15:0:5**，平均据点 1.95（三代最高） |
| vs `v2.3.2`（随机图，8 局换边） | **5:3** |
| vs `v2.2.0`（随机图，8 局换边） | **7:1** |
| vs `v2.2.0`（**default 验证集**，8 局换边） | **7:1** |
| 训练期评估（随机图、规则对手，40 局） | 区间 30%-77.5%，峰值 77.5%@77 万步 |
| `ep_info_buffer`（收尾 100 局） | 平均回报 13.43（区间 −9.21–54.09），平均局长 111.6 步（30–222） |

- 对 v2.3.2 仅 **5:3** 且训练后半段评估未再超越 77 万步峰值：**续训 + 学习率衰减带来小幅提升但未拉开差距**，后期震荡依旧（衰减把振幅收窄了一些，未消除）。续训的约 112 万新步（34 万→146 万）主要贡献是**稳定性**而非棋力上限。
- ⚠️ **样本口径提醒**：8 局换边成绩早于 `--swap-sides` 座位 bug 修复；default「7:1」在 v2.5.0 期拆座位复测中被推翻——v2.3.3 坐 player_a 对 v2.2.0 实为 **0:8**，只有后手能赢，历史 7:1 属换边小样本噪声（见 `MODELS_NOTES` 共同限制）。

## 部署与兼容性

- **双座位可战**，任意标准双人地图当时推荐都用本模型（已具备部署条件，服务器当时仍是 v2.3.2）。交付 zip 已清洗，容器内加载 + predict 通过（act=49 与本地一致）。
- 断点 `rl/checkpoints/random/20260829-211534/` 完好（至 146 万步），可随时补训剩余约 54 万步；但基于 5:3 的边际提升，**补训收益预期有限**。
- **教训**：长时间后台训练需防宿主机休眠/终端断开；分段续训或部署守护更稳。
- 3922 维旧模型不能加载进本环境；跨版本对战用 `evaluate_cross.py`（5974→env_v24）。

## 一句话总结

v2.3.3 在 v2.3.2 基础上加了「学习率线性衰减 + 锚点对手 + 快照按时间排序 + 交付清洗 lr 闭包」四项续训稳定性工程，把随机图世代的震荡收窄、并解决了大文件跨机加载段错误；但棋力对上一代仅 5:3，说明稳定性工程的边际收益已到，真正的跃迁要等 v2.4.0 的网络扩容。
