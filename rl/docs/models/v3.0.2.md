## 网络、观察和动作

同 v3.0.0/v3.0.1（详见 v3.0.0 档案）：`hex_transformer` 棋盘编码器（`HexBoardExtractor`，`d_model=64/n_heads=4/n_layers=1/features_dim=512`，actor/critic 共享，`net_arch pi[256]/vf[256]`），观测 6715 维（前 6205 同 v2.7 + 尾部 510 维候选描述），动作 `Discrete(155)`（12 单位槽 ×（7 移动候选 + 3 攻击候选 + 治疗 + 特殊）+ 10 部署候选 + end_turn）。

## 起因：155 动作在行为上退化为 54 动作

v3.0.1 中断后用离线探针 `rl/test-output/scripts/probe_action_dist.py` 检查动作分布，发现 v3.0 新增的候选**几乎从未被使用**：

| 断点 | move 候选 1-6 合法时选用率 | attack 候选 1-2 | deploy 候选 1 | 实测策略熵 |
|---|---|---|---|---|
| v3.0.1 蒸馏断点（PPO 前） | **0.00%** | 0.00% | 0.00% | 0.943 nats |
| v3.0.1 35 万步 best | 0.15% | 0.00% | 0.00% | 1.149 nats |
| v3.0.1 64 万步 | **0.00%** | 0.00% | 1.05% | 0.854 nats |

平均合法动作 25-28 个（均匀分布熵应为 3.2-3.3 nats），实测熵只有其 1/3；64 万步比 35 万步**更低**，训练在持续压缩策略。**死锁机制**：蒸馏标签全部来自老师（54 动作经 `map_v27_action` 全落在候选 0），纯交叉熵把其余 101 个新动作的 logit 反复下压；而 PPO 的策略梯度只对**采样到的**动作有信号，概率≈0 → 采样不到 → 无梯度 → 永远为 0。这解释了 v2.8/v3.0.0/v3.0.1 三代为何都只能与老师打平（43:53 / 51:45 / 49:47）——模型本质是 v2.7.0 的克隆。

## 四处修复

1. **掩码标签平滑**（`distill.py`，`--label-smoothing` 默认 **0.15**）：目标分布 = `0.85·老师动作 + 0.15·合法动作上的均匀分布`，新候选在 PPO 起点就保留可采样概率质量；蒸馏轮数 12→8 弱化克隆强度。
   - ⚠️ **不能**用 `F.cross_entropy(..., label_smoothing=eps)`：它把 eps 均分给全部 155 类（含被 `masked_fill(-1e9)` 的非法类），`log(≈0)` 量级的项会让 loss 爆炸。必须在合法集内手工构造目标分布，并用 `torch.where` 把非法位归零。
2. **探索监控**（`train.py` 新增 `ActionDiversityCallback`）：每 `RL_EXPLORE_LOG_EVERY`（默认 20000）帧把 `explore/new_candidate_rate`、`explore/{move,attack,deploy}_new_rate`、`explore/legal_actions_mean` 写入 TB；数据取自 `collect_rollouts` 局部变量（`actions` 与 `action_masks` 严格配对）。持续为 0 即可立即止损。
3. **评估降噪**：`RL_EVAL_FREQ` 5 万→**10 万步**、`RL_EVAL_EPISODES` 48→**96 局**（总开销不变，单次决策噪声减半）。**best 选择键加入后手座下界**（`eval_worker.py` `play_scenario` 分座位记账）：由四元组改为 **(最弱场景下界, 后手座合并下界, 平均下界, 占点, 回报)**。
4. **熵系数 `RL_ENT_COEF=0.03`**（原 0.01），由启动脚本显式设定。

### 冒烟测试暴露的隐蔽 bug：`RL_ENT_COEF` 对续训一直是死变量

- `distill.py` 建 `MaskablePPO` 时没传 `ent_coef`，断点存 sb3 默认 **0.0**（实测 v3.0.0/v3.0.1 两个蒸馏断点均为 0.0）；
- `train.py` 续训走 `MaskablePPO.load(..., custom_objects={...})`，而当时 `custom_objects` 只含 `n_steps`/`batch_size`/`target_kl`；sb3 的 `load` 以断点保存值为准，只有 `custom_objects` 里的项被覆盖 → **`RL_ENT_COEF` 从未生效**（`RL_GAMMA`/`RL_CLIP_RANGE`/`RL_N_EPOCHS` 同样对续训无效）。
- 后果：**v3.0.0/v3.0.1 整个 PPO 阶段零熵正则**，正是策略熵从 0.94 起未再有效打开（35 万步 1.15、64 万步回落至 0.85）、新候选概率质量从 5.5%（35 万步）掉到 1.4%（64 万步）的直接原因。
- 修复：新增 `train.resume_custom_objects(...)` 纯函数，把 7 个环境变量驱动的超参统一在 load 时覆盖；`distill.py` 新增 `--ent-coef`（默认 0.01）。验证：修复前后产出断点的 `ent_coef` 分别为 **0.0 → 0.03**（本模型 zip 内 `ent_coef=0.03` 即修复生效的铁证）。
- `env.py` 新增公共函数 `classify_action(index) -> (意图, 候选序号)`，供训练回调与离线探针共用。

## 训练过程与探索

- **配方**：v2.7.0 老师蒸馏冷启动（合法集内标签平滑 eps=0.15、8 轮，验证集动作准确率 67.4%，**新候选概率质量 11.52%** vs v3.0.1 无平滑时 0.34%）→ PPO 150 万帧。8 环境 `SubprocVecEnv`、`hex_transformer` 编码器、lr 5e-5→1e-5 线性衰减、`ent_coef=0.03`、锚点 v2.7.0 自对弈局 40% 出场、PFSP 快照阶梯。
- 超参（zip `data`）：`n_steps=512`、`batch_size=256`、`clip_range=0.2`、`gamma=0.99`、`target_kl=0.02`、`learning_rate` 交付清洗为常数 1e-5；GPU；`num_timesteps=1440000`、`_n_updates=3510`。
- **探索确实打开**：`explore/new_candidate_rate` 从 v3.0.1 的 0.00% 升至 **0.6%-1.5%**（峰值 @30 万步），attack 新候选一度 10%；策略熵全程 **1.5-1.8 nats** 不再坍缩（v3.0.1 为 0.94→1.15→0.85 始终未打开）；`explained_variance` 0.63-0.87，target_kl 未触发。
- **但训练期 15 次评估的 best 一直是 10 万步断点**：综合键（最弱场景 Wilson 下界）被 `default_champion` 场景主导——该场景从 73%@10 万步崩到 18%-35%（后期），先手座多次 0%（default 开局呈 0%↔94% 双稳态），而后期对锚点的 `random_champion` 60%-70% 走强被掩盖。**教训：训练期 best ≠ 最强断点**——交付 best（10 万步）96 局仅 53:43，1.4M 断点两批累计 123:69。

## 性能记录

验收协议：`evaluate_cross.py --map random --swap-sides --games 96 --seed-prefix <prefix>`，确定性策略，对手 v2.7.0，48 对全新随机图每对配对换座。批次一 `cross` 与 v3.0.0/v3.0.1 验收同一批地图（直接可比），批次二 `cross2` 为全新地图；逐局累计于 `rl/test-output/stats/stats_v302_1400k_v270_random.jsonl`。

| 对局 | 结果 |
|---|---|
| vs v2.7.0，批次一（96 局） | **61:35**（63.5%，下界 53.6%）；先手 72.9% / 后手 54.2% |
| vs v2.7.0，批次二（96 局） | **62:34**（64.6%，下界 54.6%）；先手 79.2% / 后手 50.0% |
| **累计（192 局）** | **123:69（64.1%，Wilson 下界 57.1%）**；先手 73/96 = 76.0%（下界 66.6%）、后手 50/96 = 52.1%（下界 42.2%） |
| 同批地图历史对照（批次一） | v2.8.0 43:53 → v3.0.0 51:45 → v3.0.1 49:47 → **本模型 61:35** |
| 交付 best（10 万步，降级） | 96 局仅 53:43（55.2%，下界 45.3%）——弱于 1.4M 断点 |

**晋级判据**：总分下界 57.1% 与 v2.7.0 当年晋级证据（66:30、下界 58.9%）同级；先手座下界 66.6% 过线；后手座点估计 52.1% 为**历代首次对 v2.7.0 不输**（此前 v2.8.0 29.2%、v3.0.0 47.9%、v3.0.1 39.6%），但 96 局样本的下界 42.2% 未过 50%——按「两座位下界均 >50%」的字面标准，后手座还需更大样本确认。

## 部署与兼容性

- 服务端 155 动作 → `run_model.py` 路由不变；前端模型列表按修改时间排序，本模型默认首位。
- **决策**：交付 1.4M 断点，**v3.0.2-1.4M 替换 v2.7.0 成为生产 champion**；v2.7.0 降级为上一代 champion 与 v3.0 自对弈锚点。
- 同代中间产物（**勿部署**；**均已被清理删除**，`train_v3.0.2.log` 证实曾生成）：`hex_ppo_v3.0.2_20260905_random_selfplay_1500000.zip`（训练期 best = 10 万步断点）、`hex_ppo_v3.0.2_20260905_distilled.zip`（掩码标签平滑 8 轮蒸馏冷启动断点，验证集动作准确率 67.4%、新候选概率质量 11.52%）。
- 6715 维断点不能由 v2.x 环境加载；跨版本对战用 `evaluate_cross.py`。
- 完整 checkpoint（16 万步起每 16 万步一个 + `best/` 为 10 万步评估 best）在 `rl/checkpoints/random/20260905-011908/`；TB 日志 `rl/tb/ppo_random_20260905-011908_resume_0`。
- **管线教训（v3.0.3 起改）**：评估场景含训练分布外（default）时，`min_wilson_lb` 选择键会被 OOD 崩塌主导、系统性偏向训练早期断点。改进方向：候选断点交付前互打验收，或把选择键拆分为「random 场景下界」选 best、default 下界仅记录不参与选择。

## 一句话总结

v3.0.2 定位并打破了 v3.0 的探索死锁——掩码标签平滑让新候选保留可采样概率、`resume_custom_objects` 修复了 `RL_ENT_COEF` 对续训一直是死变量的隐蔽 bug（v3.0.0/v3.0.1 全程零熵正则）、探索监控 + 分座位 best 选择键 + 评估降噪配套到位；1.4M 断点在两批全新随机图各 96 局配对换座中对 v2.7.0 累计 **123:69**（下界 57.1%），五代以来首次战胜 v2.7.0，成为当前全地图 champion，并留下「训练期 best ≠ 最强断点、交付前必须互打验收」的管线教训。
