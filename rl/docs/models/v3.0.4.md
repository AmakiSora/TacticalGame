## 网络、观察和动作

同 v3.0.0–v3.0.3（详见 v3.0.0 档案）：`hex_transformer` 棋盘编码器（`d_model=64/n_heads=4/n_layers=1/features_dim=512`，actor/critic 共享，`net_arch pi[256]/vf[256]`），观测 6715 维（前 6205 同 v2.7 + 尾部 510 维候选描述），动作 `Discrete(155)`。

## 配方改动（相对 v3.0.3 的最小差异）

1. **不蒸馏**：v3.0.3 已验证探索死锁修复后的持续 PPO 路线，且其训练期评估**末次（500 万步）即全程 best**、未见平台期，从已收敛断点直接续训有依据；
2. **弱图加权**：breach/desert 0.083→0.10，danger-close/default 0.083→0.08，dual-lanes/forge 0.083→**0.07**（这个削减被怀疑是 dual-lanes 整图遗忘的直接原因）；
3. **学习率降温**：3e-5 → 5e-6 线性衰减（v3.0.3 为 5e-5→1e-5；从更收敛的 5M 断点续训）；
4. 锚点、熵系数 0.03、`target_kl=0.02`、8 环境、评估 10 万步 × 96 局、断点每 1 万次调用（8 万帧）一存，均沿用 v3.0.3。

超参（zip `data`）：`n_steps=512`、`batch_size=256`、`clip_range=0.2`、`gamma=0.99`、`ent_coef=0.03`、`target_kl=0.02`、`learning_rate` 交付清洗为常数 5e-6、`num_timesteps=8,440,000`（交付断点实测；训练终点 8.6M）。

## 训练过程与超参数

- **全程健康**：`explained_variance` 0.58–0.89（末段均值约 0.80），`explore/new_candidate_rate` 0.8%–1.7%（无归零），`time/fps` 中位数约 130，`target_kl` 未触发，无 GPU 中断。
- **末次评估（8.6M）读数漂亮但未刷新 best**：分布内最弱下界 54%、后手座下界 60%、对锚点 random 64%/default 100%——但选择键（最弱下界, 后手座下界, …）元组仍低于 7.8M 断点的 (56%, 67%)，日志最后一次 `<- new best` 停在 7.8M；训练期 best 因此是 7.8M 权重，仅按「交付名 = 训练终点」惯例命名为 `hex_ppo_v3.0.4_20260909_random_selfplay_8600000.zip`（`best/best_model.zip` 权重哈希与 7,800,000 步快照逐字节一致）。

### 全图验收：总分过线，dual-lanes 一票否决

`evaluate_cross.py --swap-sides --seed-prefix 31337`（与 v3.0.3 验收同批地图），v3.0.4-8.44M vs champion v3.0.3-5M，480 局配对换座（`stats_v304_accept.jsonl`、日志 `accept_v304.log`）：

| 地图 | 比分（v304:v303） | 判定 |
|---|---|---|
| random（96） | **57:39**（59.4%） | 双座均衡（29/28），random 优势守住 |
| danger-close（96） | 48:48 | **纯座位锁**：坐 player_a 者全杀（v3.0.3 坐 player_b 同样 0 胜），判平 |
| default（96） | 48:48 | **纯座位锁（反向）**：坐 player_b 者全杀，判平 |
| breach（48） | **48:0** | 双座全胜——v3.0.3 的 35% 退化修复 |
| desert（48） | **48:0** | 双座全胜——v3.0.3 的 46% 退化修复 |
| **dual-lanes（48）** | **0:48** | **双座全崩**（全部 last_player_standing 被歼灭，比分约 1:2.2；全场仅 1029:2300 / 2435:1262 两个比分交替） |
| forge（48） | 24:24 | 纯座位锁：坐 player_b 者全杀，判平 |
| **总分** | **273:207（56.9%，Wilson 下界 52.4%）** | 总分过 50% 下界线，但 dual-lanes 触发一票否决 |

**静态图确定性警示**：同种子静态图 + 双确定性策略 ⇒ 48 局实为 2 个不同对局各重复 24 次（座位锁图同理），此类图的「48 局」有效样本是 2，只能作方向性证据——该读数同样适用于 v3.0.3 当年 danger-close 96:0 的验收。

**决策**：v3.0.3 继续担任生产 champion；v3.0.4 交付文件保留可玩（AI 竞技场 Bots 下拉可见），不进 champion 位。根因怀疑：dual-lanes 权重 0.083→0.07 后整图遗忘（与 v2.6.0 的 default 灾难性遗忘同型）。修复版 v3.0.5（dual-lanes 权重回补 0.10 续训）曾短暂启动，即按用户决策中止并清理，**未产出模型**；RELEASE_NOTES 留有判据：若「削权重 → 整图遗忘」在其他图复现（whack-a-mole 再现），说明 155 动作 × 7 图超出 1 层 64 宽 Transformer 容量，应转向加深/加宽编码器——这条判据直接引出 v3.1.0 的容量对照实验与 2026-09-10 的随机域拓宽。

- 6715 维断点不能由 v2.x 环境加载；跨版本对战用 `evaluate_cross.py`。

## 一句话总结

v3.0.3 的 breach/desert 退化用「弱图加权续训」精准修复（双 48:0），总分 273:207（56.9%，下界 52.4%）过线，但 dual-lanes 权重被挤掉 0.013 后整图遗忘、0:48 双座全崩触发一票否决；本代还留下两条方法论遗产——训练期 best（选择键停在 7.8M，交付名却按终点写成 `_8600000`）初筛互打 288 局被 8.44M 断点翻盘（v3.0.2 后第二次「best ≠ 最强断点」），以及「同种子静态图 + 双确定性策略 ⇒ 48 局有效样本只有 2」的判读铁律，并把「容量是否为 whack-a-mole 根因」的问题交给了 v3.1.0。
