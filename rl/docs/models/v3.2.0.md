## 网络、观察和动作

与 v3.0.0–v3.1.1 逐项相同（详见 `models/v3.0.0.md`）：`hex_transformer` 棋盘编码器
（`d_model=64` / `n_heads=4` / `n_layers=1` / `features_dim=512`，actor/critic 共享，
`net_arch pi[256] / vf[256]`，`net=256(from checkpoint)`），观测 **6715 维**
（前 6205 同 v2.7 + 尾部 510 维候选描述），动作 `Discrete(155)` 分层动作 + 合法动作 mask。
**决策一（v3.2.0 方案明文）就是「不改观测与动作空间」**——本轮所有改动都在训练侧。

## 训练过程与超参数

- **起点**：A4 交付物（消融 #3，奖励量纲 `hq_damage` 0.15→3.0，内部 9.0M），不是 v3.1.1 原版。
- **配方**：8 环境 `SubprocVecEnv`、`n_steps=512`、`batch=256`、`n_epochs=10`、`gamma=0.99`、
  `gae_lambda=0.95`、`clip_range=0.2`、`target_kl=0.02`、`ent_coef=0.03`、模型对手随机动作 30%。
- **学习率走原调度 `schedule 5e-05 → 1e-05`，但实测全程只有 `1.40e-05 … 1.00e-05`**：
  `train.py:88 make_lr_schedule` 用的是**累计** `progress_remaining`，续训起点 9.0M/10.0M
  ⇒ 进度只剩 0.09，第一步 LR 就是 1.4e-5。日志首个 rollout 即打印 `learning_rate 1.4e-05`。
  （本条是 v3.2.0 全系列「多轮续训零净进展」的直接机制，见方案 §5.7.3。）
- **评估**：每 20 万步异步 96 局/场景 + 算法场景 192 局；best 选择热身 30 万帧；
  `RL_SNAPSHOT_FREQ=5000` 次调用（8 环境 = 每 4 万帧一个快照）。
- **用时**：2026-09-18 15:04 启动，`time_elapsed ≈ 6927 s`（约 1 小时 55 分），fps 138–144。
- **交付断点选择**：训练期 5 个 `random_champion` 评估点 = **45 / 44 / 44 / 54 / 43 %**
  （对应 9.2 / 9.4 / 9.6 / **9.8** / 10.0M）⇒ 选中 9.8M。**但这条曲线没有上升趋势**，
  9.8M 是孤立尖峰（见「性能记录 · 轨迹测试」）。

## 训练对手与奖励

**对手池全局构成**（`RL_ALGO_OPPONENT_PROB=0.20` / `RL_SELF_PLAY_PROB=0.70` / `RL_ANCHOR_PROB=0.50`）：

| 对手 | 全局占比 | 算式 |
|---|---|---|
| 锚点 v3.1.1（冻结） | **28%** | (1−0.20) × 0.70 × 0.50 |
| 快照自对弈（PFSP 近期加权） | **28%** | (1−0.20) × 0.70 × 0.50 |
| 算法对手（greedy/field/threat） | **20%** | `RL_ALGO_OPPONENT_PROB`，优先分支 |
| 规则 | **24%** | 余项 |

> ⚠ **不要照抄启动器注释**：`run_train_v320_champ.bat` 里写「全部对局里约 35% 是打 v3.1.1」，
> 那是把 `0.70 × 0.50` 当成全局占比算的。`_choose_opponent_style`（`rl/envs/env.py:617`）
> **算法分支优先级最高，先吃掉 20%，剩下的 80% 才去抽自对弈**，所以锚点全局只有 28%。
> 方案 §5.7.2 专门为此立了「记账更正」。交叉验证：`[explore]` 的 `algo_episodes`
> 每 3 万帧 +66～74 局，除以全局约 350 局 ≈ 20%。

**奖励**（`RL_REWARD_*`）：`hq_damage=3.0`、`hq_push=0.5`、`new_unit_type=0.05`、
`shaping_scale=0.5`、`win=5.0`。

> ⚠ **机制警告（v3.2.0 新增认识）**：`env.py:551` 先 `clip(reward, -1, 1)`，`env.py:431`
> 才乘 `shaping_scale`。HQ 项 = ΔHP/100 × 3.0，**单步 ≥34 点伤害就顶满 1.0**，同一函数里的
> `control_points` / `new_unit` 被一起裁掉 ⇒ **把 `hq_damage` 从 0.15 抬到 3.0 不是加强信号，
> 只是加深饱和**。这正是 A4 那轮「动了但头对头没改善」的原因，也是后续不要再调奖励量纲的依据。

**本轮相对 3.x 原配方的 4 处差异**（v3.2.0 全部轮次都带着，方案 §5.14 列表）：

| 项 | 3.x 原配方（有 +5.7pt 战绩） | 本轮（v3.2.0） |
|---|---|---|
| 算法对手 `RL_ALGO_OPPONENT_PROB` | **0（默认）** | **0.20** |
| 锚点 | v3.0.3 @0.20 | v3.1.1 @0.50 |
| 奖励 | 全默认（hq 0.15 / new_unit 0） | hq 3.0 / push 0.5 / new_unit 0.05 |

## 性能记录

**验收协议（同一把尺子）**：`eval_worker.py --map random --opponent-style mixed
--episodes 192 --anchor hex_ppo_v3.1.1_..._10940000.zip`，`random_champion` 场景 =
对手 100% 是锚点 v3.1.1、成对换座、双方确定性策略。**零假设（v3.1.1 打自己）结构性恒为
50.0%**（每对局恰贡献 1 胜，无抽样误差）。单题 192 局的 s.e. ≈ 3.6pt。

| 场景 | `--seed-prefix 27000` | `90000` | 两套均值 |
|---|---|---|---|
| **`random_champion`（验收轴，对 v3.1.1）** | **50.0%**（96/192，lb 43.0，先手 58.3 / 后手 41.7） | **48.4%**（93/192，lb 41.5，先手 54.2 / 后手 42.7） | **49.2%** |
| `random_rule` | 87.0% | 81.2% | 84.1% |
| `default_champion` | 50.0% | 50.0% | 座位决定型 0/50/100 读数，无信息量 |

**读法（重要）**：49.2% 与 50.0% 的差 **在噪声之内** ⇒ 正确表述是「**追平、未超越**」，
不是「打输」。整条 v3.2.0 血统的上限是「单套题上摸到 50.0%」，**从未在两套题上同时越过 50%**。

**轨迹测试（决定性）**：同尺子测 champ 训练内的验收轴轨迹（`--seed-prefix 27000`）。

| 断点 | 累计步数 | 对 v3.1.1 | 先手 / 后手 | rule |
|---|---|---|---|---|
| A4 首个快照 | 8.84M（= v3.1.1 + 40k） | 44.8% | 53.1 / 36.5 | 84.9% |
| | 9.24M | 40.1% | 47.9 / 32.3 | 81.8% |
| | 9.60M | 45.8% | 57.3 / 34.4 | 82.3% |
| **交付断点** | **9.80M** | **50.0%** | 58.3 / 41.7 | 87.0% |
| | 10.00M | 44.8% | 54.2 / 35.4 | 83.9% |

- 交付点是五点最大值，比四个邻居高 4.2–9.9pt；**剔除它，其余四点均值只有 43.9%**。
- 跨第二套题复核：9.60M = 46.6%、**9.80M = 49.2%**、10.00M = 47.4% ⇒ 交付点的优势降到
  1.8–2.6pt，且**「最大值在哪个断点」两套题答案不同**（27000 认为 9.80M，90000 认为 10.00M）。
- ⇒ **本仪器在 n=192 时无法分辨 checkpoint 之间的好坏**；交付读数的 +2pt 属 best-of-run
  的正常乐观偏差（与回归均值同量级）。也因此 `run_train_v320_champ6.bat` **不启动**。

**与上一代的对照（同一把尺子）**：v3.0.4（上一代 3.x）对 v3.1.1 = **44.3%**，
v3.1.1 对 v3.0.4 = **50.0%** ⇒ **「一代进步」= 5.7pt**。而 **v3.2.0 的典型断点水平（≈44%）
恰好等于上一代 v3.0.4**，只有「选峰」才摸到 v3.1.1。

**七轮实验全部落在 40–50%**（详见方案 §5.10 / 结论文档）：A4 48.2%、**champ 49.2%（最好）**、
champ2 47.9%、champ3 46.6%、champ4 46.6%、champ5 43.0%、r3x 45.0%（末态 39.0%）。
**没有一轮产生可复现的正向位移**；唯一稳定规律是 `schedule` 优于 `constant`。

## 部署与兼容性

- 155 动作 → `runners/run_model.py` 路由不变；6715 维观测，v2.x 环境不能加载。
- **未替换 champion**：`MODELS_NOTES` 的生产 champion 仍是 **v3.0.3**；选型建议是继续以
  **v3.1.1** 为线上模型，本模型作为**统计学等价的备选**（无证据表明互换有收益）。
- 可续训（sb3 `resume` 语义：`RL_TIMESTEPS` 为**新增**帧数；注意 LR 会被累计口径锁死）。
- 断点与快照索引：
  - checkpoint `rl/checkpoints/random/20260918-150412/`（9.4M / 9.8M 切片 + `best/` = 9.8M 交付源）；
  - 自播快照池 `rl/selfplay/random/v3.2.0_champ/`（20 个，9.24M–10.0M）；
  - TB 日志 `rl/tb/ppo_random_20260918-150412_resume_0`。
- **归档而非删除**：其余 7 个 v3.2.0 实验产物（`ablation_a4` / `ablation_ent03` /
  `ablation_lrconst` / `phaseA` / `champ2` / `champ3` / `champ4`）在 `rl/models/_archive_v3.2.0/`，
  被 `arena/matches.jsonl` 的历史记录引用，保留以便追溯（`arena` 参评的 v3.2.0 成员是
  `phaseA` 与 `ablation_ent03` 两个）。
- A1–A6 的**代码基础设施保留**（算法对手通道、评估场景与 best 选择键分离等）是可复用工程资产；
  被否决的是**配方改动**，不是通道本身。

## 一句话总结

v3.2.0 把「规则算法」这类策略形态直接放进训练对手池（A1–A3 算法对手 20% + A4 补 HQ 奖励项 +
A5 兵种 novelty + A6 评估场景/选择键分离），从 A4 断点续训 100 万帧交付 9.8M 断点：两套 192 局
头对头对 v3.1.1 拿 **50.0% / 48.4%（均值 49.2%）**，而零假设恒为 **50.0%** ⇒ **打平未超越**；
轨迹测试证明那 50.0% 是换题即不复现的孤立尖峰，「一代进步 5.7pt」的标尺显示它的典型水平只等于
上一代 v3.0.4。**七轮配方实验（奖励 / 靶子构成 / 解锁 LR / 拉长规模 / 还原原配方）全部落在
40–50%、无一条产生可复现正向位移**，配方路线正式关闭；下一步只剩结构性改动（从零训练更大容量，
`RL_NET_WIDTH` 仅从零生效；或改观测/动作空间）。

### B. 评估与判读（本文档所有读数都按这套口径读）

| # | 坑 | 正确口径 | 对策 |
|---|---|---|---|
| B1 | **零假设不是「估计 50%」而是恒等于 50%** | 成对换座下同策略自战，一对局恰贡献 1 胜 ⇒ 无抽样误差 | 判读直接比 `候选读数 − 50.0%`；只有**一个**读数时无法判断好坏，必须先跑 `--model X --anchor X` |
| B2 | **单套题过 50% 不算过** | 实测换题后符号翻转；绝对水平带 **±8pt 种子集合偏移** | 「超越」类 2pt 结论最少要**两套题同向 + 第三套未见题** |
| B3 | **单题 4–5pt 差异不能给 checkpoint 排序** | 那是「策略 × 题目集」交互噪声；n=192 分不出 | 见「性能记录 · 轨迹测试」；**别用单套题写「某改动 +3pt」** |
| B4 | **best-of-run 自带约 +2pt 乐观偏差** | 5 个评估点里挑最大值 = 选峰 | 交付读数必须注明「是被选出来的」；报告用两套均值 |
| B5 | **`default_champion` 是座位决定型 0/50/100** | 不是能力刻度（先手 100 / 后手 0 = 50%） | 先翻译成「先/后」再看；它作 §6 一票否决线是**反相关**的，不宜单独否决 |
| B6 | **`--seed-stride` 不是修法** | stride=6 给 62.3%、stride=1 给 46.3%、真值 54.3% ⇒ 误差都是 8pt，符号相反 | **修测量要修功效（N），不是修那个看起来像偏差的项** |
| B7 | **跨模型比较中途换 `--seed-prefix` = 换卷子** | 同一份 v3.1.1 换区间三算法均值 54.3%→46.7% | 全链冻结同一 prefix，**只报配对差值**；「差值」与「绝对水平」分开写 |
| B8 | **`mean_win_rate` / `ood` 会被 OOD 场景污染** | 三态跳变（0/50/100），实测在 38↔81 之间乱跳 | **只有 `min_wilson_lb`（仅分布内场景）是稳定键**；别用 `mwr` 摆动论证任何事 |
| B9 | **训练期不测目标 = 白烧帧** | 阶段 A 设了 `RL_EVAL_ALGO=0` ⇒ 2.5 小时 12 个评估点全是无判别力场景，关于真实目标**一条数据都没有** | **任何以某类对手为目标的训练，每个评估点都开 `--algo-scenarios`** |
| B10 | **48 局的底噪大于所有待测效应** | 三场景合并 SE ≈ 4.2pt、单场景 ≈ 7.2pt | 算法场景 **≥192**（推荐 300）；48 局只能「看方向」 |
| B11 | **stdout 的胜率是取整的** | `eval_worker.py` 打印 `win_rate=48%`，JSON 里是 48.4% | **读数一律取 `--out` 的 JSON**（`scenarios.*.win_rate`、`.seat_first`、`.seat_second`），1pt 量级差值会被取整糊掉 |
| B12 | **best 选择键需要热身期** | 三代（v3.0.2 / v3.1.1 / v3.2.0 阶段 A）都是「best = 第一个评估点」 | 设 `RL_BEST_WARMUP_STEPS`（`train.py:785`，单位 = **本次新增**帧数）；注意全程在热身期内会**退回终点模型** |
| B13 | **诊断计数器只留在 env 等于没做** | 阶段 A 的 `algorithm_actions` / `opponent_rejections` 只存在于 `env.py` 与 `tests/`，`train.py` 从不读 ⇒ 止损线**在 1.2M 帧里根本无法执行** | 按「env 方法 → 累计值 → 回调取窗口差分」三步接线，差分才是诊断量 |

### C. 工程与命名（续训 / 改名 / 交付时）

| # | 坑 | 说明 | 对策 |
|---|---|---|---|
| C1 | **模型版本 ≠ 游戏版本** | 只改 `rl/` 不动 `package.json` / `src/` | 不需要 `npm run version`、不需要 `release/x.y.z` 分支，用 `feature/` |
| C2 | **前缀陷阱（会静默产出错数据）** | `..._champ` 是 `champ2`/`champ3`/`champ4`/`champ5`/`champ5r`/`champ6` 的**前缀** | 改名正则必须带负向断言 `(?![0-9A-Za-z_])`，否则 `champ2` 会被改成 `...100000002` |
| C3 | **大小写陷阱** | `phaseA` 含大写，`[a-z0-9_]+` 的正则会**漏计** | 统计/校验一律加 `-i`，否则误判「榜单没改到」 |
| C4 | **同名不同义** | `temp/variants/threat_v4.*` 的 `v4` 是**算法变体编号**，不是版本标签 | 全仓替换时**必须排除**；另需排除 `node_modules`（含 `setuptools-84.0.0` 等无关命中）、`.venv`、`__pycache__`、`.git` |
| C5 | **归档而非删除** | `arena/matches.jsonl` 的历史对战按**文件名**引用产物 | 被否决的实验件移入 `rl/models/_archive_v3.2.0/`，不要 `rm`（本轮 7 个已归档） |
| C6 | **交付件未经清洗会导致异构机段错误** | lr 调度闭包是 callable，跨环境加载可能崩 | 交付前走 `sanitize_delivery_zip`（本模型 `data.learning_rate` 已是常数 5e-5、`clip_range` 是 `ConstantSchedule(0.2)`） |
| C7 | **自播池目录名会被先到的 run 占用** | `RL_SNAPSHOT_DIR=rl\selfplay\random\v3.2.0` 归了阶段 A | 同版本多 run 时保留 `_<tag>` 后缀（本模型 = `v3.2.0_champ`），不必强行用纯版本号 |
| C8 | **停后台评估：杀 python 杀不掉 bash 的 `for` 循环** | 实测杀完 python 后循环继续起下一组，白跑 20 分钟 | 要彻底停，得停**后台 shell 任务本身**（或先杀 shell 再杀 python） |
