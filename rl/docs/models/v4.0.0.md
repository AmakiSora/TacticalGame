## 网络、观察和动作

- **观测 6715 维 / 动作 `Discrete(155)`**：与 v3.0.0 起逐项相同（详见 `models/v3.0.0.md`）。
- **网络（本代唯一结构性改动）**：`hex_transformer` 由 `1 层×d64` 扩为
  **`n_layers=2` / `d_model=128` / `n_heads=4` / `features_dim=512`**，
  `net_arch pi[512] / vf[512]`（v3.x 为 256），actor/critic 共享特征提取器。
  参数量 0.87M → **1.44M**。**仅从零训练生效**（`train.py:826`，续训以 zip 内 `policy_kwargs` 为准）。
- 冒烟实测：单环境 68 fps、8 环境 **240–260 fps**（优于计划预估的 90–110），
  20M 帧预算从预估 56–64h 压缩到实际约 40h（含两次中断恢复）。

## 训练过程与超参数

### S0 · 蒸馏冷启动（算法教师，不加载任何历史模型）

| 项 | 值 |
|---|---|
| 教师 | **规则算法** threat:0.4 / greedy:0.35 / field:0.25（经 worker `decide` 通道，`distill.py collect-algo`） |
| 数据 | 400 局算法互打、**27,573 样本**、label fallback 率 **3.40%**（<5% 线） |
| 训练 | 8 epochs、batch 512、lr 1e-3、value_coef 0.5、OneCycleLR |
| 标签平滑 | **合法集内 eps=0.15**（手工构造，绝不用 `F.cross_entropy(label_smoothing=)`） |
| 价值头 | 未缩放回报 + Huber；闸门 **RMSE 2.26 vs std(return) 6.38**（比值 0.35，远小于 0.8） |
| 质量门 | 留出集动作准确率 **46.0%**、新候选概率质量 **67.5%**（远高于 8% 闸门）、策略熵 2.08 nats |

> 动作映射：算法 decide 返回引擎原生 payload，经 `_algo_action_index` 三级匹配
> （精确 → 同单位/同兵种最近落点 → None 回退 end_turn）映射回 155 动作表。
> 首版精确匹配失败率 33%，加结构化兜底后降到 3.4%。

### S1 · 爬升（6M 帧，2026-09-20 → 09-21）

- 对手池：算法 **20%**（greedy 0.50/field 0.30/threat 0.20，偏弱课程）、自对弈 **70%**、
  规则填充；**无锚点**（`RL_NO_AUTO_ANCHOR=1` 关掉 `champion_model_path()` 自动拾取历史冠军）
- 地图：`random:0.7` + 6 静态各 0.05；`RL_RANDOM_CORNER_BOOST={"p":0.18}`（随机域内联合边角提频）
- 奖励：胜负 ±5、塑形 ×0.5、`HQ_DAMAGE=3.0` / `HQ_PUSH=0.5` / `NEW_UNIT_TYPE=0.05`
- lr `schedule 2.5e-4 → 3e-5`、ent_coef 0.03、`RL_SNAPSHOT_KEEP=200`（长跑硬性前提）
- **交付**：`hex_ppo_v4.0.0_s1_6000000.zip`（内部 5.7M）；末次评估 rule 59%、lb 49%。
  结项后已移入 `rl/models/_archive_v4.0.0/`（与蒸馏断点同处，未删除）

### S2 · 加压（8M 帧，2026-09-21 → 09-24）

- 算法 20% → **30%**（greedy 0.40/field 0.30/threat 0.30）、自对弈 70%、`RL_EVAL_ALGO=1`
- lr `schedule 1.5e-4 → 2e-5`（续训名义抬高，规避累计口径锁低）
- **中断**：7.15M 处宿主内存耗尽（numpy 分配失败），从 7.1M 切片恢复（无损）
- **交付**：`hex_ppo_v4.0.0_20260923_11.4M.zip`（内部 **11.4M**）
- 末次评估（14.0M）：rule **72%**、threat **41%**、greedy **49%**、field **59%**、hq_damage 109.6

### S3 · 收束（+4M，人工终止于 3.0M）

- 算法 30% → **40%**、自对弈 70% → 60%、lr 8e-05 → 2e-05、**`RL_EVAL_ALGO_IN_SELECTION=1`**
- **结果：确定性退化**（见「性能记录」）；best 停在起点 11.6M，14 个评估点无一超越

### PPO 超参（三代相同）

`n_steps=512`、`batch=256`、`n_epochs=10`、`gamma=0.99`、`gae_lambda=0.95`、
`clip_range=0.2`、`target_kl=0.02`、`ent_coef=0.03`、8 环境 `SubprocVecEnv`、
`RL_EVAL_FREQ=200000`、`RL_EVAL_EPISODES=96`、`RL_EVAL_ALGO_EPISODES=192`、
`RL_EVAL_SEED_STRIDE=4`、`RL_BEST_WARMUP_STEPS=200000~300000`、`RL_SAVE_FREQ=50000`。

## 训练对手与奖励

**S2 对手池全局构成**（`RL_ALGO_OPPONENT_PROB=0.30` / `RL_SELF_PLAY_PROB=0.70` / 无锚点）：

| 对手 | 全局占比 | 算式 |
|---|---|---|
| 算法对手（greedy/field/threat） | **30%** | `RL_ALGO_OPPONENT_PROB`，优先分支不被稀释 |
| 快照自对弈（PFSP (1−胜率)²） | **70%** | `RL_SELF_PLAY_PROB`（无锚点，全部给快照阶梯） |
| 规则 | 余项 | 快照池为空时的自动回退（训练初期） |

**奖励**（与 v3.0–v3.2 相同，未改）：胜负 ±5、塑形 ×0.5（`env.py:431`/`:551` 的
clip(−1,1) 封顶在前）、`RL_REWARD_HQ_DAMAGE=3.0`、`RL_REWARD_HQ_PUSH=0.5`、
`RL_REWARD_NEW_UNIT_TYPE=0.05`。

**模型学到的战术（本代病灶）**：长训后收敛到**步兵海**——default 图步兵部署占比 **81%**、
游侠仅 14%（对手 v3.1.1 为 53%/47%），造成伤害 774 vs 1111、HQ 伤害 75 vs 133。
A5 novelty（每兵种**首次**部署一次性奖励）在 14M 帧长跑后完全失效。

## 部署与兼容性

- **不部署**。观测/动作与 v3.0.x–v3.2.x 相同，`bots.ts` 路由不变（`run_model.py`），
  技术上可加载，但验收未过。
- 可续训（zip 内 `policy_kwargs` 已固化 `2 层×d128`；续训时 `RL_TF_LAYERS`/`RL_TF_DIM`
  不生效，改容量必须从零）。
- 交付前**未做** `sanitize_delivery_zip`（未交付）；若要归档到 `rl/models/` 供
  arena 参照，需先清洗 lr 闭包。

## 一句话总结

**从零训练 + 容量翻倍（0.87M → 1.44M 参数）+ 算法教师蒸馏，三条结构性改动全部落地且
工程上成功（吞吐 240–260 fps、无探索死锁、算法对抗达标 41/48/53%），但对 v3.1.1 只到
46.6%，且三张静态图 0% —— 本代最大的产出是证伪了「对算法弱」这个前提：它其实是
「静态图弱」的测量假象，而静态图崩塌与算法对抗是同一个病（训练分布覆盖不足）。**

## 附：已知陷阱与踩坑清单（模板外补充）

**A. 训练机制**

1. **「对算法 16.5%」是聚合口径的假象**：arena 把 7 张图平均，静态图（desert 17%、
   breach 33%）拉低了总数；同一模型在随机图上对同批算法是 41%/45%/64%。
   给算法强度设目标前，先确认读数用的是哪张图 / 哪套聚合。
2. **A5 novelty 是一次性的**：`RL_REWARD_NEW_UNIT_TYPE` 只奖励每兵种首次部署，
   14M 帧长跑后步兵海复发（81% 步兵）。要长期压制需要持续性多样性奖励。
3. **静态图 0.05 地板权重守不住**：三张图 0%，与 v3.1.0/v3.1.1 同型。注意区分
   「削权重→整图遗忘」（v3.0.4）与「加权重」（未验证过）。
4. **收敛后抬 LR + 改对手配比 = 确定性退化**（S3，第四次复现）。续训的 LR 名义值
   需要抬高以抵消累计口径锁低，但**抬过头（8e-5）会毁掉已收敛策略**；5e-5 是
   v3.2.0 champ 与 v4.0.0 S2 都用过的安全值。
5. **`RL_EVAL_ALGO_IN_SELECTION` 首次上场即挡下一次错误交付**：S3 best 停在起点，
   14 个评估点无一超越。该开关的开启条件（对算法稳定 >40%）在本代是满足的。

**B. 评估判读**

6. **`evaluate_cross` 的 stats jsonl 里 `scores`/`winner` 是引擎原始座位键**，
   用 `players` 字段（模型名）反查座位才能正确统计——直接读 `player_a` 会把
   换座后的对局算反（本代初次统计即踩此坑，得出过 `+411 分却 0 胜` 的矛盾读数）。
7. **静态图 48 局 ≠ 48 个独立样本**：dual-lanes/forge 的 24:24 是座位锁（无信息量），
   default/breach/desert 的 0% 才是真信号（对照组 v3.1.1 vs v3.0.3 在同图 48:48，
   证明是技巧决定型地图）。

**C. 工程**

8. **不要用 cmd `.bat` 在 Git Bash 下直启**：中文 UTF-8 注释在 GBK 代码页下被逐行
   当命令执行，环境变量全丢、静默跑成默认配置（本代踩了两次）。改用 PowerShell 脚本。
9. **`.bat` 里的 JSON 环境变量不要转义**：`set "X={"p":0.18}"` 正确，`{\"p\":...}` 会
   被 cmd 破坏。
10. **新增随机参数必须同时补 `DEFAULT_RANGES`**：`startingUnitCount` 漏补导致
    `resolveParam` 抛 `undefined is not iterable`。
11. **16GB 本机跑 8 环境长训的内存红线**：训练栈约 6.2GB + 27 个 node/tsx worker 1.7GB，
    空闲在 0.94–2.1GB 间波动；7.15M 处 OOM 一次。断点 50k 切片是无损恢复的保底。
12. **日志编码不统一**：PowerShell `*>` 重定向产出 UTF-16，`python ... > file` 产出
    UTF-8；读日志一律先探测编码（本代脚本用 `decode("utf-16")` + fallback）。
