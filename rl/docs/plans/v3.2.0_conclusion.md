# v3.2.0 结项结论

> 日期：2026-09-19 · 状态：**已结项，训练与评估全部停止**
> 过程档案：`rl/docs/plans/v3.2.0.md`（§5.7–§5.16 为全部实验记录）

## 一句话

**v3.2.0 与 v3.1.1 打平，未超越。** 七轮配方实验全部落在 40–50%，最好产物 champ 的两套
192 局头对头均值为 **49.2%**，而零假设（v3.1.1 打自己）结构性恒为 **50.0%**。

|---|---|---|---|

| v3.0.4（上一代 3.x） | 44.3% | — | — |
| A4（奖励） | 46.4% | 50.0% | 48.2% |

- 零假设恒为 50.0% 不是巧合：成对换座下每对局恰好贡献 1 胜，无抽样误差。
- **整条 v3.2.0 血统的上限是「单套题上摸到 50.0%」，从未在两套题上同时越过 50%。**
- 单题 192 局 s.e. ≈ 3.6pt，换一套种子题的整体位移可达 ±4–7pt ⇒ 49.2% 与 50.0% 的差
  **在噪声之内**。正确表述是「追平、未超越」，不是「打输」。
- 唯一边缘负结果是 champ5 的 43.0%（≈2 s.e. 之下），元凶是 `constant` 学习率长跑
  （等长对照 `schedule` 49.2/47.9 vs `constant` 46.6/46.6，且 `constant` 越长越差）。
- **r3x 也复现了「继续训练 = 退化」**：它自己的 best（≈9.75M）在 `27000` 题上是 45.0%，
  而末态快照（10.4M）掉到 **39.0%**，且**两套题完全一致**（39.0 / 39.0）⇒ 不是噪声，
  与 champ5 同型（末态不如训练期 best，且退化幅度更大）。

## 二、为什么没做出来：四条机制归因

### 1. 奖励裁剪封顶，抬权重只加深饱和

`env.py:551` 先 `clip(reward, -1, 1)`，`env.py:431` 才乘 `shaping_scale`。HQ 项 =
ΔHP/100 × 3.0，**单步 ≥34 点伤害就顶满 1.0**，同一函数里的 control_points / new_unit
被一起裁掉 ⇒ 把 `hq_damage` 从 0.15 抬到 3.0（那轮 A4）**不会增加信号，只会加深饱和**。

### 2. 学习率被时间表锁死

`make_lr_schedule` 用**累计** `progress_remaining = 1 - num_timesteps/total`。续训时起点
已在时间表后段，实测 LR 是 **1.4e-05 → 1.0e-05**，而不是名义的 5e-05 → 1e-05。
但单独解锁 LR（champ3 / champ4）同样无效 ⇒ 不是唯一瓶颈。

### 3. 仪器分辨率不足以判 2pt 级差异

单题 192 局 s.e. ≈ 3.6pt。轨迹测试证明 champ 交付点的 50.0% 是**孤立尖峰**：邻居 8.84M =
44.8%、9.24M = 40.1%、9.60M = 46.6%、10.00M = 44.8%，且**换到 90000 题后「哪个断点最好」
直接翻转**。⇒ 交付读数的 +2pt 属 best-of-run 的正常乐观偏差。

### 4. 配方已饱和（r3x 给出的直接证据）

| 应用 | 配方 | 结果 |
|---|---|---|
| v3.0.4 → v3.1.1 | 3.x 原配方 + 2.5M 帧 | **+5.7pt**（44.3% → 50.0%） |
| v3.1.1 → r3x | **逐字相同**的配方 + 2.5M 帧 | **−5pt**（50.0% → 45.0%） |

同一条有 +5.7pt 战绩的配方，在同一起点上第二次应用收益为零且为负。
⇒ **「算法对手 0.20 是元凶」这一头号假设被证伪**，且说明「还差某个旋钮」的判断不成立。

## 三、七轮实验各自证伪了什么

| 轮次 | 唯一改动 | 结果 |
|---|---|---|
| A4 | HQ 奖励 0.15 → 3.0 | 46.4%（无改善） |
| champ | 靶子+规模（A4 + 1M 帧） | 50.0 / 48.4（最好，但未越线） |
| champ2 | 锚点占比 0.50 → 0.75 | 49.0 / 46.9（无改善，且当轮 LR 锁死） |
| champ3 | 解锁 LR（constant 2.5e-05） | 46.9 / 46.4（更差） |
| champ4 | 集中靶子（锚点 76.5%） | 47.9 / 45.3（更差） |
| champ5 | 拉长规模（+2.3M 帧） | 46.9 / 39.1（**明确退步**） |
| r3x | 还原 3.x 原配方（4 处全改回） | 45.0%（无改善）；末态 39.0% |

**唯一稳定规律**：`schedule` 优于 `constant`。
⇒ **配方路线正式关闭**：奖励 / 靶子构成 / 解锁 LR / 拉长规模 / 还原原配方五条路径全覆盖。

## 五、下一步只剩结构性改动

1. **从零训练更大容量**：`RL_NET_WIDTH` **仅在从零训练时生效**（`train.py:826`）。
   10M 帧 @ ~110–125fps ≈ 25 小时（以天计）。
   **必须先加 `RL_SNAPSHOT_KEEP=200`**，否则 >2.3M 帧的长跑会被宿主的批量删除门禁杀掉
   （§5.12.1 的崩溃根因）。
2. **改观测 / 动作空间**：当前 6715 维 / `Discrete(155)`。配方空间已榨干，剩下的变量在这里。
3. 不建议再做任何「从 v3.1.1 续训 + 调配方」的轮次 —— 已被七轮覆盖，
   且 §二.4 给出了饱和的直接证据。
