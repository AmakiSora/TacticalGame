# v3.5.0 训练计划：静态图泛化与算法超越

> 状态：草案，2026-09-30
> 目标：训练一个在全地图、双座位条件下稳定击败内置算法的单一 RL 模型
> 依据：`rl/docs/plans/v3.3.0_conclusion.md`、`rl/docs/MODELS_NOTES.md`

## 0. 结论先行

下一轮不再把网络容量或算法对手比例作为主变量。v3.1.0 和 v3.3.0 已经证明，容量从约 0.87M 参数扩大到 1.44M 参数仍不能修复静态图；v3.3.0 的算法对抗实验也证明，随机图上的模型并非全面落后，真正的失败集中在 `default`、`breach`、`desert` 等训练权重不足的静态地图。

主线从 v3.3.0 的 11.4M 断点续训，做两个短分支：提高静态图采样比例，并把一次性的兵种 novelty 奖励改成持续性的兵种多样性信号。每个分支只跑 1.0–1.5M 帧，然后用逐图、逐算法、换座位的大样本评估选择检查点。

## 1. 当前问题与可验证假设

| 问题 | 证据 | 本轮假设 |
|---|---|---|
| 静态图崩塌 | v3.3.0 在 `default/breach/desert` 为 0% | 将每张静态图权重从 0.05 提高到 0.075–0.10 后，模型能获得足够梯度并恢复基本策略 |
| 步兵海 | v3.3.0 `default` 步兵约 81%，游侠约 14% | 持续多样性奖励能减少单一兵种循环，同时保持 HQ 伤害与控点收入 |
| 继续长训退化 | v3.2.0、v3.3.0 S3 等多次复现 | 从同一断点开短分支，低学习率评估选择，避免一条轨迹长时间漂移 |
| “算法太强”判断失真 | 随机图上 v3.1.1 对算法约 41%/45%/64%，静态图显著更差 | 训练目标应是全地图泛化，算法占比维持 20%，不再提高到 40% |

## 2. 训练起点与固定配置

训练起点：

```text
rl/models/hex_ppo_v3.3.0_20260923_11.4M.zip
```

不从零训练，不修改观测空间、动作空间、编码器或网络宽度。两个分支共享以下配置：

```text
RL_SELF_PLAY_PROB=0.70
RL_ALGO_OPPONENT_PROB=0.20
RL_ALGO_MIX=threat:0.40,field:0.35,greedy:0.25
RL_ALGO_EPSILON=0.10
RL_OPPONENT_STOCHASTIC_PROB=0.30

RL_LR_MODE=schedule
RL_LEARNING_RATE=0.00005
RL_LR_END=0.00002
RL_TARGET_KL=0.02
RL_ENT_COEF=0.02
RL_NUM_ENVS=8
RL_SNAPSHOT_KEEP=200
RL_EVAL_MODE=async
RL_EVAL_FREQ=100000
RL_EVAL_EPISODES=96
RL_SAVE_FREQ=12500
```

算法对手的 20% 是真实对局占比，不被自对弈比例再次稀释。每个训练窗口都必须检查 `opponent/algorithm_episodes`、`opponent/rejection_rate_window` 和 `explained_variance`。

## 3. 地图权重实验

两个实验从完全相同的 11.4M 断点启动，不能串行续训。

### A：保守平衡分布

```text
random:0.55
breach:0.075
danger-close:0.075
default:0.075
desert:0.075
dual-lanes:0.075
forge:0.075
```

目标是恢复静态图，同时尽量保持随机图能力。训练 1.0M 帧，若 1.0M 检查点已达到候选门槛，再追加 0.5M 帧低学习率续训。

### B：静态图优先分布

```text
random:0.40
breach:0.10
danger-close:0.10
default:0.10
desert:0.10
dual-lanes:0.10
forge:0.10
```

目标是验证静态图是否需要更强的训练权重。训练 1.0M 帧；若随机图相对起点下降超过 8 个百分点，立即停止该分支，不追加训练。

两个分支都保存 100k、200k、400k、600k、800k、1.0M 检查点。训练期的 `best_model.zip` 只能用于定位候选，最终交付必须用独立验收结果决定。

## 4. 奖励修改

在启动长跑前先实现并单测持续多样性奖励。现有 `RL_REWARD_NEW_UNIT_TYPE` 只奖励每种兵种首次部署，长局中会失效，不能继续作为主要修复手段。

建议使用最近 6–8 次部署作为窗口：

1. 某兵种在窗口中占比低于 25% 且部署动作有效时，给小额奖励；
2. 同一兵种连续第三次部署时给轻微惩罚；
3. 每个回合的多样性奖励总额限制在 `[-0.10, +0.10]`；
4. 只在单位实际部署成功后结算，不奖励非法动作、空转或重复 `end_turn`；
5. 不强制支援兵出场，奖励只作为轻微偏置，不能压过 HQ 伤害、击杀和控点信号。

建议初始量级为 `0.02–0.05`，并保留开关以便做消融：

```text
RL_REWARD_DIVERSITY=0.03
RL_REWARD_REPEAT_UNIT=-0.02
RL_DIVERSITY_WINDOW=8
```

实现后先用固定状态序列验证：窗口计数、连续部署惩罚、非法动作不计奖、回合重置和并行环境互不串状态。若奖励仍在单步 clip 前饱和，先修正奖励量纲，再开始训练。

## 5. 训练过程与止损

每 100k 帧进行一次异步评估，每次至少包含：`random_rule`、`random_algo`、`default_algo`、`breach_algo`、`desert_algo`。算法评估使用 epsilon=0，训练中的 `RL_ALGO_EPSILON=0.10` 只用于打断确定性对手。

出现以下任一情况，停止当前分支并保留最后一个有效检查点：

- 静态图连续两个评估点仍为 0% 或接近 0%；
- `explore/new_candidate_rate` 连续两个窗口归零；
- `opponent/rejection_rate_window` 持续大于 0；
- `explained_variance` 连续三个评估点低于 0.3；
- 步兵占比继续上升且 HQ 伤害、控点收入同步下降；
- 分支相对 11.4M 起点在随机图下降超过 8 个百分点。

训练脚本必须支持实例中断后从最近断点恢复，断点、快照和日志放在独立目录：

```text
rl/checkpoints/random/v420_static_a/
rl/checkpoints/random/v420_static_b/
rl/selfplay/random/v420_static_a/
rl/selfplay/random/v420_static_b/
```

## 6. 验收协议

候选检查点先进行 24 局冒烟；通过后进行正式验收。正式验收至少使用两组不同 `seed-prefix`，每个“模型 × 对手 × 地图”累计 192 局，固定配对地图并换座位。

必须记录 `players` 字段反查真实模型座位，不能直接按 `scores.player_a/player_b` 统计换座位结果。明细保留到 `arena/details/`，摘要追加到独立 stats JSONL。

### 晋级门槛

候选模型必须同时满足：

- 每张地图对 `threat` 的点估计胜率至少 55%，95% Wilson 下界大于 50%；
- `field`、`greedy` 不出现单图崩塌；
- 7 图总体对三种算法胜率至少 60%；
- 对 v3.0.3 和 v3.1.1 的头对头胜率下界均大于 50%；
- 没有任何地图出现 0% 或接近 0% 的结果；
- 两个座位的胜率差距不超过 15 个百分点；
- 步兵占比不超过 65%，游侠占比恢复到至少 20%，且 HQ 伤害与控点收入不低于起点模型。

任一静态图未通过，就不能以“全图 champion”交付。若随机图更强但静态图仍失败，只保留为随机图专项候选，不替换生产模型。

## 7. 结果分流

### A、B 均通过

选取静态图最低下界更高的检查点；若两者接近，选择随机图回退更小者。对选中的检查点追加 0.5M 帧低学习率复核，复核退化则回退到未追加的检查点。

### 只有 A 通过

交付 A，B 标记为静态图优先但随机图退化的失败实验。继续优化时只调整奖励，不再提高静态图权重。

### 只有 B 通过

先做一次随机图恢复消融：固定 B 的奖励和对手池，将随机图权重提高到 0.50。若仍能保持静态图门槛，再交付；否则保留 B 作为静态图 specialist，不替换全图 champion。

### 两者均失败

停止继续加帧。下一阶段改为每张静态图训练 300k–500k 帧的 specialist，再将 specialist 行为蒸馏回一个通用模型；同时检查观测是否显式编码地图身份和关键几何特征。
