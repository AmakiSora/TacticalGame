# v5.0.0 从零训练计划：HexZero Expert League

> 状态：计划稿，不代表已经开始训练
>
> 目标：从随机初始化出发，训练一个在当前所有 RL 模型和内置算法之上的单一交付模型。
>
> 首发范围：当前 `round_robin.py` 支持的双人 standard 地图。simultaneous、annihilation、royale
> 需要各自的动作/结算模型，作为后续版本阶段，不能提前宣称由本版覆盖。

## 1. 先定义“超越”

“超越所有”不能用一次 8 局互打或训练日志里的最高胜率证明。v5.0.0 只有同时满足下面的条件，才允许称为 champion：

1. 冻结一份参赛清单：`rl/models/` 中所有能被对应 runner 加载的 RL 模型（包括已过期 zip），加上 `algorithms/registry.mjs` 当前注册的全部算法。manifest 记录版本、runner、哈希和排除项；现有 `round_robin.py` 不支持的旧格式必须用兼容 runner 单独完成对局，不能把“脚本不支持”记成 v5 已超越。
2. 每个候选对手至少做 384 局配对对局，按地图和座位分层；整体分数按地图等权。平局按半胜计。每个对手对 v5 的配对胜率 95% Wilson 下界需大于 50%，最强 RL 对手还需大于 55%。低于 55% 的点估计需扩样或判未通过，不能凭均分放行。
3. 每张地图先做 96 局筛查，任何地图低于 50% 就停止晋级；其余地图扩到至少 192 局，点估计需达到 55%。正式交付不能有地图 0 胜或明显座位锁；对最强 RL 对手，每座位下界均须大于 45%。
4. 以 `round_robin.py` 的 Bradley–Terry 评分和 95% 置信区间复核，v5.0.0 的下界高于第二名；若存在循环克制，则以最弱地图单元格为准，不以总榜掩盖短板。
5. 合法动作率为 100%，搜索开启时单步 p99 延迟不超过部署预算；先以每步最多 50 ms、最多 64 次模拟作本机初始预算，S0 基准测试通过后才能调整，实际值写入模型清单。

验收必须保存原始逐局 JSONL、种子、座位、地图、模型文件哈希、运行时版本和搜索预算。只提交汇总胜率而没有逐局数据，结果无效。

## 2. 为什么 v5 不再把 PPO 当主算法

当前 PPO 配方已经证明了三个问题：

- 它是严格 on-policy，旧样本很快被丢弃，静态地图和稀有战术得到的梯度不足；
- 共享策略在异构地图上出现梯度冲突，修好一张图后另一张图崩塌；
- 收敛后继续 PPO，哪怕只改学习率或对手比例，也会稳定退化。

v5 改用 **Expert Iteration + Gumbel 根搜索 + 优先级回放**。搜索直接调用 TypeScript 规则内核推进状态，不额外学习动力学模型。战斗伤害含隐藏随机数，树搜索必须按独立、不可被策略观察的随机流采样；不能让所有候选动作共享同一段可被搜索利用的 RNG 序列：

```text
随机初始化网络
    ↓
网络先验 + Gumbel Sequential Halving / MCTS
    ↓
搜索访问分布（策略标签）+ WDL/分数/终局距离目标
    ↓
分层优先级回放，离线更新网络
    ↓
新网络进入联盟，和历史快照、地图专家、内置算法对局
    ↓
只把通过统计门禁的快照加入主池，重复搜索
```

这不是把 MCTS 算法简单套在现有模型外面。搜索分布会反过来训练策略和价值头，网络再为下一轮搜索提供更好的先验；最终交付的是“网络 + 固定搜索预算”的一体化策略。PPO 可以作为消融基线保留，但不得进入 v5 主训练链路。

## 3. 模型和动作表示

### 3.1 网络：HexZero Policy–Value Network

新增 `rl/v5/` 命名空间，不修改 v3 的环境快照和运行器。首版网络固定为：

- 331 个六角格 token，包含地形、占用、所有者、兵种、当前/最大生命、据点状态和局部可达性；
- 单位 token、总部 token、据点 token、经济/行动点 token、回合与终局规则 token；
- 地图配置 token，显式编码 `mapId` 和会改变裁决的 `balance` 字段，禁止模型把静态地图当成未知 OOD；
- 六角轴坐标的相对位置偏置和旋转/镜像数据增强；增强后的动作必须经过同一个坐标变换器反变换，不能只转观测；
- 起始容量 4 层、`d_model=128`、8 头注意力、`features_dim=384`，actor/critic 共享棋盘干路；先以本机 8 GB GPU 做显存探针。只有吞吐和显存实测允许时，才把 6×192 作为独立消融，不能把扩大网络当作默认解法。

策略头不再只输出 155 个平面动作：

```text
action = (phase, unit-or-type, intent, target-or-endpoint)
```

策略对当前状态的**完整合法动作列表**逐项打分，再加类型/单位/目标辅助头帮助泛化；避免先作有损因子分解后漏掉合法 payload。搜索器只扩展引擎合法动作。训练时记录 action dictionary 哈希；`run_model_v5.py` 仅在哈希匹配后把索引还原成原始 payload。

### 3.2 训练目标

每个回放样本包含：`observation`、合法掩码、搜索根分布 `pi_search`、终局 WDL、裁决分数差、到终局的步数、地图/座位/对手池标签和搜索访问统计。

初始单批损失为以下可消融配方；系数由 S0 固定验证集标定，不能未经消融就当作事实：

```text
L = 1.0 * CE(policy, pi_search)
  + 0.75 * CE(wdl, terminal_wdl)
  + 0.25 * Huber(score_delta, z_score)
  + 0.10 * Huber(time_to_terminal, t)
  + 0.05 * consistency(policy_view_a, policy_view_b)
```

`score_delta` 做按地图分层的稳健标准化，但终局 WDL 不缩放；任何标准化都不能改变胜负目标。策略标签只在合法集内归一化。每张地图、每个座位、每个终局类型独立维护回放配额，避免 random 地图的样本量淹没静态图。

## 4. 搜索器设计

### 4.1 根节点

- 用网络 policy logits 加 Gumbel 噪声做根排序；前期扩展全部合法动作，稳定后使用 `top-k=32`，若合法动作少于 32 则全部保留。
- 使用 Sequential Halving 在固定模拟预算内淘汰明显劣势动作，而不是把模拟平均浪费在 155 个槽位上。
- 搜索温度按训练阶段衰减：前 2M 个样本 `τ=1.0`，随后 `τ=0.25`；验收和部署固定 `τ=0`。

### 4.2 树节点

当前 `local-worker.ts` 是一个进程持有一个可变游戏实例，**没有 clone/undo 或分支 API**。S0 必须增加独立 simulation kernel：从序列化 `GameState` 创建分支副本，调用纯规则函数推进每个子节点；搜索状态不共享事件总线、缓存、token 或其他分支引用。
- standard 模式部署会生成 UUID，因此仿真 ID 必须由 `(root_seed, ply, action_index)` 确定生成；验证中实际部署动作与仿真动作都走同一规则函数。
- combat/heal 随机结果由隐藏 RNG 影响。每条 rollout 使用 keyed counter-based seed，训练种子可重放；不同 action branch 使用独立子流，policy observation 不包含随机状态。最终性能还要用多随机种子对局验证，防止搜索利用模拟器偏差。
- transposition key 包含规则配置哈希、单位/资源、行动点、当前玩家、回合阶段和所有会影响合法性/裁决的状态；不包含 UUID、事件历史和 RNG 内部值。
- 根节点使用 Gumbel Sequential Halving；树内用 PUCT，叶节点取 WDL + 分数头。终局直接读引擎裁决。首轮预算 8/16/32 模拟逐档测试，64 只在延迟与强度消融均通过时使用。

### 4.3 搜索质量门

进入正式训练前必须通过：

- 在手工构造的必杀、保总部、抢最后据点、行动点耗尽、无上限回合局面中，搜索选择与穷举最优动作一致率 ≥ 95%；
- 在相同计算预算与独立随机流下，搜索策略在保留集对规则基线的胜率显著高于裸网络；Brier 分数只评价概率校准，不作为搜索正确性的替代证明；
- 搜索返回的每个动作都能被引擎接受，非法动作计数必须为 0；
- 搜索超时只能回退到网络合法动作，回退率单独记录，超过 0.5% 即停止扩展训练。

## 5. 从零训练阶段

“从零”定义为：v5 网络所有参数随机初始化，不加载任何 v2/v3 权重。内置算法可提供公开、可审计的动作标签作冷启动监督，但历史 RL 模型只作为冻结对手；教师数据比例必须衰减到 0，最终晋级评估不得用教师动作替代自博弈。

### S0：环境与搜索基线（3–5 天）

交付内容：

- `rl/v5/env_v5.py`：结构化 token 观测、联合动作映射、相对视角、地图 token；
- `rl/v5/search.py`：确定性树、Gumbel 根搜索、transposition table、超时回退；
- `rl/v5/replay.py`：分层回放和地图/座位配额；
- `tests/rl/test_v5_search.py`、`test_v5_action_mapping.py`、`test_v5_replay.py`；
- 一个小规模可复现实验（固定地图、固定随机种子），能从随机网络学到必杀和占点；采用小状态穷举核对分支模拟与真实引擎转移一致。

S0 不追求棋力；任何搜索/动作合法性问题未清零，都不能开始长跑。

### S1：随机冷启动（1–2M 个决策样本）

- 8 个采集 worker，地图按当前地图清单均匀采样；random 地图按参数空间分层采样，不让默认随机域吞掉边界条件；
- 先从 `threat`、`field`、`verdict` 等算法采集合法动作标签，动作与全合法列表必须精确匹配，标签 fallback 率低于 0.1%；再以随机合法对手 30%、内置算法 50%、自身温度自博弈 20% 采集。该阶段是监督冷启动，不加载旧模型权重；
- 搜索预算 16，保存全部根分布而不是只保存最终动作；
- 每个当前地图按等额 epoch 配额采样、两个座位各半；地图数量变化时不复用固定样本数。优先级由终局稀有度、TD 误差和搜索熵联合决定；
- 每 200k 样本做一次独立种子评估，连续两次价值校准变差或地图最小胜率低于随机基线 10 个百分点就停下来定位。

S1 的退出条件是：WDL 校准 ECE ≤ 0.12，必杀局准确率 ≥ 80%，所有地图都有非零策略熵，合法动作率 100%。

### S2：专家迭代主循环（8–15M 个决策样本）

每轮固定顺序：

1. 从当前主网络和联盟池采集 100k–250k 个状态；
2. 对采集状态重新搜索（reanalyse），搜索预算 32 或 64；
3. 写入优先级回放，按地图/座位/终局类型做最小配额；
4. 更新网络 2k–8k 个 batch，早停依据是验证集 policy CE 和 WDL Brier，而不是训练 loss 单调下降；
5. 用冻结种子集和所有旧快照做晋级评估；只有通过门禁的快照才进入联盟池。

训练 batch 采样比例为：当前难例 30%、地图均衡 30%、历史回放 25%、随机新局 15%。地图层级在池内等额，random 参数域分层抽样。历史回放最多保留 50 万状态起步，只有 S0 证明主机内存余量充足后才扩容；任何地图不能超过总池 25%。

### S3：联盟自博弈和反制训练（5–10M 个决策样本）

联盟至少包含：

- `main`：全图通用策略；
- `map-exploiter-*`：按最弱地图动态分配的专精策略；
- `tactical-exploiter`：只抽取总部斩首、反杀、最后据点和补员短局；
- `defender`：目标是打败 `main`，专门寻找座位锁和步兵海；
- `historical`：所有冻结的 RL 模型和内置算法，只作对手，不回传其参数。

对手按每个“地图 × 座位”胜率做 PFSP，而不是按全局胜率抽样。低于 45% 的组合提高到 35% 上限；高于 65% 的组合降到 5% 下限；新快照默认 10%，防止新策略过早被忽略。联盟成员每 100k 样本评估一次，连续两轮对 `main` 没有产生新失败样本的 exploiter 可以冻结。

### S4：硬负样本和交付收束（2–4M 个决策样本）

从 S2/S3 的失败局面建立硬样本集：

- 只差一回合输掉的局面；
- 搜索和网络意见分歧最大的局面；
- 某地图某座位连续失败的局面；
- 侦察/远程/重甲三类兵种长期未部署的局面；
- `default`、`breach`、`desert` 等静态布局的战术转折点，以及当前地图清单中的所有新增地图。

硬样本最多占 batch 的 30%，并保持 70% 的全图回放，避免把模型再次过拟合成单图专家。S4 不再抬高学习率；如果需要改变目标，必须复制出新 run，禁止在候选 champion 上原地继续训练。

## 6. 地图、座位和数据覆盖

训练配置不硬编码旧地图数量。启动时读取仓库地图清单和模式配置，生成带哈希的 `map_manifest.json`：

- manifest 过滤条件为 `mode === standard` 且 `supportedPlayerCounts` 包含 `2`；当前评估脚本的 `DEFAULT_MAPS` 只是兼容默认值，不能成为 v5 的隐含验证集；
- 每个采样 epoch 给当前地图清单等额配额；地图数量变化时按 `1 / 地图数` 自动重算，不能写死一个会在扩图后失真的百分比；
- 静态图不允许只在评估出现，每个 epoch 都必须进入采样配额；随机地图的剩余配额再按参数域分层分配；
- 每张图按先手/后手各 50%；对 simultaneous 模式按计划阶段和结算阶段分别计数；
- 所有随机地图保存参数向量，确保失败局能重放；
- 地图配置改变后哈希必须变化，旧 replay 不能静默混入新规则。

现有竞技场对静态地图不使用 map seed，但引擎战斗仍有伤害/治疗随机数；因此 v5 的评估适配器必须为每局注入 `rngState` 初始种子，并把该种子写进逐局 JSONL。随机地图的地形种子和战斗种子分开记录。这样同一局面可以重放，重复对局也仍能用不同战斗种子估计方差；未完成这项适配前，静态图只能做功能测试，不能做晋级证据。

训练日志每 50k 样本输出一次地图覆盖、座位覆盖、兵种分布、终局原因、搜索回退率和非法动作数。单看平均回报、熵或 `explained_variance` 不再作为晋级依据。

## 7. 评估和晋级流程

### 7.1 快速评估

每个候选快照先跑 32 局/地图，逐座位配对，检查：

- 非法动作为 0；
- p99 推理延迟在预算内；
- 没有地图胜率低于随机基线 15 个百分点；
- 搜索开启相对裸策略的平均分不下降。

任何一项失败都不进入大样本评估。

### 7.2 主验收

使用 `rl/evaluation/round_robin.py` 的统一编排器，新增 v5 runner 但不另造一套统计口径：

```text
候选：v5.0.0@checkpoint
对手：所有当前 RL 模型 + algorithms/registry.mjs 全部算法
地图：`maps/*.json` 中 mode 为 `standard` 且支持 2 人的全部地图；不受 `round_robin.py` 旧默认列表限制
每对手：2 个独立 seed batch × 192 局
座位：每批严格 96 局先手 + 96 局后手
模式：默认搜索预算固定为 64 simulations 或 50 ms（二者取先到）
```

主验收同时输出三套结果：搜索开启、网络裸策略、搜索超时回退率。线上交付使用搜索开启版本，但裸策略结果用于排除“只靠无限算力”的假提升。

### 7.3 统计规则

- 不做临时删图、删座位、删难对手；
- 不因为训练期 best 较高就跳过独立种子；
- 先用 sequential test 判断是否明显低于 50%，明显失败的候选提前停止；接近 50% 的候选必须跑满；
- 同一候选若两个 seed batch 结论相反，标为不稳定，不交付；
- 与最强对手的差值用 bootstrap 95% CI 复核，避免 Wilson 下界单独造成误判。

## 9. 止损线和回滚

出现下面任一情况，立即冻结当前 checkpoint，复制新实验分支后再改参数：

- 任意地图或座位的非法动作率超过 0；
- 搜索回退率 > 0.5%，或 p99 延迟连续两个窗口超预算；
- 某地图相对 epoch 配额偏差超过 5%，或某座位低于 45%；
- WDL ECE 连续三次变差，或者价值头在验证集上的 Brier 分数比上一晋级点差 10%；
- 训练两轮后最弱地图仍低于随机基线，继续采样没有新增失败类型；
- 新 checkpoint 的主验收点估计胜率下降 ≥ 5 个百分点，或任何已通过地图跌破 45%；
- 训练已经通过所有门禁后仍继续更新。通过门禁即封存，不允许“再跑一点看看”。

回滚顺序为：最近一个通过快速评估的 v5 checkpoint → 最近一个通过主验收的 v5 checkpoint → 当前生产 champion。v3 模型文件不替换、不重命名、不覆盖。

## 10. 预期时间和资源

本机基线为 RTX 3060 Ti 8 GB 显存、16 GB 系统内存、12 个逻辑处理器。初始配置限制为 1 个训练进程、4 个采集 worker、评估串行执行；显存先从 batch 16/FP16 测起，系统内存超过 80% 时自动暂停采集。下表是阶段预算，不是基于当前吞吐的承诺：

| 阶段 | 样本量 | 预计墙钟 | 产物 |
|---|---:|---:|---|
| S0 | — | 3–5 天 | 环境、搜索器、单元测试 |
| S1 | 1–2M 决策样本 | 先实测 | 冷启动网络与回放 |
| S2 | 8–15M 决策样本 | 先实测 | 主网络与回放池 |
| S3 | 5–10M 决策样本 | 先实测 | 联盟快照与硬负样本 |
| S4 | 2–4M 决策样本 | 先实测 | 候选 checkpoint |
| 验收 | 由对手 × 地图 × 配对局数公式生成 | 先 dry-run | 全矩阵逐局结果 |

实际墙钟和可达样本量须在 S0 每小时吞吐探针后重估；恢复点最多间隔 25k 样本，评估与采样不可在 16 GB 主机上无上限并行。

## 11. 交付判定

满足全部主验收门禁后：

1. 用 `run_model_v5.py` 做一次干净加载和 100 局合法性冒烟；
2. 生成 `rl/docs/models/v5.0.0.md`，写入实际 checkpoint、搜索预算、模型哈希、全矩阵结果和已知限制；
3. 更新 `rl/docs/MODELS_NOTES.md` 与 `rl/docs/RELEASE_NOTES.md`，只记录对外可验证变化；
4. 由 `npm run build && npm test` 和 `npm run test:rl` 完成仓库级验证；
5. v5 未过线时，候选只进入归档，不替换现有 champion，也不把“训练完成”写成“超越”。

## 12. 成功之后的扩展顺序

标准模式通过后，复用相同的搜索/回放协议接入 simultaneous，再接 annihilation，最后接 royale。每个模式都要建立独立的动作联合分布、终局目标和地图 manifest；不能把 standard 的网络输出直接解释成另一个模式的动作。新模式通过各自门禁前，v5.0.0 的生产路由只声明已验收的模式。

这个顺序的核心取舍是：先用可审计的搜索目标解决“共享 PPO 梯度把地图练塌”的主问题，再增加模式和容量。没有通过统计门禁的更大网络、更长训练和更多搜索，都不算进步。

## 13. 开工后的第一周执行表

第一周不跑长训，目标是把“搜索是否真的提供了比网络更好的标签”这件事单独证实。顺序固定如下：

### Day 1：冻结接口和清单

- 从 `GET /api/maps` 和 `algorithms/registry.mjs` 生成 `map_manifest.json`、`opponent_manifest.json`；记录 SHA-256。
- 固定 Python、Node、PyTorch、引擎 git SHA 和随机种子格式；所有后续 replay 都引用这四项。
- 写 `action_space.py` 的双向测试：引擎 payload → 联合动作 → 引擎 payload，循环 10,000 次后字段必须逐字一致。
- 不引入 PPO 依赖到 v5 入口；v5 训练进程只依赖 PyTorch、NumPy、Gymnasium 和本地引擎 worker。

### Day 2：搜索器正确性

- 先在小棋盘上实现 `clone / apply / terminal`；不做容易留下共享引用 bug 的原地 undo。每个节点带完整状态哈希。
- 用穷举结果验证必杀、保总部、抢点、行动点耗尽、平局裁决五类局面。
- 运行 1,000 个固定种子局面，输出转移对照差异、搜索前后 top-1 改变率、独立随机流统计、非法动作数和回退率。
- 任何状态哈希冲突、回滚后快照差异或非法动作都阻止进入 Day 3。

### Day 3：回放和网络小实验

- 生成 50k 个随机/算法对手位置，搜索预算固定 16；不做长时间自对弈。
- 训练 2k 个 batch，验证 policy CE、WDL Brier、ECE 和各地图样本量。
- 搜索标签相对教师/裸网络标签必须在留出集上提升对局结果；交叉熵仅检查拟合，不能当强度提升证据。

### Day 4–5：短专家迭代

- 启动 2 个采集 worker、1 个训练 worker，预算 8 → 16，各跑 100k 样本。
- 每 25k 样本保存一次可恢复 checkpoint 和 replay 索引；模拟中断后从最近索引恢复并校验样本哈希。
- 只比较三组消融：无搜索、网络 + 16 搜索、网络 + 32 搜索；其余配置完全相同。
- 若搜索组在两个独立种子上都没有优于无搜索组，暂停 S1，先不要增加模拟次数。

### Day 6–7：决定是否进入 S1 长跑

满足以下条件才进入 S1：

- 五类手工局面搜索 top-1 一致率 ≥ 95%；
- 分支模拟与真实引擎的 10,000 个动作转移逐项一致；
- WDL ECE ≤ 0.12，非法动作为 0，搜索回退率 ≤ 0.5%；
- 每张地图、每个座位都有样本，且地图配额误差不超过目标的 ±5%；
- 2 个独立种子的短专家迭代都没有出现一张图胜率跌破随机基线 15 个百分点。

不满足时只允许修复接口、搜索、采样或统计口径；不允许用提高训练步数、提高网络容量或降低验收标准来掩盖失败。

### 首轮配置文件

首轮配置保存为 `rl/runs/v5.0.0/configs/s0.json`，内容至少包括：

```json
{
  "version": "5.0.0",
  "seed": 500000,
  "mode": "standard",
  "network": {"d_model": 128, "layers": 4, "heads": 8, "features_dim": 384, "dtype": "float16"},
  "search": {"type": "gumbel_sequential_halving", "simulations": 8, "root_top_k": 32, "time_ms": 50},
  "replay": {"capacity": 500000, "map_balance": "equal_epoch", "hard_case_cap": 0.30},
  "opponents": {"random": 0.30, "algorithm": 0.50, "self": 0.20},
  "eval": {"episodes_per_map": 32, "swap_seats": true, "seed_prefix": 500000}
}
```

实现完成后的推荐启动方式为：

```powershell
python -m rl.v5.train_v5 --config rl/runs/v5.0.0/configs/s0.json --run-id s0-smoke
python -m rl.v5.evaluate_v5 --run rl/runs/v5.0.0/s0-smoke --quick
```

长跑前先把实际配置、地图清单和对手清单写入 run 目录；命令行临时覆盖必须落入 `overrides.json`，不能只存在终端历史里。
