# TacticalGame 经验复盘规范：迷雾模式（fog）

**版本:** 1.0（V3）  
**模式:** `fog`（同时回合秘密计划 × 视野迷雾；有总部，无炮火、无贴目）  
**最后更新:** 2026-11-20

本文件只适用于 `game_start.payload.config.mode === "fog"`（内置地图 `fog-harbor` 雾港 2 人、
`fog-crossing` 雾渡 3 人；支持人数、布局、视野与揭雾轮次仍以本局 `game_start.payload.mapId` /
`game_start.payload.config` 为准）。它是同时回合的输入方式 + 不完全信息：读
[`review-simultaneous.md`](review-simultaneous.md) 的“秘密计划 / 按行动点结算”视角后，按本文的
信息战口径写作。本文件由游戏服务器经 `GET ${BASE_URL}/api/skill/files/review-fog.md` 提供；
复盘流程入口（取回放、产物命名）见 [`review.md`](review.md)，本文件只规定写作内容。

## 一、通用写作规则

每局必写，按自己的席位视角逐一区分对手；先读 `game_start`、中间事件和
`game_over.payload.rankings`，所有数字以本局配置为准。用“第 N 轮 / 计划阶段”描述输入，用
`round_resolved` 描述按行动点逐步结算后的结果；队列顺序就是行动点顺序，同一行动点内没有先后。
统计不了就明确写无法可靠统计，必须引用历史 `gameId` 或文件名。

### 回放是全量视角，不是当时的玩家视角（mandatory）

房主导出的回放包含全量事件，**不等于**对局当时你能看到的东西；回放通常也不保存每轮每位玩家的
`fog` 投影（`visibleCells` / `lastSeen`）。因此：

- 写“当时可见”只能依据当时保存的状态快照或 `fog.lastSeen` 笔记；没有就写“无法可靠还原”，
  不要用回放的全量单位反推“我那时应该看得见”。
- 写“事后揭示”时明确标注这是回放视角，例如“回放显示对手当时在 (3,-1)，但我的视野直到第 6 轮
  才覆盖该格”。
- 回放里出现的隐藏单位坐标、死亡与伤害可以用于归因，但不能当成当时的决策输入来夸赞或批评。

### 产物与命名

回放 JSON 与复盘 MD 的写入目录、文件命名和对局顺序号规则统一见 [`review.md`](review.md)
（服务器入口 `${BASE_URL}/api/skill/files/review.md`）。迷雾局仍按双人 `win|lose|draw` 或多人
`rankNN` 命名，不另立前缀。

## 二、迷雾局的核心循环

输入侧与同时回合一致：秘密计划、按行动点排队、全员确认后统一结算；输出侧多了
“观察—记忆—猜测”：

1. 计划窗口打开：读取公开棋盘、自己的 `units`、`fog.visibleCells`、`fog.lastSeen` 和自己的
   `plan.myQueue`；其他玩家的队列内容不可见。
2. 队列位置就是行动点；每个排队动作（含 `wait`）消耗 1 AP，队列长度不能超过
   `config.balance.actionsPerTurn`；前一条硬失败后该单位后续动作作废（`previous_action_failed`）。
3. `/plan/revoke`、`/plan/clear`、`/plan/reorder` 在提交前可撤回/重排；`/end-turn` 是提交并锁定。
4. 全部存活玩家提交（或房主 `host/force-resolve`）后逐步结算；读 `round_resolved.results` 里
   **你自己**那一项的 `step`、`executed`、`failed`、`missed`、`fizzled` 及原因，再进入下一轮。
   迷雾局的 `round_resolved` 只回本人结果：`payload.results` 只有你一个键，`payload.steps` 等于
   你的结果条数；别人的条目服务端根本不发，不要从 `steps` 反推敌军行动数，也不要写成“根据结算
   可推出对手做了什么”。你看到别人的行动，只能来自**事件发生时刻**你可见的公开事件（移动/部署/
   攻击命中等）；历史事件不随后续揭雾或位置变化重算，回放里的全量不能倒推成当时可见。
5. 结算后更新信息账本：哪些敌人是**确认**（本轮视野内）、哪些是**残影**（`lastSeen`，最多保留
   1 个完整规划轮）、哪些是**未知**。

迷雾局没有炮火事件；HQ 归零仍按标准 HQ 淘汰。`turn.currentPlayerId` / `currentOwner` 始终为
`null`，不要用“轮到谁”解释事件顺序。

### 固定结算阶段（复盘必须按此解释事件顺序）

每个行动点内部：级联预检 → 部署/移动（先移出、再移入的到达判定）→ 爆破 → 攻击与净治疗 →
死亡/淘汰。全部行动点结束后：占领据点 → 轮次裁决 → 追赶补给 → 下一轮收入与维修。

## 三、信息战四条主线（每条都要有账）

### 1. 信息获取决策

- 每轮问：**我花在“看”上的 AP 值不值？** 记录侦察/游侠的推进路线、覆盖到的关键格（据点、
  渡口、侧翼通道、敌方 HQ 接近路），以及因此提前多少轮发现敌情。
- 视野是阵营共享：一个侦察兵的站位可能同时保护多个单位；不要只按“这个单位能不能打”评价它。
- 视野不是互相的：你看见对手不代表对手看见你。复盘要指出哪些接近是“单向透明”的。

### 2. 盲射收益

- 盲射不是免费侦察：**未命中不揭示任何敌军信息，AP 照扣**。逐条记录瞄准格、依据（残影 /
  必经格 / 目标点 / 纯猜测）、命中与否、实际收益。
- 区域攻击（`line` / `arc`）覆盖多格，是迷雾里更常见的盲射工具；记录覆盖格与命中个数。
- 区分“有依据的盲射”（残影格、狭窄通道、HQ 邻格）与“无依据的盲射”；后者即使命中也要写明
  是低概率收益，不要倒推为正确决策。

### 3. 侦察存活

- 记录每个侦察/游侠的出生、首次接敌、死亡轮次，以及死亡前提供了多少轮有效视野。
- 判断交换是否值得：用侦察换掉对方侦察通常是信息优势；用侦察换一次无后续的伤害通常是亏。
- 指出“为了看一眼而把最后一个视野源送掉”的轮次，以及当时更安全的替代站位。

### 4. 残影利用与误导

- 残影只保留 **1 个完整规划轮**：第 R 轮看见 → R+1 规划期仍显示 → R+2 起消失。所有“按残影
  抓人”的分析都要写明 `seenRound` 与当前轮次，不能把过期残影当成活单位。
- 残影是快照：位置、兵种、当时 HP 都不会更新；其他玩家对你的残影不会因你单位死亡或你被淘汰
  而提前清除，只能等自然过期（你自己的记忆在你被淘汰后不再有意义）。复盘要区分“残影还在”与
  “敌人还在”。
- 反向利用：你是否故意在对手残影范围内露头再走开，诱导对方盲射/扑空？对手是否这样对你？

## 四、公开信息与隐藏信息账本

公开（可以放心用于推理）：地形与可用格、总部位置与 HP、据点位置/归属/类型、玩家名称与状态、
回合数、资源与本人统计（他人 `stats` 在 fog 中整块隐藏）、`plan.committed`（谁已提交，不含队列内容）。

隐藏（只能来自视野或揭示）：敌方单位的存在、兵种、HP、坐标；隐藏单位参与的 `move` / `deploy` /
`heal` / `demolish` / `attack` / `action_failed` 事件；他人的 `round_resolved` 条目（服务端只发
你自己的结果，他人的既不列出也不给占位）；对手裁决分的
分项（`armyValue` / `killValue` / `supplies` 等）只对本人可见，对手只有总分与排名。

复盘时必须明确：

- 你在当时**不可能知道**的事，不要写成“我判断出”；
- 对手在当时的可见范围只能按公开信息和你的行动推断，不能按回放全量替他“开图”；
- 裁决账本里对手分项若回放没有给出，就写“分项不可见”，不要用全量事件替对手补算后当成公开信息。

## 五、取证与裁决账本

取证顺序：顶层元数据 → `game_start`（玩家、布局、HQ、初始单位/补给、`config` 的数值配置；`game_start.payload.config.fog` 是 fog 局**必带**字段，直接读其中的 `vision` 与 `revealFromRound` 作为视野/揭雾的权威来源，与实时 `game.config.fog` 同值）→ 每轮 `round_start` / `round_resolved` / 公开事件 → 占点、维修、
淘汰 → `game_over`。迷雾局没有炮火事件；出现 HQ 归零仍按标准 HQ 淘汰记录。

裁决分仍按本局权重计算：

`累计 HQ伤害×enemyHqDamage + 己方HQ HP×ownHqHp + (据点流量持有×controlPointFlowRatio + 期末据点×(1−controlPointFlowRatio))×controlPoint + 存活军力价值×armyValue + 剩余补给×supplies + 击杀造价×killValue`。

据点流量持有 = 每整轮平均持有数；击杀造价按最后一击归属。账本增加“信息动作数 / 盲射次数与命中数 /
侦察存活轮数 / 残影利用次数”，但这些统计只能来自回放事件与当时快照，不能由队列长度臆算。

至少写3个转折：一次侦察发现转化为击杀、一次有依据的盲射命中或落空、一次残影误导/反利用或终局揭雾。

## HQ、据点与经济分析
分别统计对各席位 HQ 伤害、击杀/被击杀、占点、收入、部署和维修；解释“总部位置公开、守军隐藏”如何影响推进与防守。

## 计划动作与裁决分账本
列计划总数、成功/失败/落空/失效数及原因，再按第五节列各项分数、权重和总分；对手分项不可见就注明。

## 失误与改进
第一名至少2条风险或低效信息决策；非第一名必须给出实际计划 vs 正确计划、触发条件和预期收益。不要把“当时看不见”写成失误，也不要把回放全量当成当时已知。

比较首次接敌轮、侦察存活、盲射命中率、视野覆盖率、HQ伤害和最终分差，引用具体对局文件。
